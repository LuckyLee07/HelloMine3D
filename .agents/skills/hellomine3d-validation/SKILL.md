# HelloMine3D 验证

定位仓库根（`git rev-parse --show-toplevel`）。本技能位于根目录的
`.agents/skills/hellomine3d-validation/`；下列文档均相对仓库根。
独立黑盒验收者只使用交接中获准的材料，不为加载技能而读取源码。

## 选择检查

1. 从用户范围、实际 diff 和对应合同确认要证明的行为，读取
   [验证矩阵](../../../docs/current/validation-matrix.md) 中相关行。
   不把其他批次的完整门禁或历史失败重跑要求套到当前任务。
2. 先执行聚焦检查，再执行适用的完整门禁。依据
   [README](../../../README.md) 选择真实平台命令；检查脚本参数和构建配置，不猜参数。
3. 正式玩法/视觉验收时，读取 [验收规范](../../../docs/current/ai-assisted-gameplay-acceptance-v1.md)
   的对应场景和证据要求；准备或复用身份匹配的干净包。仅做自动测试时不启动 UI 验收。
4. 记录实际命令、退出状态、平台/架构/配置、源码与包身份、产物位置。
   失败先定位并保留证据；通过后只对新改动或未解决疑点追加验证。

## 玩法交接

按 [工作流](../../../docs/current/agent-workflow.md) 的交接及窗口路径执行。
提供包路径/哈希、真实用户授权的动作、场景、输出目录和结束状态；
确认唯一窗口操作者。用户已有授权不因任务切换而要求重复确认，实际工具拒绝则按原理由处理。

独立上下文与 AI-06 package-only 隔离分别核实；不要给盲玩者源码或内部攻略。
脚本可启动应用、保存原始窗口截图；正常玩法通过实际输入完成。
静态截图不证明动态行为，字幕/日志不证明声音，headless 不证明正常玩法。

## 交付

输出每项 PASS/FAIL/BLOCKED/NOT_RUN、对应证据和下一步；在已有执行记录中更新恢复区。
只更新受影响的当前文档。缺少一个平台或场景不阻止其他已授权工作，
但整体完成仍需满足用户约定的全部退出条件。不要把技能建议当作新增批准流程。
