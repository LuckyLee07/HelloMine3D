## FS1：首次进入正确性

### 已确认问题

世界管理服务会先写入用于目录发布的 `(0.5, 96, 0.5)` 占位出生点，并保持
`player_present 0`。运行时过去把“存在 world.meta”等同于“已经初始化”，因而跳过真正的
出生点搜索。默认创建种子又固定显示为 `0`，最终可能让玩家从原点落入海面，首个“收集
橡木”目标也失去可达性。既有 G6 自动旅程使用强制玩家坐标，没有覆盖这条真实路径。

### 权威规则

1. `player_present 0` 表示世界目录已经发布，但首次玩家位置尚未初始化；第一次正常打开
   必须先建立 terrain seed/version，再计算并持久化出生点。
2. 出生点搜索只依赖 seed、terrain version 和世界坐标，候选顺序确定且有明确上限；相同
   世界身份必须得到相同结果。
3. 首选轻林/温带森林中的陆地列；候选地面必须高于水位、可碰撞，并为玩家身体保留两格
   净空。坐标落在方块中心，不允许出生在水、树干、树叶、仙人掌或悬空位置。
4. 首选候选的预加载邻域内必须存在橡木；有界搜索找不到带橡木候选时，允许回退到最近的
   安全非海洋陆地，但必须输出可诊断的回退信息，不能无限搜索。
5. 世界创建界面启动时给出非零随机建议种子；玩家仍可输入包括 `0` 在内的任意合法整数，
   seed `0` 也必须能安全开始。
6. 早期占位世界只在同时满足占位 spawn、玩家仍在占位列、短会话、空库存、无目标进度和
   无旅程标志时自动救援。任何已移动、已收集或已有目标进度的世界都不得被静默传送。
7. 救援只更新出生点、玩家位置和由占位会话产生的自然演员；不升级 terrain version，
   不改 seed，不改保存格式，不删除玩家修改的区块。

### 回归与退出条件

- 新增真实 `WorldManagementService::createWorld -> prepareWorldForOpen -> World` 测试，不设置
  `HELLOMINE3D_PLAYER_POSITION`。
- seed `0` 重复运行时出生点一致，至少一个固定种子也满足同样安全规则；脚下为实体陆地、身体两格为空、所在
  生态不是 Ocean，预加载邻域可找到橡木或明确命中有界回退。
- `player_present 0` 首次打开后写入真实 spawn/player；第二次打开保持同一位置。
- 明确匹配的短时空白占位世界被救援；有库存、目标进度、移动记录或超出短会话窗口的世界
  保持原位。
- 世界运行时定向/全量回归、目录回归、Debug/Release 构建和隐藏客户端进入世界通过。

### 2026-08-21 完成证据

- 世界管理创建的新目录继续先发布 `player_present 0`，首次打开才写入真实玩家状态；seed 0
  两次均得到 `(296.5, 82, 40.5)`，固定 seed `20260807` 得到 `(168.5, 69, 264.5)`。
- 三个首次打开样本均只加载一个候选区块即命中带橡木的安全陆地；脚下实体、两格净空、
  非 Ocean、3x3 预加载和重开位置保持全部通过。
- 明确匹配的短时空白占位世界会重建 spawn，保留 seed/terrain 身份和非自然掉落物，清理
  占位会话的自然演员；已移动或已有库存的世界保持原位。
- Debug/Release `HelloMine3DWorldRuntimeSmoke` 均为 `532/532`，其中 FS1 覆盖 40 项；两种配置
  的 `HelloMine3DWorldCatalogueSmoke` 均为 `45/45`。
- Release 验证客户端在隔离 seed 0 存档中首次搜索耗时 `0.508 s`，保存
  `spawn/player_position 296.5 82 40.5`；真实 Ogre 窗口随后隐藏运行 30 帧并以 0 退出，
  地形上传包含 solid/water/flora。该证据不替代 FS3 后的 R3 真人输入与视觉验收。

## FS2：天空、水面与颜色基线

FS2 建立独立 water fragment shader，处理视角反射、水深色、太阳高光、远景雾和水下色调；
天空在现有昼夜参数上增加风格化云层，重新校准黎明、白天、夜晚及地平线颜色。地形片元
路径同步检查 gamma、方向亮度和过饱和问题。现有云图可以用于技术验证，但正式资产必须与
体素风格一致并进入 manifest/许可证检查。

最低截图矩阵覆盖固定 seed 的森林、海岸、正午、黄昏和夜晚；修改水面透明排序、常驻几何
或 shader 成本时重跑相关 Q1 快速移动/内容规模比较。

### 2026-08-24 完成证据

- `HelloMine3D/WaterFragment` 不再采样方块图集，按浅水/深水、视角 Fresnel、天空色、太阳
  高光、水下色调和远景雾合成；水面顶点只保留两组低幅波动及解析法线。Release 隐藏客户端
  实际上传 3 个水面区段、1,508 个水面顶点和 2,262 个索引，并以 0 退出。
- 程序化天空增加低频移动云层，云亮面、阴影和覆盖率随世界时间稳定变化；雾、天顶、地平线
  和水色重新校准。地形图集经过亮度、饱和度及绿色优势校正，地形和演员使用有下限的夜间
  曝光曲线，避免夜晚接近全黑。
- 固定证据为 `screenshots/validation-fs2-forest-noon.png`、
  `screenshots/validation-fs2-coast-noon.png`、`screenshots/validation-fs2-forest-dusk.png` 和
  `screenshots/validation-fs2-forest-night.png`。森林使用 seed `296595`、位置
  `(2766, 102, 2905)`，海岸使用 seed `0`、位置 `(285, 72, 40)`；时间固定为
  `6000/12000/18000`。四张图均由真正隐藏的 Ogre 窗口运行时读回，不显示或激活桌面窗口。
- `run_render_capture.ps1 -HiddenWindow` 现在显式设置 `HELLOMINE3D_WINDOW_HIDDEN=1`，并跳过
  查找、显示和移动窗口的 Win32 路径；`WindowScreenshot` 与隐藏模式互斥，防止再次短暂抢焦点。
- Debug/Release `HelloMine3DWorldRuntimeSmoke` 均为 `536/536`；资源 manifest 为 47 项，Release
  Ogre/GLSL 隐藏验证通过。10 秒内容规模基线/复测按 Q1 合同为 `PASS`，帧 P95
  `17.995/19.945 ms`、P99 `26.305/26.977 ms`。15 秒快速移动短样本帧 P95
  `18.245/18.826 ms`、P99 `24.793/26.066 ms`；终止时常驻量差异需要显式 15% 常驻容差，
  其余合同和预算保持默认并为 `PASS`，完整 RC 仍保留原 30 秒采样要求。

## FS3：体素美术与 HUD

FS3 选择一致的 16x16 或 32x32 像素风格，重绘或替换当前高饱和占位图集；快捷栏显示方块/
物品图标和数量，减少调试式文字，增加手持物、采集粒子、拾取和命中反馈。继续复用当前
ImGui 状态/命令边界，不在本批迁入 MiniGame 的 XML/Lua UI 或受其资源许可约束的资产。

当前实现选择 16x16 图集并固定以下边界：

- `DefaultPack.png` 保持 256x256 和既有第一行方块坐标；箱子、工作台、熔炉、玻璃、无框玻璃
  与木板使用第二行专属单元，物品和工具使用第三行专属单元。
- `Material::iconCoordinate` 是 HUD 图标的唯一坐标表；快捷栏绘制图标、数量和工具耐久条，空槽
  只保留键位和弱化占位符，不再输出 `Empty x0` 调试式文本。
- 当前手持物以图集图标在右下角绘制轻微呼吸摆动；方块破坏、放置、拾取/制作和战斗命中使用
  不同颜色的准星反馈，采集进度同时保留条形和环形表达。
- 生成源、两轮提示词摘要、哈希和许可边界记录在 `docs/reports/art-asset-sources.md`；固定裁切与最近邻
  打包由 `tools/build_fs3_texture_atlas.ps1` 完成，不直接手改运行时图集。
- 自动回归由 `caseOreTextures` 的 `FS3/*` 断言覆盖材料目录映射、交互方块专属格和十个物品格
  的填充/唯一性。实际 HUD 仍以隐藏 RuntimeReadback 截图检查，真人输入统一留给 FS3 后的 R3。

FS3 的 2026-08-24 关闭证据：

- Debug/Release 客户端、世界回归和资源包回归完成；两种配置世界矩阵均为 `539/539`，资源包
  均为 `27/27`，资源清单为 47 项。Release 首轮 V5 在高负载下触发 5 秒采样误报；保留最终
  进展要求并把 Windows 等待上限放宽到 15 秒后，无并行负载复测为 `539/539`。
- `docs/screenshots/validation-fs3-hud-noon.png` 显示五个独立图标、选中边框、数量/耐久条和
  右下角手持石剑；`docs/screenshots/validation-fs3-container-hud.png` 证明新版快捷栏可与箱子
  UI 同时工作。两图均来自真正隐藏的 Release OpenGL RuntimeReadback。
- 隐藏窗口增加 `WS_EX_NOACTIVATE`，截图/性能脚本默认隐藏；隐藏客户端不执行 OIS
  `capture()`，因此不会抢占前台，也不会读取用户正在其他窗口输入的键鼠。焦点守卫实际确认
  `foreground_owned=false`、`visible_window=false`、退出码 0。
- R3 v1 仍为 `NOT_RUN`，RC0 已被 BETA-RC 取代；v1 即使通过也不再自动关闭当前 D4/D6。
  后续 Physical Input v2 与独立产品体验使用显式前台 Release 窗口执行，不反向改写 FS3 的
  自动实现和截图状态。

## 非目标

- 不更换 Ogre GL3Plus，不新增 D3D/Vulkan 后端。
- 不在 FS1 改 terrain generation version、世界保存版本或目标定义。
- 不在 FS2 首轮引入 PBR、实时反射、级联阴影、天气系统或重型后处理框架。
- 不复制 `F:\env1_trunk` 的美术资源；只参考其渲染/UI 分层和有界资源管理思路。

FS2/FS3 是已经冻结的 before 基线，不代表视觉方向结束。BETA-RC 后的顶点平滑光照/AO、材质
管线、原创资产、生态 tint/变体、定向大气/立体云、可选方向阴影和轻量后处理已拆入 Stage 10，
权威顺序与退出条件见
`docs/archive/visual-quality-roadmap.md`；新批次必须保留本文固定 seed/位置/时间截图作为比较基线。
