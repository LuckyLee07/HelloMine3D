# 冒险世界 B5 持久探索地图合同 v1

用户已授权[完整体验目标](../current/adventure-experience-goal-prompt-2026-09-22.md)。
本合同限定持久地图的数据来源、容量和失效方式；B5a 已完成有界观察数据层，
B5b 已完成独立文件、世界备份与真实世界保存接线。B5c 的个人标记值层、文件 v2、
World 命令、文件 v4 的任务绑定及平面地图页面已接入，实际窗口操作仍待验收。
这些工程结果不代表玩家已能在界面使用持久地图。进度见[执行记录](../reports/adventure-experience-execution-2026-09-22.md)。

## 数据真值与容量

- 只接收玩家世界已加载区块中的 `SurfaceMapSample`。锁忙或缺失时保持未知，
  不能调用地形生成器、同步加载远区块，或用任务位置反推出未到达的地形。
- 归档按世界坐标每 4 m 一个地表单元；32×32 单元为一页，负坐标采用数学向下取整。
  已知空列与未知列不同。再次观察同一单元可刷新真实方块编辑后的高度和材料。
- 最多 4096 页；包含容器节点开销的内存保守上界小于 16 MiB。达到容量时保留已有记录，
  拒绝新增页并向界面返回明确满额结果，不循环淘汰玩家未备份的探索历史。
  持久文件最多 64 MiB；超过容量应拒绝保存并维持旧的有效文件。
- 已探索归档是地表资料，不等同视线可见性或地下洞穴地图。临近玩家的现有 1／2／4 m
  局部样本仍优先绘制，可在远区平面总览使用 4 m 归档；未知区域持续遮蔽。

## 持久化与世界边界（B5b 已实现）

- 使用世界目录内独立版本化地图文件，不扩大当前 64 KiB 的 `world.meta`。
  世界存档 v12 与地形 v22 不因地图表现自动改变；旧世界地图默认为空，首次真实观察后再写。
- 文件含格式版本、世界 ID、种子、地形版本、页数／标记数、长度和校验。
  载入只接受匹配当前世界身份的有界完整文件；重复页、非法材料／坐标、截断及校验错误
  退回空地图并提示，不使世界目录或主存档无法载入。
  地图文件 v2 追加有界标记记录、下一个稳定 ID 与追踪 ID；v3 再追加至多一个由真实
  方块放置或界石交互发现的任务地点。读取 v1 时标记／地点默认为空，读取 v2 时地点
  默认为未知。v4 追加独立的任务绑定界石（至多一个）；v3 仅有发现记录，
  不自动将其升级为活动任务绑定。下次真实写入升级为 v4。每个标记的 ID、UTF-8 名称、单一基地与已探索
  位置必须有效；任务地点仅存正高度的世界坐标。存储 API 要求显式传入标记与地点，
  绑定地点也须显式传入，避免保存地表时误清空已有导航信息。
- 发布沿用 `StorageTransaction` 的候选写入、持久刷盘、完整校验、原子替换与失败隔离；
  `WorldBackup` 的创建、验证、恢复和回滚必须包含可选地图文件。地图保存失败不得伪称
  世界完整保存，备份不得遗漏存在的地图。容量上限和备份总量需配套检查。
- 切世界、退出和恢复备份清除旧世界内存；页内记录从实际重新观察更新，
  未重新加载的远区保留上次已知地表而不伪称当前状态。
- 生产 `World` 每 10 个固定 tick 最多查询玩家周围 81 个 4 m 地表列；锁忙则跳过。
  HUD 小地图和详情页通过 `World::observeSurfaceMap` 共享真实采样到归档的路径；
  UI 每次最多 195 列、至多 30 Hz，两视图不重复发起该预算。HUD 暂停模拟时仍可记录已加载地表。
  归档只更新 X/Z 均为 4 m 整数倍的规范列，避免更密小地图样本在同一归档格内反复改变材料。
  API 上限沿用底层 256 列，未知或锁忙不生成、不加载，不擦除远区历史。
  观察改变时才发布地图，顺序为区块／元数据、地图、备份。
  退出时同样保存未写出的观察。损坏或错身份文件隔离为同目录 `.corrupt.failed`；
  隔离槽已有文件或路径不是普通文件时不覆盖它，并明确报告保存失败。
  `ExplorationMapStatus` 向界面提供当前会话的损坏／身份重置原因、隔离失败、保存失败和
  满额状态，不将 stderr 当作玩家反馈。成功重试清除保存失败，重置提示保留本会话；
  新世界或健康重开使用新状态，不污染其他世界。

### B6 世界入口派生预览

- 世界目录可包含 `world-preview.hmp` v1。它是从已持久化 `ExplorationAtlas` 真实已知格
  重采样出的非权威、可重建派生缓存；未知格保持未知，构建过程不得查询生成器、加载远区
  或补造尚未探索的地表。固定画布为 49×25 格、每格 8 m，完整文件不得超过 4096 B。
- 预览携带世界 ID、种子、terrain identity，以及来源 `exploration.hmap` 的文件长度和文件尾
  64 位 checksum 组成的 source revision。只在身份与来源修订都匹配时显示；缺失、损坏、
  身份不符或来源陈旧统一软回退，不影响 `exploration.hmap`、世界 metadata 或区块载入。
- `world-preview.hmp` 通过 `StorageTransaction` 原子发布。发布失败可以保留上一个缓存或无预览，
  但不能把已经成功的主世界／探索地图保存改报失败。该派生文件不提升 world save v12、
  terrain v22 或 `exploration.hmap` v4，也不加入世界备份。
- 恢复备份后必须删除或拒绝恢复前的陈旧预览；后续正常保存可从恢复后的真实归档重新生成。
  世界列表枚举不读取该文件，只有用户选中一个已枚举世界后才允许管理服务执行有界读取。

## 地图导航与界面（B5c 部分实现）

- 个人标记最多 64 个，支持创建、重命名、移动、删除和跟踪；满额有明确反馈。
  出生／基地位置以玩家确认的保存信息显示，营地／路标只在实际发现后显示。
  B5c 已建立 `ExplorationMarkers` 值层、兼容 v1 的文件 v2 和 World 命令；稳定 ID、
  单一基地、单一追踪、UTF-8 名称和容量边界均可验证。World 创建或移动标记前必须确认
  该 4 m 单元已探索；如尚未归档，最多向驻留区块查询一个真实列，锁忙或远区仍拒绝。
  玩家地图页已接入创建、重命名、设基地、追踪、移动和确认删除，标记在已探索的平面图
  显示；小地图显示当前追踪点的方向和距离。普通输入、紧凑布局和保存重开的界面回路
  尚未实机验收，不把编译视为已证实可用。画布、列表和新增入口共用稳定 ID 与名称
  缓冲的选择更新；删除／切世界清理。底图北向，玩家箭头与小地图按同一 yaw 计算方向。
  地图异常在小地图显示标识，在详情页展开原因；备份入口先按原正常关闭流程保存并
  打开对应世界备份列表，失败则保留会话并说明原因。实际恢复仍需现有确认且回滚整世界，
  不静默覆盖地图、删历史或绕过保存失败。
- 已知任务目的地提供方向和距离；目标未发现或没有权威坐标时不揭露生成结果。
  当前仅当玩家实际放置或使用的界石已有已知坐标、且任务为对应仪式／防守阶段时，
  平面图才绘制任务位置与方向／距离。早期寻找、修复等无固定坐标目标不推导生成点。
  玩家放置界石更新最近发现地点；成功激活／继续事件或恢复真实事件锚点时，
  同时记录独立任务绑定。导航优先绑定，其次运行时事件锚点，只有任务尚未激活时
  才回退到最近发现。普通新放置不能覆盖任务绑定；拆除时分别清除匹配的记录。
  两记录随 v4 地图保存、备份和恢复，远离所在区块重开仍可导航。旧 v1/v2 没有地点，
  v3 没有可靠任务绑定，无法凭生成器或既有任务进度补造；真实交互／事件恢复后才获得。
  多个界石的发现仅保留最近一个，后续地点列表须另行有界设计。
  玩家标记导航使用北向八方位与地表水平距离；极端旧存档坐标先扩宽再相减，
  不产生溢出或虚构路径。
  平面总览以归档内真实地表作底图，129×129 屏内、可平移复看和点选材料；
  查询支持 4／8／16／32／64 m 每格；显示可独立继续放大到 16 倍，不改归档精度。
  首次按当前渲染范围适配至视口短边约 82%，回到玩家可重新适配；两种状态都为当前世界临时 UI 状态。缩小时每格从实际记录的 4 m 单元选离中心最近的
  代表样本；有任一实际记录的格才显示已知，且标记使用代表样本的真实坐标，未知区域
  不补生成预测。总览查询只扫描视口覆盖的现有归档页，不读盘、不加载区块；临时结果
  至多 16641 格。局部立体详情独立覆盖当前渲染距离加一 chunk 对齐余量，按中心向外分批观察；
  不再把小地图 64／128／256 m 的显示范围当成已加载场景范围。缓存最多 129×129 列，
  基础 4 m 间隔；大渲染距离按 8／16／32 m 取样，仍只展示实际采到的列，粗略采样不是逐方块几何。
  驻留列卸载后从立体图清空，归档继续保留最后已知记录。移动／范围变化按世界坐标保留重叠列，
  只将尚未观察的边缘列加入优先队列；队列完成后继续轮询已有列以刷新编辑和卸载，切世界清空。
  玩家箭头按 X/Z 对应的已观察地表投影，飞行高度不将其移到地图边缘，未知地表不虚构落点。
  平面视图在归档之上优先绘制当前真实驻留地表，使用与小地图相同的材料／高差配色。
  平面实时缓存上限 257×257 列，基础 2 m、RD8 为 145×145；大渲染范围自适应 4／8／16 m。
  独立于平面缩放保留附近细节，不把实时树林／海岸先聚合成粗色块。悬停、选中与标记采用
  优先显示的真实细列坐标；未知细列回退到历史已知归档，不预测地形。平面、立体和小地图
  仅活动视图消费每次 195 列／30 Hz，暂停也可刷新；平面新增临时 CPU 数据预算小于 6 MiB，
  不扩大归档页数、磁盘上限或改变文件版本。默认适配不随部分行到达而跳变，手动缩放／平移保持。
  另用至多 2048 个 16×16 m 页保留当前世界会话的 2 m 实际观察，最多 131072 个细列，
  超额淘汰最久未被重新观察的页；不会擦除持久归档。该容量包含最大 257×257 实时视图，
  不会因当前窗口自身超过容量而产生缺块。小地图与平面图复用现有查询填入细历史，不新增世界采样。
  未知不会擦除最后已知细节；视口外不绘制，跨页高差配色使用真实相邻列。最大细历史几何为
  524288 顶点／786432 索引，ImGui CPU／GPU 绘图缓冲另外计入实测，不混入 6 MiB 数据预算。
  平面实时层或小地图使用较粗间隔时，新回复可刷新细历史中同一实际 X/Z 的既有已知 2 m 列，
  避免旧细层绘制和优先选点遮住该列的新高度／材料。只能刷新精确偶数坐标，不创建细页或
  未观察槽，不向相邻 2 m 列推断；已知空列可替换旧地表，未知或锁忙回复仍保持旧记录。
  有效且长度匹配的回复即使未改变实时缓存，也可刷新细历史及其页的最近观察顺序；
  容量、采样预算和持久格式不变。V10i 接入活动平面视图，V10j 接入 256 m 小地图的 step4；
  64／128 m 小地图的 step1／2 保持原观察路径，立体图不新增观察。
  世界退出清除细历史，保存重开仍使用既有 4 m 持久记录，不宣称 2 m 历史已落盘。
  规范 4 m 列仍进入归档，因此旧世界、离开区域和保存重开沿用既有规则。
  同一世界关闭再打开保留缩放、平移和立体方向，只有“回到玩家”主动复位；采样回复按世界坐标校验，
  旧中心回复与锁忙不能写错位置或跳过待补边缘。
  视图切换保持玩家当前位置及操作反馈。
- 普通输入检查离开后复看、重启、切世界、标记编辑、追踪返家；诊断坐标镜头、
  预置存档和自动测试只能证明对应工程语义，不能代替普通探索。

### V06c 实际改块与地图原像素工程证据

V06c 在冻结的 seed42 河流机位、RD1、256 m 小地图和全新隔离世界中，选取自然水柱
`(220,64,-204)`，通过原生产放置／拆除命令及原世界更新、网格上传和 UI 绘制路径检查六阶段。
步骤为基线、水下填砂、恢复水下方块、表面填砂、拆除表面砂块、精确恢复原水块；恢复步骤为
诊断直接写回，库存也是诊断准备，不能计作普通玩家操作。标准／兼容材质均正常退出，独立
`tools/tests/shore_edit_capture_oracle.py` 各通过 208 项，结果为
`PASS_SCOPED_STORAGE_WORLD_MAP_PIXELS`，不是完整地图或普通玩法 PASS。

编辑后必须先等到 256 m HUD 的新 step4 回复，记录其已更新的精确同列 2 m 细历史，再打开
RD1 的 step2 平面实时视图。捕获帧中平面视图没有再次查询目标列，因此其正确颜色不能掩盖
HUD 未刷新细历史。实际绘制仍使用生产细历史优先层与生产表面解析；捕获分别核对目标、
西／北细列的绘制事实与未修改的原 PNG 像素。目标在 Water64、Sand64、Water63、恢复
Water64 时显示对应材料／高度颜色，西／北细历史和显示像素保持不变。该检查不证明鼠标
悬停或点选，不将目标以外的细邻列绘制事实扩称独立完整 World 真值。

独立检查同时读取原生产 uploader 的 CPU 输入与原生 VBO／IBO 存储，核对当前 44 B 顶点、
u32 索引、有限数值、索引范围、实际上传修订与驻留状态，并由真实 3×3 World 水柱独立计算
目标四角水深。读取原存储不等于验证 Ogre 内部 VAO 的最终取数，也不证明地形像素逐三角形
归属、原子 World 快照或 incarnation／ABA。2 m 细历史仍只属本会话；4 m 归档重开不能由
本次六帧或 `World::save()` 成功单独证明。另由正式 `shore_world_reopen_test.cpp` 对两套实际
恢复态存档各58项通过：原存储codec与公开World重开→save→再重开，调用observe前就有
canonical Water64历史，400归档格不增；原Water64／63 metadata和库存保持。只证明恢复态
production重开，不关闭编辑态保存或普通UI重开，首轮helper错误文件数假设失败保留。

五类负例在真实捕获文件的独立副本中改写原始缓冲或事实，并重算外层 SHA：NaN、错误 stride、
越界索引、旧水深 UV、缺失 HUD 细历史均在通过文件哈希检查后被语义检查拒绝。它们证明
oracle 可识别这些错误数据；跳过生产上传、取消深度更新、恢复旧 UI 刷新代码等源码生产者
故障在 V06c 当批为 `NOT_RUN`，不能用文件副本负例替代；后续实际校准见 V06d。

目录且不存在的明确路径，拒绝其他诊断夹具。实际已有 save／共用 save-catalogue 两例均
正常拒绝（exit1、无 signal），已有哨兵保持不变；独立源码复核确认原 camera／fern 保护路径
不变。195 列／30 Hz、2048 细页、131072 细列与地图文件版本沿用原规则。原始记录见

### V06d 生产源码故障校准（2026-10-06）

在独立故障副本中省略 HUD 的粗回复→既有细历史刷新，经实际编译、链接和原客户端运行后，

`SOURCE_PRODUCER_REJECTED_BY_HUD_FINE_READINESS_GUARD`；捕获不完整，独立 oracle 为
`NOT_RUN_INCOMPLETE_CAPTURE`，不能称 oracle 已拒绝旧 HUD 生产者或六阶段已完成。

另一源码变体将生产水深固定为基线2.0，标准／兼容各完整捕获六阶段、native exit0、无 signal；
未修改的独立 oracle 均在阶段1检出真实 World 四角预期1.75与原 CPU／GPU 存储2.0不符。
正常代码同条件正控两模式各208项通过；源码副本、替换的单一生产对象、实际包输入与原件
身份均单列核对，区别于 V06c 仅改捕获数据的五类负例。

本批校准仅覆盖实际 pixel ratio1、1280×720 原帧；此前 ratio2 正控失败保留，不写成当前
