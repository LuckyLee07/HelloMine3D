# E6 林地层次与植被斑块 terrain v12 合同 v1

冻结日期：2026-09-17。实际起始 commit 为
`3e732a1e62b5e03d7b3e1ba0d1eb1a86091f9b33`，修改前工作区干净。E5 的 terrain v11 自动工程
证据已通过，窗口、性能和中文正常玩法因 Computer Use 仍判断图形会话锁定而延期；E2 的林地
流送 P99 失败继续独立挂账，不作为本批性能豁免。

v11 生产基线使用当前 C++ 生成器新增的只读 `E6-VEGETATION-SURVEY` 导出。16 个固定林区来自
E5 已冻结的 v11 宏观 CSV，在修改装饰规则前选定；每个林区生成 3×3 个真实区块，共 144 个
区块、36,864 个地表列。两次独立导出的 `sites.csv`、`chunks.csv` 与 `columns.csv` 均逐字节
一致。身份、位置与描述统计见
[E6 v11 冻结清单](../reports/ecology-e6-v11-vegetation-baseline-2026-09-17.json)。

## 本批玩家可见范围

追加 terrain v12，只重组新世界的树木与地表植被放置规则。以 seed、带符号世界 XZ、v11
规划列和确定性低频场生成疏林、密林、林缘地被和小片花草；现有橡树使用 3 种有界体素轮廓，
形成高低、冠幅和天际线变化。规则必须是纯规划，不读取或同步加载邻区块；跨区块树体仍由
现有 StructureBuilder 投影。

v12 不改变 v11 高度、生态标签、地表材料、岸线、水系、洞口、矿物和地点规划；不加入新
方块 ID、树种物品、贴图、shader、动态风、季节、腐烂、树木生长、存档格式、区块生命周期或
渲染系统。v1–v11 旧世界和已保存区块永久走原路径。

## 修改参数前冻结的自动退出条件

1. v1–v11 的生产 `T0-SURVEY` 样本与区块指纹逐字节不变；terrain v12 在八 seed、正负坐标、
   区块边界、正逆加载和独立生成时确定。v12 的公开高度、生态与 v11 逐点一致，已保存区块和
   玩家改块在重开后不重生成。
2. 由一个纯生态规划器决定树锚点、树形和追加地被。它只消费 seed、世界坐标和 v11 列，
   不持有 Chunk、随机流或可变全局状态。新规则不得旁路现有生成版本、StructureBuilder halo
   或装饰物地面清理。
3. 三种橡树轮廓都必须在八 seed 的固定生产林区中出现；独立形状夹具验证树干、树冠连通、
   最大水平半径不超过 3、总高度不超过 12，并保留至少 3 格可见树干。轮廓仍为有体积的方块
   叶簇，不能退回薄十字片、随机缺洞或跨格悬伸渲染。
4. 固定 144 区块中的树根总数保持在 v11 基线 425 的 `70%..130%`，即 `298..552`；每个 seed
   的两个固定林区合计至少 20 个树根。至少 12/16 个林区同时有疏区块（树根不超过 1）和
   林区块（树根至少 4），避免把全图变成同密度棋盘；木材获取距离不得劣于现有资源门槛。
5. 固定区块的高草、花和枯灌木合计从 v11 的 751 提高到 `900..2200`，但任一地表列最多一个
   装饰物。追加植被只能落在匹配地面：高草/花在草方块，枯灌木在沙方块；不得落水、悬空、
   覆盖地点或重新填满 v9 草甸开窗。至少 12/16 个林区须同时包含低密度和高密度地被区块，
   证明是斑块而非均匀撒点。
6. 八 seed 的安全出生、木石煤铁沙草、洞口、Waystone、Ruin、RaiderCamp 仍可找到和接近。
   运行 Debug/Release `E6_VEGETATION` 聚焦、完整 WorldRuntime、v1–v12 生产调查及相关存档/
   资源回归。
7. 窗口阶段复用唯一项目 `.app`，在一次 Release 启动中拍同 seed/XZ/朝向/时间/画质的
   v11/v12 林地与林缘原图，并各做三轮常驻和快速流送；P95/P99 三轮中位数比值均不超过
   `1.10`。Computer Use 仍不可用时按用户当前指令记 `NOT_RUN` 并继续工程批次，不能用离屏
   自动测试冒充窗口或正常玩法。

实现、自动验证、窗口证据和结果文档分开本地提交；不推送、发布或打标签。失败原件全部保留，
不得通过删除样本、改基线或放宽门槛换取 PASS。
