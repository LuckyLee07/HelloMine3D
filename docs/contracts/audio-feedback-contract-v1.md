# G5/N6/N12B/B9 音频反馈合同 v1

> Architecture Lab 迁移说明（2026-08-31）：G5/N6/N12B 的工程与资源证据保持冻结；
> 2026-09-26 的冒险世界 B9 在兼容旧定义的前提下追加区域、动物与脚步声音。人类听感必须
> 由实际可听验证单独记录，不能用定义、日志、编译或自动断言代替。

本文固定 HelloMine3D 基础反馈与冒险环境声音的数据、只读世界输入、调度、播放、降级和验证
边界。声音只能表现已经存在的世界事实，不能改变玩家、动物、地形、探索图、任务、存档或
区块驻留。音频失败不得阻止世界加载、保存、切换或退出。本合同不引入 FMOD、流式环境循环、
音频资源热更新或可执行资源包扩展；低密度音乐仍由
[流式音乐合同](streamed-music-contract-v1.md) 独立约束。

## 定义格式与版本兼容

正式基础定义位于 `media/audio/Base.audio`，当前首行必须是：

```text
# HelloMine3D audio definitions v4
```

每条非注释行使用固定字段；逻辑路径、字幕 key 和英文降级字幕都带引号：

```text
sample <id> <category> <mode> "<logical_path>" <gain> <max_voices> "<caption_key>" "<fallback_caption>"
```

- `category` 只允许 `ui`、`effects`、`ambient`；`mode` 只允许 `2d`、`3d`。
- `logical_path` 必须是 `media/audio/samples/*.wav` 下不含反斜杠、盘符、空段、`.` 或 `..`
  的规范路径；运行时拒绝绝对路径和目录逃逸。
- `gain` 必须在 0–1，单 cue 并发数必须在 1–8。id 必须唯一；未知字段、尾随数据、重复 id、
  非法数值或缺少必需 cue 都拒绝整份定义。
- `caption_key` 必须精确等于 `audio.<cue-id>.caption`。英文降级字幕必须包含 1–96 个可打印
  字符；本地化目录正常时仍由语义 key 决定显示文本。
- 解析器继续接受历史 `# HelloMine3D audio definitions v3`。v3 只要求原有 9 个 cue；v4 要求
  原有 9 个与新增 15 个 cue 全部存在。多个定义源必须使用同一版本，v3/v4 混用明确拒绝。
  v3 兼容仅保留旧测试、旧资源视图和历史证据，不把缺少冒险 cue 的 v3 当成当前正式资源。

v3 的 9 个稳定 cue 为 `ui.click`、`block.break`、`block.place`、`item.pickup`、
`craft.success`、`combat.hit`、`combat.windup`、`combat.guard`、`ambient.wind`。v4 追加：

- 区域环境：`ambient.open`、`ambient.forest`、`ambient.river`、`ambient.coast`；
- 动物：`animal.sheep`、`animal.rabbit`、`animal.marsh-bird`；
- 脚步：`footstep.grass-dirt.1/.2`、`footstep.stone.1/.2`、
  `footstep.wood.1/.2`、`footstep.sand.1/.2`。

当前 v4 共 24 个 cue、23 个唯一 WAV；`ambient.open` 与历史 `ambient.wind` 共用同一采样。
全部采样合计解码 PCM 为 1,298,306 字节。原 9 个 WAV 继续由
`tools/generate_n12b_audio_samples.ps1` 拥有，新增 14 个 WAV 由
`tools/generate_adventure_audio_samples.py` 确定性生成和检查。资产统一为 44,100 Hz、单声道、
PCM16、小端 RIFF/WAVE；单文件必须为 44–524,288 字节且持续 10–3,000 ms。生成脚本、逐文件
SHA-256、来源记录及 `media/audio/samples/LICENSE-HelloMine3D-Audio.txt` 一同进入仓库。

清单分别使用 `audio`、`audio-sample` 和 `license` 类别。这三类在 resource-pack v1 中均为
base-only，不能被现有包覆盖；未来允许替换音效时必须显式升版资源包合同。缺定义或采样属于
可降级启动资源，随包许可证缺失仍是发行错误。

## 业务事件与只读世界输入

业务层只发布“动作已经成功”这一事实，不接触播放设备。`AudioRuntime` 订阅活动世界的
`SandboxEventBus`，并把基础事件映射为提示：

| 业务事实 | cue | 位置 |
| -------- | --- | ---- |
| 方块成功破坏 | `block.break` | 3D，目标方块位置 |
| 方块成功放置 | `block.place` | 3D，放置位置 |
| 物品实体成功进入库存 | `item.pickup` | 3D，拾取位置 |
| 实体实际受到伤害 | `combat.hit` | 3D，受击位置 |
| 敌人进入攻击前摇 | `combat.windup` | 3D，敌人位置 |
| 玩家成功格挡 | `combat.guard` | 3D，格挡位置 |
| 制作事务成功提交 | `craft.success` | 2D |
| 成功的菜单/UI 操作 | `ui.click` | 2D |

一次业务动作最多产生一次基础声音。失败的放置、破坏、拾取、攻击或制作不发布成功事件，UI
也不能用额外点击声重复制作成功声。世界切换时先解绑旧事件总线，再绑定新世界；保存、关闭或
切换失败时恢复原绑定，避免悬空订阅和重复播放。

`AdventureAudioPresentation` 只消费 Ogre 壳从活动世界复制的事实：玩家位置、是否落地/飞行、
脚下实际方块、世界时刻的 daylight、真实 `ActorSnapshot` 的稳定 id/物种/活动/位置，以及玩家
周围 5×5、间隔 8 m 的地表观察。地表观察优先使用驻留区块的 `SurfaceMapSample`，未驻留列只
读取同一世界已冻结的地形生成器 biome/表面高度，不请求或生成区块，不揭示探索图，也不写回
World、Actor、Player、地图或存档。玩家低于中心地表 4 m 以上时不提交地表环境声。

冒险声音按以下规则派生：

- 旷野与森林按附近 biome 权重平滑过渡；内陆水只来自 River/Lake 或驻留样本中的 Water。海岸
  必须在同一有界探针格内同时存在 Ocean 与陆地证据；纯外海不冒充海岸。河流/湖泊和海岸使用
  不同 cue 与空间位置，不能用同一“水声”冒充。
- 调度器保留旷野、森林、内陆水、海岸四种候选，内陆水与海岸互斥，单帧最多暴露 3 个权重最高
  的有效环境层。权重约 2 秒连续收敛；Ogre 壳使用固定四槽倒计时有界重播冻结短采样，旷野层以
  约 1.45 秒、森林／内陆水／海岸层以约 2.25 秒为昼夜中值，白天稍密且稍强、夜间稍疏且稍弱，
  允许同层最多两个声部短暂交叠以覆盖接缝。它不建立流式或无限循环，也不随帧率增加计时器、
  采样或声部。
- 羊、林兔、湿地鸟只来自当前帧真实动物快照，最多跟踪 24 个来源、32 m 可听范围；活动状态影响
  触发优先级和冷却，同一时刻只选择一个有资格的真实来源，卸载或离开观察后清除临时槽位。
- 脚步以玩家真实水平位移累计，每 1.65 m 最多触发一次；草土、石、木、沙各有两种确定性交替
  变体。未落地、飞行、未知支撑面、表面类别变化、暂停/UI 捕获、世界切换或单帧位移超过 4 m
  都重置累计，避免传送、重生和恢复焦点后补播脚步。
- 每帧最多提交 3 个冒险 cue；所有数组、来源槽、冷却和计时均固定有界。调度状态只属于当前
  表现会话，切世界或玩家事实失效时清空，不进入保存格式。

## 后端、混音与生命周期

- 启动时一次性严格解码并冻结采样库；相同逻辑路径只缓存一份。唯一采样最多 32 个，解码后
  PCM 总量最多 4 MiB；当前 v4 为 24 cue/23 唯一采样/1,298,306 字节。
- Windows 默认使用系统 `waveOut` 输出立体声 PCM；播放时只从冻结的单声道采样复制并应用
  gain、距离衰减和左右声像，不在提交路径打开文件或合成波形。
- macOS 默认使用系统 `AudioQueue` 输出 44.1 kHz 双声道 PCM。单一输出队列在固定 16 槽声部表
  中混音，回调复用三个固定 512 帧缓冲；2D/3D gain、距离衰减、左右声像和 cue 并发限制与
  Windows 路径一致。挂起时暂停队列，恢复时续播；销毁时停止并释放队列。
- Linux、其他未实现原生后端的平台、定义/采样缺失、无音频设备或显式设置
  `HELLOMINE3D_AUDIO_BACKEND=dummy` 时使用 dummy。dummy 保留事件、并发和统计语义，
  但不打开设备、不发声。
- 全局同时播放上限为 16；每个 cue 还受定义中的 `max_voices` 限制。3D cue 根据 listener 位置
  与朝向计算距离衰减和左右声像；2D cue 不受世界位置影响。
- 声部接纳为 UI 分类和 `combat.windup`／`combat.hit`／`combat.guard` 留出 4 个余量：
  其余环境、动物、脚步和普通交互声仅在总活跃声部少于 12 时接纳，关键反馈仍可使用总上限 16。
  同 cue 限额保持；不抢占仍由原生回调读取的声部，不排队补播被抑制的事件。Windows、macOS、
  dummy 共用此接纳策略；关键反馈本身满额时仍有界抑制，不承诺无限并发或由容量检查证明听感。
- 主音量先与 `ui`、`effects`、`ambient` 分类音量相乘；设置应用后立即更新。静音或零音量抑制
  听觉播放；恢复后只接受新事件，不补播已经跳过的事件。
- 世界暂停时，运行时对已经播放的世界声执行一次 `stopAll`，调度器不推进；后端本身继续可用，
  因而暂停菜单的 `ui.click` 仍可播放。恢复后只接受新事件，不追赶暂停期间的环境、动物或脚步。
- 只有窗口失去焦点才全局挂起真实后端；环境重播倒计时同时冻结，重新获得焦点后续播后端声部并
  恢复原倒计时，不叠加一份新环境声，也不补播挂起期间的声音。
  容器、合成、HUD 地图或其他 UI 捕获输入时冻结脚步与动物调度并重置脚步累计，但世界未暂停时
  已有环境床继续按固定层权重重播，后端保持可服务 UI 点击反馈。
- 世界结束、切换、启动失败和退出都必须清空调度状态、解绑总线并幂等停止后端。后台回调不能
  越过冻结采样库或 `AudioRuntime` 生命周期。

## 字幕语义

所有 24 个 cue 均有双语语义 key。字幕启用后，运行时在静音或零音量下仍可提交字幕；关闭字幕
立即清空，缺定义、世界暂停抑制的非 UI cue 或未发生的世界事实不生成字幕。重新启用字幕时，
仍在播放的环境层允许重新公告一次。环境层从无声转为首次可听时提交一次字幕，动物实际鸣叫时
提交字幕；同一环境层的后续有界重播与所有脚步使用事件级
`caption=false`，避免环境床或连续行走反复刷新字幕。环境、动物和脚步字幕使用最低优先级；交互
提示可替换它们，命中和战斗预警继续拥有更高优先级。允许提交字幕的同一 cue 刷新既有 2.5 秒
寿命。字幕显示不取得输入焦点，不反向驱动声音或玩法。

## 启动与失败语义

启动先冻结有效资源视图，再读取音频定义、解析全部被引用采样并创建运行时。定义头、字段、
版本组合、必需 cue 或任一采样非法时，相关 registry/bank 以空的冻结结果降级；不能保留一半定义
或一半采样。定义有效但采样不可用时，字幕仍可显示，听觉提交计入 `missingSamples` 后静默返回。
真实后端初始化失败自动转入 dummy；单次播放、回调、UI 字幕 sink 或设备生命周期失败只增加
有界诊断/统计，不能抛过玩家命令、保存、世界切换或退出。

当前 v4 正常日志至少说明定义数量、唯一采样、解码大小和所选后端，例如：

```text
[AUDIO_REGISTRY] frozen=1 definitions=24 samples=24 unique_samples=23 decoded_bytes=1298306 degraded=0
[AUDIO] backend=macos-audioqueue real=1 definitions=24 samples=24 unique_samples=23 decoded_bytes=1298306 degraded=0
```

## 验证合同

B9 代码批次至少覆盖：

1. v3/v4 严格解析、各版本必需 cue、混版拒绝、规范路径、字幕 key、重复/范围/尾随错误和
   缺文件降级；历史 v3 fixture 不因生产 v4 失效。
2. 23 个正式 WAV 的 RIFF 大小、PCM16/单声道/44.1 kHz、时长、逐文件哈希、共享路径去重、
   24 cue、1,298,306 字节精确总量、32 样本/4 MiB 上限及损坏/缺失降级。
3. 四类环境候选、河海互斥与不同 cue、地下抑制、三类动物、四类脚步、两种步态变体、昼夜
   冷却、世界 epoch/暂停/UI/飞行/传送重置、24 来源与每帧 3 cue 上限的纯调度正反例。
4. 世界适配只读取已复制或有界查询的真实事实；不得加载区块、写探索历史、改变动物/玩家，
   或让表现反馈成为 Gameplay 条件。
5. 方块、拾取、制作和战斗基础事件的精确一次语义，2D/3D、分类/主音量、暂停、焦点、静音、
   dummy、缺定义/采样、字幕优先级、解绑与 16 声部/单 cue 并发上限；背景和普通交互高并发时
   关键反馈余量可用，暂停与解绑后容量释放。容量工程检查不替代实际可听性。
6. resource-pack v1 拒绝定义、采样和许可证覆盖；缺基础音频时有效资源视图和启动预检仍可完成，
   许可证缺失则失败。
7. Windows 与 macOS Debug/Release 受影响构建、`WorldRuntimeSmoke`、`ResourcePackSmoke`、资源
   清单正负例、强制 dummy 隐藏校验及适用平台真实后端生命周期。实际听感、空间感、循环接缝和
   音量平衡必须在可听客户端中另记 `PASS/FAIL/NOT_RUN`，不能由上述自动证据代替。

## 历史冻结证据

2026-08-17 的 G5 历史关闭证据为：资源清单 40 项，清单门禁 3/3，资源包门禁 23/23，世界
运行时门禁 403/403；Debug 与 Release 的验证模式和三帧运行均在隐藏窗口中以退出码 0 完成。

N12B 的 2026-08-26 正式证据为：9 个原创 WAV 的固定哈希/格式检查、严格 v3 定义、312,230
字节解码缓存、共享路径去重、损坏/缺失静音降级和生命周期自动断言通过；资源清单为 61 项，
双语目录各 346 个 key。VS2017/v141 Debug/Release 客户端、681/681 世界和 34/34 资源包目标
通过；隐藏校验和真实三帧客户端均退出 0，真实运行报告 `windows-waveout real=1`、9/9 采样和
`degraded=0`。完整门禁通过十三个测试目标、38 个性能夹具、128,209 字节受控 dump 和 81 文件
包；发行 ZIP SHA-256 为 `1F7AEBFF35A796053A739D99CE060C14A7E39459A818DC1A6B609C5A778C416F`。
同身份可用菜单 `711.836/712.408 ms`、首次可控世界 `398.068/416.950 ms` 均比较 `PASS`。
这些数据只证明历史 v3 基线，不证明当前 v4 的新增环境、动物、脚步或 macOS 听感。当前实际
可听证据以冒险体验执行报告为准；未执行项目必须保留 `NOT_RUN`，人类听感不得由本文宣布。
