## 本批玩家可见范围

追加 terrain v9，仅在离岸内陆的 LightForest、TemperateForest 中用 seed 与世界 XZ 的低频连续规划形成有宽窄变化的草甸开窗与疏林边缘。开窗地面使用现有草块，让树群稀疏、草花仍有合适地面；草地、林地和山地的高度、近岸 v8 岸线/浅滩保持原值。目标是飞行观察时森林不再连续铺满同一种树冠密度，步行时能看到可穿行的林间空地。沙漠、海洋、水面、水深、河网、新方块、存档格式、区块加载与渲染系统不纳入本批。

新世界默认使用 v9；旧 v1–v8 世界及已保存区块继续按冻结生成身份运行，不能把 v8 清理或材质逻辑回写到旧版本。生成区块、公开地表/生态查询、树木/草花、洞口和地点规划必须消费同一 v9 列；纯规划不加载邻区块。E2 尚存的性能 FAIL 独立挂账，不作为 E3 的性能豁免。

## 修改参数前冻结的自动退出条件

1. v1–v8 生产采样、生成区块指纹与既有冻结基线一致；v9 多 seed、正负坐标、区块边界、正逆/独立生成结果一致。v9 的高度与 v8 逐点相同，保持 1..176、相邻坡度不超过 3；高度 ≤80 和 Mountain/Desert/Ocean/原 Grassland 的规划列与 v8 一致。
2. 在来自生产生成器的八 seed 固定内陆采样中，v8 LightForest/TemperateForest 里转换为草甸的列比例处于 5%..30%，至少四个 seed 有连续 16 格以上的可穿行开窗；样本草甸不呈逐格椒盐状或固定等宽直条。该统计从 C++ 生成器/真实生成区块导出，不用 Python 复刻规划。
3. 新开窗树木不能留下悬空树干，草花只能落在可承载地面；出生资源、三类地点、洞口与矿物仍可获取和接近。已保存旧世界与玩家改块保存重开不漂移；新 v9 世界存档与目录身份能重开。
4. 运行本机受影响 Debug/Release 自动、资源及存档回归；必要的实机性能对比使用同一个项目客户端并合并多组检查，不反复创建临时包。自动性能仍记录原始失败。真实中文菜单步行、采集、保存重开的人工/动态观察依用户要求延期，记 `NOT_RUN`，不得冒充 `PASS`。

本批只允许在生成规划、版本接线、相应测试/工具及本合同、执行报告、任务账本内修改。E3 能否认定完成另看全部真实证据；E2 的 `FAIL` 与人工缺项单独留在 E2 账本。没有推送、发布或打标签授权。
