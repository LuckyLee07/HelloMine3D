# 冒险地下空间 terrain v23 合同 v1

建立日期：2026-09-26。状态：B7 实施合同已冻结；terrain v23 工程、普通路线、画面与性能
尚未完成，不能由本文记为通过。

## 目标与范围

B7 在现有噪声洞穴和 terrain v4 天然洞口基础上，为新世界增加可辨认的大洞室、裂隙通道、
浅层地下水和两类有实际用途的地下目的地。入口、目的地和返程组成同一个确定性地下系统；
系统应提供矿物、有限补给、落脚位置和照明层次，而不是只扩大随机空洞或给洞穴换名称。
总范围沿用[冒险世界规划](../current/adventure-experience-plan-2026-09-22.md)，旧洞口语义见
[P11-2 合同](terrain-contours-cave-entrances-contract-v1.md)，流送硬边界见
[Backpressure 合同](streaming-backpressure-contract-v1.md)。

本批沿用现有体素水、方块、箱子、矿物、火把、光照、碰撞、区块流送和探索地图语义。
不加入流体模拟、瀑布、洞穴生态群落、地下城网络、新敌人、传送、地下全量地图、新方块 ID、
新 `StructureType`、独立生成线程或第二套区块生命周期。

## 版本身份与旧世界兼容

- 在 `LandmarkWorkshopTerrainGenerationVersion == 22` 后只追加
  `AdventureUndergroundTerrainGenerationVersion == 23`，并将新建普通世界的默认地形身份更新为 v23。
  world save format 保持 v12，继续由 `terrain_generation_version` 保存世界唯一生成身份。
- v1–v22 的高度、生态、普通洞穴、天然洞口、矿物、植物、地点、工位、方块实体、奖励、已生成
  区块和未来未生成区块规则必须逐版本保持。显式 v22 查询和生成不得进入任何 v23 分支。
- 已有 v1–v22 世界不迁移、不回填地下系统，不覆盖玩家建筑或修改过的区块。已保存区块仍以方块
  数据为准；同一世界不会在未生成区块中混用 v22／v23。未知 v24 及更高版本继续拒绝。
- 本批不重排稳定的 block／item／actor／biome／structure 身份，不新增持久文件。目的地箱子使用
  现有方块实体和区块保存路径；拆除、取走或修改后由已保存区块保持结果，不在重开时重复生成。

## v22 生产入口基线

修改生成规则前的基线身份为提交 `33569b0`、world save v12、terrain v22。基线必须通过生产类
而非复制算法取证：显式构造
`ClassicOverWorldGenerator(seed, LandmarkWorkshopTerrainGenerationVersion)` 和
`CaveGenerator(seed, LandmarkWorkshopTerrainGenerationVersion)`，把前者的公开地表高度和生态查询
传给 `getNaturalEntranceForCell`。

查询从 cell `(0, 0)` 开始，按 Chebyshev 环半径 `0..24`；每环以 `cellX` 为外循环、`cellZ`
为内循环并都按升序，只检查 `max(abs(cellX), abs(cellZ)) == radius` 的格。每格内部沿用生产实现的
候选 `0..11` 顺序，取第一个有效入口。冻结结果如下：

| seed | cell | candidate | anchor `(x,y,z)` | direction `(x,z)` | endY |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 42 | `(11, 2)` | 9 | `(1139, 120, 237)` | `(0, 1)` | 102 |
| 20260807 | `(-5, -5)` | 0 | `(-465, 89, -431)` | `(0, -1)` | 71 |
| 239701883 | `(3, -6)` | 3 | `(364, 95, -507)` | `(1, 0)` | 77 |

聚焦测试必须重新调用上述生产 API 核对全部字段，并记录原 v22 通道及终室涉及区块的逐块哈希；
不能把表中数字作为替代生成器的测试桩。表中的 `candidate` 是对生产选择循环命中位置的审计记录；
现有 `NaturalEntrance` 公共值不暴露该索引，因此兼容断言以 cell、anchor、direction、endY 和实际
区块哈希为准，不为测试扩大运行时 API。v23 后显式 v22 的入口字段和逐块哈希必须不变。

这组环扫描入口只冻结兼容见证，并非普通出生路线证据。当前尚未完成三个 seed 的真实出生点、
地面步行路线和往返输入，均保持 `NOT_RUN`。后续普通路线必须从生产世界真实出生开始记录；若另取
距离出生更近的入口，只能按事先写定的距离与坐标 tie-break 选择，并保留本表作为不可替换的兼容基线。

## 确定性地下规划

- v23 复用现有 `EntranceCellBlocks == 96` 的天然洞口 cell 和入口计划作为稳定 key。
  `CaveGenerator::getAdventureUndergroundPlanForCell` 返回纯值 `AdventureUndergroundPlan`；它包含
  原入口、布局类型、洞室、裂隙、目的地和水池的世界坐标。固定 salt／hash 只从 seed、版本和
  cell 坐标派生，不消费可变随机流。
- 每个 cell 仍只接受现有 12 个候选中的至多一个有效入口，并至多生成一个地下系统。一个系统的
  最大水平 reach 为 64 m。目标区块扩张后最多查询相邻 3×3、共九个入口 cell；额外地表／生态
  纯查询每个候选系统不超过八次。不得读取、锁定、加载或同步生成邻区块。
- 所有负坐标使用现有 `floorDiv`／`floorMod` 语义，中间距离和包围盒计算先扩宽再比较，避免极端
  坐标溢出。每个区块重算同一世界计划，只投影落入本区块的方块；正序、逆序、并行准备和缓存
  驱逐后的结果必须逐块一致。
- 允许没有缓存；若实现派生计划缓存，单实例／线程最多 256 项且有效载荷小于 64 KiB，身份至少
  包含 seed、terrain version 和 cell。缓存不进入存档，不持有 `World`／`Chunk` 指针，切世界或
  身份变化后不能复用。

## 空间、通行与水体

每个有效 v23 系统保留原长 24 m 的天然入口通道，并连接以下空间：

1. 大洞室采用有方向的有界椭球，中心线方向半径 9、横向半径 7、垂直半径 5，外包络最多
   `19×15×11`。洞室有稳定地面、矿脉露头和可放置火把的干燥落脚区，不能全部成为悬空壳体。
2. 裂隙从洞室继续 24 m，宽 3、高 9；轮廓可以有高差和侧向变化，但实际返程侧保持连续干路。
   裂隙不是无底竖井，不能把进入目的地的唯一通路变成不可逆下落。
3. 浅层地下水只放入封闭的约 `7×7` 洼地，深一格；本合同仍以每系统最多 192 格水面占地、
   384 个 Water 方块作为硬上限，为边缘裁剪和后续小幅形状变化留余量。水面至少低于相邻干路
   一格，不能覆盖入口、目的地立足格或唯一返程，也不能与地表河海形成未封闭的半池。

从入口内侧到目的地的可行走路线必须全程非 Water，连续宽度至少三格、头部净空至少三格，
相邻落脚面步差至多一格；普通跳跃可跨越既有的一格台阶，但路线不得要求攀越两格高差或跳过
宽沟。沿同一路线可以在不游泳、不破坏方块、不放置方块和不使用传送的条件下返回入口。
所有新雕刻和投影满足 `y >= 8`，最高点不超过对应地表 `surface - 5`；既有 Water
不被入口或洞室雕刻成 Air。安全条件不成立时拒绝整个 v23 系统并保留原 v22 洞穴输出，不生成
只有入口、没有目的地或无法返回的半套空间。

## 两类地下目的地与资源

每个有效系统由稳定 hash 二选一，只生成一个目的地；三个冻结 seed 的生产计划整体必须覆盖两类，
不能为了通过测试改选 seed 或事后挑入口。

- **矿井缓存**：使用现有木材和石材形成可进入的支架、作业角和真实箱子。每系统至多一个箱子，
  payload 确定为三个非空槽、共 10 件低阶补给：火把 4、木板 4、面包 2；不包含工具、机器、
  矿物成品、任务物品或独立奖励货币。放置的照明使用现有火把和方块光，不新增常驻光源类型。
- **苔石地窖**：以现有苔石、淤泥、砾石和石材形成湿润石室及矿物台，暴露可真实采集的煤矿
  4–8 格、铁矿 2–4 格，并保留干燥立足和返回通道。地下水是可绕行的空间特征，不用水下奖励
  强迫玩家游泳。

目的地最多投影一个方块实体、四个已放置火把；其结构和资源写入计入下述统一预算。矿物由正式
方块和既有开采／掉落语义提供，不以装饰模型或 UI 文案冒充收获。自然敌人与动物仍由现有运行时
规则决定；生成器不预置 Actor，地面和净空必须避免其出生在实体方块内。

探索地图仍是地表资料，不预测或泄露地下体素。玩家实际观察入口地表后，可使用现有个人标记、
方向和距离记录返程点；地下目的地不会仅因生成而自动出现在地图中。本批地图验收证明入口标记、
关闭重开和返家可用，不把局部立体地表图伪装成地下地图。

## 几何、内存与流送预算

以下为硬上限，写入数量按相对 v22 实际改变的唯一世界体素坐标统计，而不是累计重复 set 调用，
测试按生产区块结果取证，不能只检查常量：

| 范围 | 上限 |
| --- | ---: |
| 单地下系统全部候选写入 | 12,000 格 |
| 其中写为 Air | 9,000 格 |
| 其中写为 Water | 384 格 |
| 结构、照明、资源及方块实体所在格 | 1,500 格；方块实体 1 个 |
| 单目标区块的 v23 新增写入 | 16,384 格（`16×16×64`） |
| 单系统水平影响半径 | 64 m |
| 单目标区块查询的入口 cell | 9 个 |
| 可选计划缓存 | 256 项且有效载荷小于 64 KiB |

地下块继续进入现有 Chunk／section 网格；不得增加专用 renderable、材质 pass、draw call、常驻世界
对象或无限期流送 demand。检查每个系统包围盒内的实际新增可见 solid／water faces、顶点／索引、
section 数和 buffer bytes。12,000 个唯一改动体素给出每系统最多 72,000 个未合并方块面候选的
理论上限；实际暴露面和 greedy mesh 应低于该值。任何几何无法由这个上限和现有网格生命周期
约束时视为实现缺陷。

现有流送硬边界保持：pending jobs 总数最多 128、单 loader pass 权威提交最多 8、每帧 section
上传最多 8、每次 update 卸载最多 8、一个 loader worker 和既有 6 ms／64-target pass 上限。
地下规划不请求范围外区块，不因同一跨区块系统建立第二份任务或保持已离开的区块常驻。

## 工程验证

新增唯一聚焦入口 `HELLOMINE3D_WORLD_SMOKE_FOCUS=ADVENTURE_UNDERGROUND`，Debug／Release
至少证明：

1. v23 只在 v22 后追加，save v12 不变，新建默认 v23；显式 v22 及未知 v24 的处理正确。
2. 表中三个 v22 入口的全部字段、涉及区块哈希与当前生产 API 一致；v1–v22 冻结摘要不漂移。
3. 三个 seed 的 v23 计划确定、重复一致，整体覆盖大洞室、裂隙、水池和两种目的地；正、负世界
   坐标及跨区块系统都有实际生产样本。
4. 生产区块中的空间尺寸、写入数量、水体上限和资源数量符合合同；箱子是真实方块实体，payload
   在保存重开后保持，领取或拆除后不重生。
5. 对实际方块运行三维通行检查：入口到目的地及返程均满足三格宽／三格净空、一步高差和全干路；
   水池封闭、可绕行，没有 Water/Air 区块接缝或河海泄漏。
6. 系统涉及的全部区块按正序、逆序和独立生成取得相同哈希；邻区块未被隐式加载，改块保存重开
   保持，卸载／重载不重复方块实体。
7. 入口地表经过真实观察后可建立、保存、重开和追踪个人标记；未知地下内容不提前进入地图。
8. 快速进出系统涉及区块时，pending／commit／upload／unload 均不超过既有硬预算，离开后可正常
   卸载且无额外常驻缓存。

聚焦通过后复核 `P11-2`、`ADVENTURE_WATER`、`ADVENTURE_ECOLOGY`、`ADVENTURE_EXPLORE`、
`ADVENTURE_LANDMARK`、`ADVENTURE_APPROACH`、`ADVENTURE_WORKSHOP`、`EXPLORATION_MAP` 和
`LIGHT_BOUNDARY` 的受影响路径；执行 Release 完整 WorldRuntime、Debug／Release 客户端编译及
必要资源／存档回归。无窗口检查只证明工程关系，不代替普通输入、画面或性能。

## 性能与实际体验

- 使用三个固定 seed、同一入口影响区块集合，对显式 v22 控制与 v23 候选做 Debug／Release 各三次
  配对生成；记录逐区块生成绝对耗时、总耗时、P95／P99、写块数、可见面、section 和峰值内存。
  三次结果全部保留，按三次中位数比较，生成 P95／P99 比值保持不超过 1.10。
- 当前生产客户端在相同机器、分辨率、FOV、画质、渲染距离、入口路线和采样时长下，分别执行
  地下常驻与入口快速往返流送三对；不带截图编码，前后台分开。帧时间 P95／P99 中位数比保持
  不超过 v22 控制的 1.10，同时记录 request-to-visible、队列峰值、mesh 耗时、CPU／GPU 内存和
  resident terrain buffer bytes。不能删除慢样本、换简单入口或放宽阈值换取通过。
- 普通输入对三个 seed 分别记录入口可见性、接近、进入、目的地收获、入口地图标记和原路返回；
  至少覆盖昼间与携带火把的地下照明。传送、强制坐标、库存注入、存档编辑和诊断相机只可用于
  工程／画面对照，不计为普通路线。当前这些路线、画面、动态流送和人类审美均为 `NOT_RUN`。

只有上述工程、兼容、性能和三个 seed 的普通进出／返程证据齐全，B7 才能标为完成。首个规划器、
单个漂亮洞室、精选截图或旧 P11-2 洞口通过都不构成 B7 完成。
