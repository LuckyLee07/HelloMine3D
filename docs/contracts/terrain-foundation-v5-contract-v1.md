## T0 固定测量协议

- 种子固定为 `0, 1, 42, 424, 20260807, 20260809, 8675309, 325322`，在候选实现前确定。
- 宏观网格：每 seed、每显式版本，世界 X/Z `[-2048,2048]`，步长 32。记录实际生成器返回的
  高度、生态以及 +X/+Z 相邻一格高度差；按四象限汇总，坐标轴另算。
- 局部网格：每 seed，X/Z `[-64,64]` 逐格采样，记录截顶四连通面积与高度剖面。
- 边界剖面：X 或 Z 固定在 `-161,-160,-159,-17,-16,-15,-1,0,1,15,16,17`，另一轴
  `[-512,512]` 逐格采样。区块边界比较真实相邻列，不以“高度完全相同”作为接缝门槛。
- 兼容快照：显式 v1–v4 的宏观/局部/边界采样，另对固定四象限区块 `(2,2),(-3,2),
  (2,-3),(-3,-3)` 的实际生成方块与 metadata 计算稳定 hash；版本/seed/区块身份全部写入。
- 保留原始 CSV、工具版本/构建命令、二进制 hash 和派生 JSON；统计来自生产生成器，不以
  Python 复刻噪声替代。分析脚本可负责聚合和画图。
- 性能分开记录：headless 采样/生成成本与真实客户端 frame/load/mesh/upload 成本不混用。
  画面对照固定 seed、XZ/朝向、时间/档位/视距/窗口，若地面变化导致相机高度调整须记录。
  开发者固定位置采集与正常主菜单/正常输入步行分开归档，不互相替代。

## 实现不变量

1. 新高度/生态路径不调用带负坐标退化和 signed hash 算术的旧基础采样；使用明确 floor、
   uint64 运算、固定 salt 和有界坐标。保留旧路径，不能仅删除 early return。
2. 地貌字段连续组合，生态身份不直接制造高度台阶；地形仍是高度图，采样接口代表装饰与
   洞穴之前的规划地表。实际站立/碰撞以生成后的方块为准。
3. 既有洞穴、矿物数量、植物和树形、地点/奖励身份保持其职责；仅为正确消费新版地貌做必要
   适配。世界坐标候选与本区块投影保持确定性，不同步加载邻区块。
4. 保持生成高度安全上限；是否使用软压缩/坡面覆盖须由 T0 证据决定并在 T1 实现前记录。
5. 已保存区块、玩家修改与 block entity 不重跑生成覆盖。新增版本校验覆盖默认新建、显式
   旧建档、读取和未知版本负例，不用修改旧测试期望来掩盖旧版漂移。

## T0 发现与 T1 冻结门槛

基线：8 seed 的 v4 宏观样本 133128 个，高度 9..176，高度 63 占 36.9314%，截顶占
0.3125%，相邻一格最大坡差 5；加密边界剖面最大坡差 15。各负域象限高度 63 占比约
28%..70%，正域约 1%。原始/派生身份见[基线摘要](../reports/terrain-t0-t1-evidence/baseline-v4-summary.json)。

以下为本批产品目标，先于新版实现冻结，不是对所有随机种子的数学证明：

| 项目 | 必需门槛 |
| --- | --- |
| 旧版兼容 | 同平台同采样协议，v1–v4 的 32 个 surface SHA256 与 128 个区块 hash 全部相同；保留旧 fixtures 的语义。 |
| 坐标域 | 每 seed 的每象限高度标准差 ≥ 8、不同高度数 ≥ 32、高度 63 占比 ≤ 10%；基础生态不能固定为单一 Desert。 |
| 地貌跨度 | 汇总高度最低 ≤ 56、最高 ≥ 140，所有采样严格在 1..176；四象限均出现低地与高地，不要求镜像。 |
| 连续性/通路 | 所有加密边界和局部样本的一格最大坡差 ≤ 3；宏观样本坡差 P99 ≤ 2，单格坡差 ≤ 1 的比例 ≥ 95%。该指标不是玩家路径验收替代。 |
| 生态 | 汇总 6 种既有生态每种占比 ≥ 1%；每 seed 的每象限至少 4 种生态，任何单生态占比 < 90%。 |
| 高度上限 | 截顶比例 ≤ 0.1%，且不增加宏观最大截顶连片。采用有界幅度组合保留保护 clamp；先不增加坡面方块种类或修改山地裸岩规则。 |
| 资源/结构 | 8 seed 均存在可用木材/高草/煤/铁及有效路标/遗迹/营地候选；实际出生与选定路线检查支撑、干燥、步行及回程。保持矿物次数/高度和奖励版本。 |
| 保存/顺序 | 新版正逆加载、独立并发生成逐块一致；新旧世界保存重开身份不变，已修改区块不重生；拒绝 v0/v6。 |
| headless 成本 | 相同 32 区块采样方法的总生成耗时，以独占 CPU 的 3 次运行中位数比较，不超过 v4 的 1.5 倍；CSV 采样+I/O 单独记录。 |
| 客户端成本 | 固定配置/seed/相机起点，steady 与 fast-streaming 各暖机 5 秒、采集 30 秒，3 次中位数；frame P95/P99 ≤ v4×1.20+2ms，update P95 ≤ v4×1.25+0.5ms；记录 mesh 耗时/重建数与 GPU 常驻字节、就绪 backlog。现有硬预算不变，不新增性能例外。 |
| 真实窗口 | 固定 forest/negative/mountain 三场景 5s/10s 原图；正常主菜单新建、步行、保存重开单列。缺项保留，不用开发诊断关闭 AI_INTERACTIVE。 |

固定诊断场景由 `tools/capture_terrain_macos.py` 定义，均 seed 20260807、world time 6000、
rotation `0 0 0`，XZ 为 `(256,256)`、`(-256,-256)`、`(1024,1024)`，原起始 Y 为
90/70/140。新版若地表高于初始 Y，允许仅将 Y 调整为真实地表上方，记录差异；不能移走
不理想场景以换取更好截图。重力运行后保存的实际位置用于解释最终机位。

坡面岩土覆盖本批暂不改变：基线首先证明了坐标域/坡差问题，未证明更改真实方块经济必要。
山麓/谷地层次通过高度场改善；材质系统保持不变。

基线采集时确认当前 frames.csv 没有独立 upload 耗时字段，因此在 T1 实现前将此前拟写的
“CPU mesh/上传 P95”替换为真实可测的 update P95，并辅以 mesh/常驻 buffer/backlog 数据。
update 包含上传等主线程工作，不称为纯上传耗时；不为本批虚构缺失指标或扩建渲染诊断系统。
