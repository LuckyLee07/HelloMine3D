# 冒险玩家全身表现合同 v1

状态：`B8a 工程基础`
适用范围：`src/HelloMine3D/Presentation/PlayerAvatarPresentation.h`

## 1. 目的与边界

本合同冻结 B8 首批全身玩家模型与动作的纯表现语义，使后续 Ogre 全身模型、第三人称相机和第一人称裁切可以消费同一组有界值。此批只定义协调的体素角色轮廓、动作目标和帧率无关平滑，不把渲染基础建设误记为可玩的第三人称已经完成。

表现输入是按值复制的玩家位置、旋转、速度、贴地状态、动作反馈、移动时间和移动强度。表现代码：

- 不持有或回调 `Player`、`World`、`Actor`、输入设备、相机或 Ogre 场景对象；
- 不写位置、速度、碰撞体、生命、攻击、工具命中、库存、任务或 fixed tick；
- 不新增存档字段、方块／物品 ID、网络语义或世界版本；
- 只把已发生的权威事实派生为可丢弃、可重建的模型姿态。

因此本批对旧存档、玩家碰撞、移动速度、跳跃、战斗伤害、工具时序和第一人称数值语义均为零变更。

## 2. 模型规格

默认 `Profile` 固定为八个长方体部件：头、躯干、左／右臂、左／右腿、发帽和腰带。六个身体部件各出现一次；发帽跟随头部，腰带跟随躯干，不能形成独立漂浮关节。

- 根坐标位于双脚中心，`centre`／`pivot` 使用根空间，`size` 是完整边长；
- 默认轮廓最高约 1.95 m，所有单件边长不超过 1 m；
- 上限固定为 8 部件、96 三角形。按每面独立顶点实现时最多 192 顶点；
- `Profile`、`Snapshot`、`Pose` 与 `PoseHistory` 均为固定数组或标量，不含堆对象和外部引用；`Profile` 与 `Pose` 各不超过 512 字节；
- Ogre 接入可以复用纹理图集中的皮肤、上衣、裤装、头发和点缀槽，不得为每个玩家实例创建独立纹理。

如果后续需要披风、背包或护甲，必须仍满足总 Goal 已冻结的玩家最多 12 部件预算，并为新增遮挡、材质与视角裁切另行验收；v1 默认模型不预留空绘制部件。

## 3. 姿态派生

`derivePose` 提供六种主姿态：`Idle`、`Walk`、`Airborne`、`Land`、`Tool`、`Hurt`。主姿态只用于可读性和检查；实际部件变换允许将移动、着地、工具和受伤反馈有界叠加。

- `Walk` 使用调用者提供的累计移动时间作为步态时钟，左右腿反相，手臂与对侧腿同相；它不从渲染帧数累加权威位移；
- `Airborne` 依据 `grounded=false`，只用复制的竖直速度改变剪影，不预测落点；
- `Land`、`Tool`、`Hurt` 分别消费 `[0,1]` 的已发生反馈包络，优先级为受伤、工具、着地、空中、行走、待机；
- 工具姿态只抬起表现层右臂，不提交使用或命中；受伤姿态只产生后仰／侧倾，不修改生命或无敌时间；
- 非有限输入归零，包络与移动强度限制到 `[0,1]`，部件欧拉角、根偏移、根倾斜和缩放均在代码中硬限制；
- 头部俯仰保留真实复制朝向。其余装饰动作受 `Off`／`Reduced`／`Full` 控制，强度分别为 `0`／`0.55`／`1.0`，不能放大到 Full 以上。

主姿态并非动作权威状态机，不能反向驱动攻击、采集、跳跃、落地伤害或声音事件。

## 4. 平滑与生命周期

`PoseHistory` 由一个渲染角色实例拥有，切世界、重建角色或离开第三人称时可直接丢弃。`smoothPose` 使用指数权重 `1-exp(-dt/settle)` 平滑关节与根部装饰偏移，因此相同目标和相同经过时间不依赖 30／60 Hz 帧数。

- 世界位置和朝向始终采用最新快照，不在表现层外推或滞后；
- 普通动作默认 65 ms 收敛，工具／着地／受伤默认 40 ms，允许后续设置适配但限制在 10–250 ms；
- 首帧、负数／非有限帧间隔或超过 250 ms 的断帧直接安全贴合目标，不能将 NaN 写入历史；
- 平滑历史不存盘、不跨世界共享，不进入 simulation tick，也不创建线程、任务、缓存或逐帧堆分配。

## 5. Ogre 与第三人称接入要求

后续 Ogre 适配器应按 `pivot + rotation * (centre - pivot)` 组合部件盒体，并把 `Pose` 当成只读帧快照。接入批次还必须完成：

1. 使用正式像素材质绘制八部件，在第一／第三人称和 FOV 90／120 下检查比例、接缝、面朝向与深度；
2. 将工具挥动／使用包络接到真实动作反馈，使第一人称手臂和全身模型共享时序；
3. 实现可保存设置的第一／第三人称切换、近墙相机 sweep／缩距、角色头部遮挡处理和返回第一人称裁切；
4. 切世界、死亡、暂停、窗口失焦和设置切换时清理场景节点与平滑历史；
5. 检查普通移动、跳跃、着地、工具、受伤和狭窄空间的连续动态画面。

上述接入、设置迁移、相机碰撞、实际材质、图形生命周期和普通玩家验收均不属于 B8a，保持 `NOT_RUN`，不能因本合同和纯值测试通过而记为 B8 完成。

## 6. B8a 验证

`scripts/verify_player_avatar_presentation.sh Debug|Release <new-output-directory>` 使用仓库外部依赖为零的系统 C++17 编译器构建独立 harness。定向检查覆盖：

- 八部件／六个身体角色、正尺寸、有限值和 96 三角形上限；
- 行走时左右腿／臂反相及对侧协调；
- 空中、着地、工具、受伤姿态具有不同有界剪影；
- `Off`／`Reduced`／`Full` 强度单调且不超过 Full；
- NaN／Inf 输入回退与所有输出有限；
- 30／60 Hz 在相同经过时间后的指数平滑结果一致，以及非法帧间隔安全复位。

该独立验证只证明纯表现合同，不替代 Debug／Release 客户端构建、Ogre 画面、真实输入、第三人称近墙、第一人称裁切、连续动态或人类审美验收。
