# 可玩 Alpha 旅程合同 v1

> Architecture Lab 迁移说明（2026-08-31）：本文冻结 Alpha 当时的验收计划与工程证据；旧的
> 真人/延期表述不再是当前待办，现行模型见 `docs/current/ai-assisted-gameplay-acceptance-v1.md`。

本文冻结 G6 的第一条正常玩家旅程。它的目的不是替代后续 N1 通用目标系统，而是为世界
入口、采集、制作、工具成长、战斗、拾取和保存恢复建立一个可以持续回归的最小纵向切片。

## 玩家旅程

新世界左上角显示当前步骤、累计进度和一条操作提示。旅程按顺序包含 10 个里程碑：

1. 收集 11 个橡木原木；
2. 在玩家 2×2 制作区制作工作台；
3. 把工作台放入世界；
4. 在工作台制作木镐；
5. 用木镐收集 3 个石头；
6. 制作石镐；
7. 用石镐取得铁矿；
8. 通过正常战斗击败一个自然生成的敌人；
9. 靠近并拾取其物理掉落物；
10. 保存退出并重新打开同一世界。

完成一步后显示 3 秒反馈。数量步骤显示有界进度条；全部完成后仍保留明确的 Alpha 会话
终点。提示只描述现有输入和规则，不直接发放物品、不修改方块，也不替玩家执行动作。

## 状态来源和边界

`AlphaJourney` 订阅现有的库存、制作、方块放置、实体死亡和物品拾取事件，并从玩家库存
补充推导材料与工具里程碑。战斗步骤只接受玩家造成的实体死亡，拾取步骤必须发生在击败
敌人之后。实际采集仍经过 `BlockInteractionSystem`，制作仍经过 `CraftingSession` 的原子
提交，战斗和拾取仍经过 Actor 运行时。

固定回归夹具只负责初始地面、11 个原木、3 个石头、1 个铁矿和自然生物生成落脚面；从
第一次破坏方块开始，不允许测试直接注入库存、完成标志、敌人死亡或掉落物。随机种子新
世界另有冒烟，证明旅程不依赖固定种子才能初始化。

G6 是一次性的纵向切片控制器。N1 已将其抽取为版本化目标定义、前置关系、通用进度和
只读 UI 快照，同时继续兼容这里冻结的十步语义和既有存档；当前合同见
`docs/contracts/objective-system-contract-v1.md`。

## 存档版本 4

`world.meta` 版本 4 在版本 3 的目录身份、时间戳、构建身份、玩家和 Actor 状态之上新增：

```text
alpha_journey_flags 0
```

低 10 位分别对应上述十个里程碑；其他位一律非法。新世界从 0 开始。版本 1-3 仍可读，
读取时旅程标志默认为 0，下一次通过世界管理或正常世界保存后升级到版本 4。版本 1-3 不得
提前携带该字段，版本 4 必须且只能携带一次。候选文件仍经过真实 `WorldSave` 解析后才原子
发布；非法位或版本/字段不匹配会拒绝保存或打开，并保留最后一份已发布存档。

当已有存档带着前九步标志重新进入同一世界时，运行时记录“重新打开世界”，完成第十步并
在下一次保存中持久化完整标志。工具耐久、铁矿、战利品、玩家状态和 Actor 状态与旅程标志
一起恢复，旅程本身不拥有这些业务数据。

N1 以后当前保存格式为版本 5。版本 4 仍按本节读取，其低 10 位通过世界管理边界迁移为
稳定目标 ID，同时继续写出同值兼容镜像；版本 5 的目标集合、部分进度、未知 ID 保留和
严格失败语义由 `objective-system-contract-v1.md` 冻结。

## 自动验收

`HelloMine3DWorldRuntimeSmoke` 的 G6 用例从 `WorldManagementService` 创建并打开世界，沿
正常 API 完成十步，核对木镐/石镐耐久、受等级限制的铁矿掉落、自然生物战斗、物理拾取、
资源守恒、保存、重开和非法标志拒绝。版本 3 迁移样本固定在
`tools/fixtures/alpha/world-v3-empty-journey.meta`，证明旧库存格式和空旅程状态一起升级；
随机种子样本证明新世界从第一步开始。

G6 关闭要求 Debug/Release 相关目标均无编译错误，世界目录、事务、备份和 420 项运行时
断言全部通过，隐藏验证客户端与三帧客户端正常退出。真人输入、正式发行包、长稳和最终性能
预算仍按计划后置；它们不改变本合同中的旅程和存档语义。

G6 后的旅程、迁移夹具、性能参考和崩溃诊断开发基线见
`docs/reports/alpha-development-checkpoint-v1.md`。
