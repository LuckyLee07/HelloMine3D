# 工具成长与渐进采集合同 v1

> Architecture Lab 迁移说明（2026-08-31）：本合同冻结历史工程证据；文中 R3、真人和延期
> 描述保留当时语境，当前退出模型见 `docs/current/ai-assisted-gameplay-acceptance-v1.md`。

最后更新：2026-08-17。

本文冻结 G3 的玩家路径、数据格式、失败语义和兼容边界。第一版只建立“手采集原料—
制作木镐—采石—制作石镐—开采铁矿”的最小成长循环，不包含熔炉、铁制工具、修理、
附魔或容器存放工具。

## 玩家路径

1. 玩家仍可徒手破坏方块，但石头、煤矿和铁矿会按照方块定义拒绝错误工具掉落。
2. 工作台 3×3 可用 5 个橡木原木制作木镐；木镐能取得石头和煤矿掉落。
3. 3 个石头加 2 个橡木原木可制作石镐；石镐达到铁矿要求的等级并取得铁矿掉落。
4. 破坏不再由一次点击立即完成。玩家必须持续按住破坏键；目标、方块或手持工具变化，
   以及松开输入、打开 UI、暂停或关闭世界都会取消当前进度。
5. 每个成功破坏只消耗一次工具耐久。耐久归零时工具消失，并安全切换到下一个非空快捷栏。

## 启动期工具数据

工具定义位于 `media/tools/*.tool`，由 `ToolRegistry` 在有效资源视图冻结后读取并一次性冻结。
资源包 v1 不拥有 `tool` 类别；包内同路径工具文件会作为未版本化覆盖被拒绝。

格式头为：

```text
# HelloMine3D tool registry v1
```

每项必须完整声明 `tool`、`class`、`tier`、`speed`、`durability` 和 `end`。当前约束为：

- 工具材料必须已注册、不可堆叠且标记为工具；每个工具材料恰好有一条定义。
- `class` 当前只接受非空的 `pickaxe`。
- `tier` 为 1 到 10；`speed` 为有限数 1 到 16；`durability` 为 1 到 100000。
- 最多 8 个源、每个源 64 KiB、合计最多 32 种工具；重复、缺项和未知指令使启动失败。
- 当前木镐为 `tier=1 speed=2 durability=16`，石镐为
  `tier=2 speed=4 durability=32`。

## 方块采集属性

方块数据新增四个可选字段：`Hardness`、`MiningClass`、`RequiredToolTier` 和
`WrongToolDrops`。旧方块省略这些字段时采用兼容默认值：硬度 0.25、无工具类别、最低等级
0、错误工具仍掉落。

当前关键方块规则为：

| 方块 | 硬度 | 类别 | 最低等级 | 错误工具掉落 |
| ---- | ---- | ---- | -------- | ------------ |
| 石头 | 1.5 | pickaxe | 1 | 否 |
| 煤矿 | 2.0 | pickaxe | 1 | 否 |
| 铁矿 | 3.0 | pickaxe | 2 | 否 |
| 橡木原木、工作台 | 0.8 | 无 | 0 | 是 |

实际采集时长为 `max(0.05, hardness / matchingToolSpeed)`。工具类别不匹配时速度倍率保持
1；等级只控制掉落资格，不阻止方块最终被破坏，避免玩家因错误工具陷入不可恢复状态。

## 渐进破坏状态

`BlockMiningProgress` 是独立于 Ogre 的一次持续动作状态：目标坐标、目标方块、手持材料、
已累计时间和所需时间共同定义动作身份。任一身份字段变化都会从零开始；每帧最多累计
0.25 秒，避免窗口停顿或调试断点让一次恢复帧直接完成破坏。

Ogre/ImGui 只展示快照：准星下方显示当前百分比，快捷栏对工具显示“剩余/最大耐久”。
世界修改、掉落判断和耐久消费仍由 `BlockInteractionSystem` 与库存模型负责。

## 库存、容器与死亡策略

- 工具最大堆叠数固定为 1；每个 `ItemStack` 独立保存耐久。
- 制作产出的工具使用定义中的最大耐久。
- 只有成功破坏非空气、非水方块才消耗一次当前工具耐久。
- 工具损坏后先清空原槽，再选择下一个非空槽；没有非空槽时保持一个可用空槽。
- 玩家死亡沿用现有 `retain` 策略，工具及其剩余耐久不变。
- 箱子序列化仍为 v1、只保存材料和数量，因此 v1 明确拒绝工具转入，避免耐久被洗成满值。
  后续若要让容器保存工具，必须另行升级容器格式并定义旧数据迁移。

## 世界存档兼容

世界身份格式仍为 v3；库存子格式新增可选字段：

```text
inventory_format 2
inventory_slot <material-id> <amount> <durability>
```

新存档始终写 `inventory_format 2`。工具必须为数量 1，耐久在 1 到该工具最大耐久之间；
普通物品耐久必须为 0。越界值使候选存档校验失败，并保留上一份已发布存档。

没有 `inventory_format` 的既有存档按子格式 1 读取：旧的两列 `inventory_slot` 自动补耐久
0。由于工具材料是在 G3 尾部追加的，旧存档不可能合法包含工具；下一次保存会无损升级到
子格式 2。世界版本不因库存子格式变化而递增。
