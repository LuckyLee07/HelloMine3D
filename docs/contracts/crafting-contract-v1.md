# 制作合同 v1

本文固定 G2 的玩家制作、工作台、库存交换和 UI 焦点边界。配方语法继续使用
`recipe-contract.md` 的 G1 精确材料合同；本批不加入材料组替换、烹饪或自动化制作。

## 制作会话

- `CraftingSession` 是渲染无关的输入网格。玩家制作区固定为 2×2，工作台固定为 3×3。
- 网格是配方蓝图，不从玩家库存暂存实物；关闭、方块销毁、保存或重载时不存在需要退回
  的隐藏物品，因此不能因 UI 生命周期复制或吞掉材料。
- shaped 配方按非空边界归一化位置，且每格表示一个材料单位；shapeless 配方按精确材料
  及数量匹配。2×2 会话不会匹配宽或高超过 2 的配方。
- `CraftingPreview` 只读取网格、冻结配方视图和库存快照，返回产物、最大可制作数量、
  会话版本和库存版本。预览不得修改任何状态。
- V10p 的 UI 每帧重新取得真实预览，当前状态、最大数量和制作按钮始终使用该预览。
  `CraftingResultFeedback` 将最近装入／提交的结果作为独立信息保留 4 秒；成功信息不能
  覆盖刚用尽材料或填满背包后的真实不可制作状态，失败信息也不能替代已恢复的可制作预览。
- 结果计时只在应用处于 Playing 且制作区打开时消费 UI 帧时间；暂停保持剩余时间，同一
  操作再次提交会刷新寿命。关闭、重建会话、切世界或编辑材料／网格清空临时反馈。
  结果信息与当前预览分开显示，操作按钮保持固定；这些状态不写入存档或修改库存交换规则。

## 原子提交

- 提交必须携带刚取得的会话版本、库存版本、配方 id 和正整数制作次数；网格或库存发生
  变化后，旧预览确定失败。
- `Inventory::exchange` 在副本中先消耗所有输入，再检查/放入全部输出，成功后一次交换
  发布；缺材料、产物容量不足或版本不匹配时，原库存保持逐槽不变。
- 最大制作次数同时受材料数量、99 次批量上限以及“消耗后库存”的真实产物容量约束。
  消耗完整堆栈释放的槽位可以接收产物；只消耗部分而没有空槽时不能误判成功。
- 批量制作重复同一条交换规则，不提供绕过版本检查的 shift 快捷路径。

## 玩家和世界边界

- E 键打开玩家 2×2 制作区；使用工作台方块打开 3×3 制作区。打开箱子和制作区互斥。
- 工作台使用尾部追加的 `Material::Workbench` / `BlockId::Workbench`，旧材料和方块数值
  保持不变。基础配方用 2×2 橡木原木制作工作台，工作台才能匹配现有 3×3 箱子配方。
- 制作 UI 只修改虚拟网格并调用 preview/commit；它不能直接增删库存。
- 制作界面捕获键盘和鼠标。打开期间放置、破坏等世界动作被拒绝；Escape/Close 关闭。
  工作台生命周期结束时同步关闭绑定的 3×3 会话。
- 会话和工作台 UI 状态不写入世界存档；已经成功交换进玩家库存的产物沿用现有玩家存档。
