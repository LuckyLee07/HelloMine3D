# AI 开发与验收工作流

这是执行指南；开发承诺在 [TODOLIST](todolist.md)，检查要求在
[验证矩阵](validation-matrix.md)，正式玩法语义在 [验收规范](ai-assisted-gameplay-acceptance-v1.md)。
按任务选择下面的路径，不把所有路径串成每次必跑的流程。

## 实现与验证

1. 检查当前 commit、工作区、用户范围和相关入口。普通修复直接推进；跨批次 Goal 才需要冻结范围、依赖和退出条件。
2. 根据实际失败或需求决定设计，读取相关合同章节。只对新增系统或语义变化建立/更新合同，不为文字修正制造批次。
3. 完成实现，运行受影响检查，再执行合同要求的回归与玩法验收。失败先定位；已有证据只有在版本和覆盖范围仍适用时才能引用。
4. 更新实际改变的状态和说明。验证后按授权提交完整批次；交付实现、提交、证据和仍未满足的退出项。

提交标题和正文沿用既有中文形式，例如 `视觉: 增强物品体积与地图导航`、
`修复: 保持后台窗口不激活`、`文档: 同步验收记录`；已有批次可继续使用 `E6: 中文说明` 等前缀。

本地功能实现可以参考用户授权的本机工程；相关名称、绝对路径和源码索引仅存放在 Git 忽略的 `.local-notes/`，不写入提交文件、文件名或提交说明。仓库文档只记录本项目的需求、设计、实现与验证结论。提交前按本地笔记中的排除名称检查暂存内容及提交说明；获得推送或发布授权后，还须检查待推送提交范围、PR 描述与发布附件，避免历史版本或生成内容夹带参考工程标识。该约定不限制已授权的本地源码研究。

文档编辑检查链接、命令和状态一致性；技能编辑检查发现路径、frontmatter、触发范围和决策是否合理。
这些修改本身不触发游戏全量重编译、压力测试或重新打包。
修改验证程序则运行其真实行为和相关负例，不能只检查语法或返回文字。

按用户约定，验收截图、画面对照图和录像不提交到 Git；报告、必要测试数据、元信息和哈希可以提交。
原始媒体用于当前迭代的画面对照与问题定位，不作为永久归档。批次完成后及时整理冗余截图、测试包和缓存；用户明确要求清理时，可删除历史原始媒体和采样产物，并记录原附件已清理，不能再将旧报告当作仍有原始附件可复核的证据。
清理前保护正在使用的客户端、游戏存档和未提交代码；游戏运行资源与美术源文件不属于测试缓存。需要重新验收时按对应版本重新构建、采集，不因保留历史测试副本而无限累积产物。

## 长任务恢复

每个长期任务维护一份执行记录，放在 `docs/reports/`；当前账本链接到它。
短任务可使用会话记录，不强制生成报告。恢复区保留：

```text
范围/退出条件：原始范围、用户后续调整、排除项
版本：起始 commit、当前代码版本、工作区改动、包/二进制身份
已完成：结果与对应证据路径；历史证据注明原版本
运行中：真实任务/进程/工具 handle、状态、窗口或文件所有者
待办：下一可执行操作、依赖；失败原因与必要解除条件
授权：用户已批准的动作、作用对象；实际审批拒绝单独记录
```

按批次更新恢复区；逐步日志与大图片留在产物目录。不要在 README、账本和多份报告中复制完整时间线。
压缩后先核对工作区和活跃 handle，再从下一步继续。观察超时不代表进程结束，不据此重启或重复派发。
同一阻塞没有新证据时，不重跑相同操作、不制造仅改日期的提交；Goal 状态按宿主实际规则更新。

## 并行与交接

在宿主及用户允许委派时，把能独立推进的调查、实现或审查交给边界清楚的子任务；父任务同时推进其他工作。
简单修改或必须串行的操作不为使用多代理而拆分。需要独立验收时使用独立上下文，不能把实现者自测改称独立结论。
新用户可见任务只在用户请求/批准创建时建立。可能同时修改同一文件的任务使用隔离 checkout 或明确写入归属。
正常窗口一次由一个执行者操作；父任务收集证据时不同时抢焦点。

交接说明写入实际范围和已有用户授权：包路径/哈希、可创建的测试世界、允许的设置/玩法操作、输出位置、停止条件。
普通验收不要只交接“恢复窗口”，随后才临时扩大动作。严格 AI-06 另按规范提供 package-only 环境与高层目标，不传源码和攻略。
交接文字不能改变宿主权限，也不能保证审批通过。遇到实际拒绝，保留原理由；先核对已有授权，只有确实缺失的部分才向用户询问，不换工具绕过。

## macOS 窗口验收

### 集中实机检查，避免逐场景重启

先把本批未证明的问题列清，再选择最小验证集合。领域逻辑、资源、迁移和纯几何检查不启动
游戏窗口；shader 多条件检查复用一次 GPU 验证进程。文档改动不重新打包。

普通迭代以一个工作客户端会话集中检查多个界面或场景，已有同版本证据直接复用。
`--reuse-app` 只复用应用包路径，**不复用正在运行的进程**；连续调用 capture 仍会反复冷启动，
不能据此声称减少了启动次数。完整生态／昼夜／FOV／字号矩阵及三对性能放到阶段整合，
功能修改后的必要专项检查仍须执行；明确依赖重启的持久化、启动和配对性能另行计数。

启动前核对现有进程、窗口所有者、包身份和配置用途。观察超时或工具返回迟缓时，先核对
同一实例，不另启客户端。一次实机工作结束时记录启动次数、已检查范围和待补项；不以减少
启动为由把动态、声音、正常路线或性能记成 PASS。窗口被用户操作时停止竞争输入，保留窗口，
继续独立的代码／无窗口工作；下一次操作须重新核对窗口归属和最新状态。

自动视觉/性能诊断默认不打断用户：`tools/capture_visual_macos.py` 使用隐藏、不激活窗口，
并在启动前要求包具有 `hidden_window_no_activate_v1` 能力；旧包先重建，不能悄悄回退前台。
`--foreground` 是显式前台选项，只在符合用户当前窗口使用约定时使用。后台结果单独记录，
不替代正常输入验收，也不与前台性能混算。本次视觉 Goal 自动诊断仍保持后台；2026-09-19 用户明确允许可视化窗口后，可继续前台 CUA 正常验收。
性能模式关闭截图读回，避免 PNG 编码污染采样；窗口点与 framebuffer 大小由原生创建日志严格核对。
视觉原图单独采集，不能把没有截图的性能执行当成画面验收。
需要核对隐藏启动时，可用 `tools/validate_background_launch_macos.mm` 只读观察目标进程、
前台应用与可见窗口；轮询不能排除采样间隔内的瞬时事件，仍需检查原生窗口激活路径。

优先复用已验证的工具。获准进行正常窗口验收时，游戏包可用 `open /path/to/HelloMine3D.app` 启动；
同一批次的窗口视觉/性能迭代复用项目内同一个已验证的 `.app` 路径和身份，不为每次
截图另建、另启动 `Runtime.app`。`tools/capture_visual_macos.py --reuse-app` 直接使用该包，
各次证据仍写入不同输出目录；此模式会更新包内的诊断 `config.txt`，最后一次运行后
再冻结包和哈希。可执行文件或清单资源变化时，先关闭客户端，再用
`tools/package_macos_release.py --refresh-existing --output <同一个工作包.app>`
原位刷新并重校验；不要为每次迭代另建待启动的应用包。已验收或签名包不可原位刷新。
读取实际窗口后通过公开 Computer Use 输入接口操作。截图工具已可直接保存目标窗口及身份：

```sh
python3 tools/macos_window_evidence.py --app /path/to/HelloMine3D.app \
  --configuration Release --launch --output /tmp/hm3d-evidence/frame-001.png
```

用新输出名保留原图，查看图片确认场景。`--launch` 会复用已识别的运行实例；多个窗口时先选择该包的窗口 ID。
该工具需要 Python 3、Xcode command-line Clang 和桌面截图访问。桌面会话访问失败与游戏运行时失败分别诊断。
不再通过 Finder/TextEdit 转存截图。脚本输出 `CAPTURED` 只证明落盘；正常输入、动态、声音与盲玩仍各按规范验收。

## 阻塞分类

| 情况 | 下一步 |
| --- | --- |
| 产品缺陷 | 保存失败证据，交给实现路径修复，再验受影响场景。 |
| 仍在运行但观察超时 | 查询同一 handle 或其他权威状态；不要创建重复实例。 |
| 工具缺少能力 / 平台不可用 | 记录具体缺少的能力与受影响项，继续不依赖它的检查。 |
| 实际审批拒绝 | 记录动作、对象和原理由，核对用户授权；必要时请求缺少的明确授权。 |
| 当前证据已足够 | 完成当前批次，继续下个已批准任务；不为“更放心”重复全量验证。 |

`Engineering Done`、单项 `PASS` 和整体完成是不同结论。平台替代需有用户授权，且结果只归属实际执行平台。
本指南不改变验收合同或宿主审批策略。指导依据及审计限制见
[Astra 指令审计](../reports/astra-agent-workflow-audit-2026-09-06.md)。
