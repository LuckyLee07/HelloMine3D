# 视觉升级：清晰的野外探索界面与可信的小地图

用户于 2026-09-17 授权：从产品、用户和美术角度实际体验，提出详细方案并直接实施；范围包括 UI、小地图及世界视觉。当前 E4 terrain v10 已有窗口证据，另一个任务正在实施 E5 水系，本轮保留其文件，地形表现升级先作用于材质、光色与空间可读性，不并发改写生成规则。

实施及实机结果见 [执行记录](../reports/visual-upgrade-2026-09-17.md)。本方案的“完成”以该记录的实际证据为准。

## 2. 视觉方向

保留立方体树冠和像素世界，以“野外探索工具”组织界面。界面使用偏蓝黑/炭灰的深色底，暖白正文，低饱和沙金表示当前选择，青绿色表示健康，珊瑚红表示危险。世界承担绿色，界面承担信息识别。

- 常态正文使用明确可读的正常字重；标题约为正文 1.2 倍。辅助文字降低亮度但不使用极细字体。
- HUD 统一安全边距；目标区固定在左上，地图右上，物品与生命在下方中心。
- 使用细描边、局部强调和清楚留白。避免所有内容都套同色大圆角板。
- 物品图标使用现有真实图集，空槽保持空，不伪造玩家尚未拥有的物品。
- 中文、英文及 0.85/1.0/1.25 字号均需容纳；长目标和长物品名称可换行或截断并保留完整提示。

## 3. 本轮实施范围

### V1 字体与基础控件

从仓库现有 OFL 字体生成固定字重的派生字体，保留原字体与许可证，记录生成脚本及确定性哈希。更新运行资源清单和实际字体入口。统一文字、面板、按钮、悬停、选中和禁用色彩。

验收：中文缺字为零，正常正文与禁用文字有明显区别；主菜单、建档、暂停、制作都使用新样式。

### V2 任务、快捷栏、生命与操作提示

任务区：旅程计数作为小型眉题；当前任务是主标题；说明正文对齐；数量与短进度条共享一行。快捷栏：五槽玩法不变，物品图标居中，数字角标，数量和耐久在独立区域；选中槽有明确亮边/底标。生命用可数的分段显示并保留数值；危险色有数值冗余。手持名称与状态反馈不使整个物品栏上下跳动。

操作提示缩成键帽与动作文字。字幕保证阅读时间和原有无障碍信息，避免盖住准星。制作/容器增加图标辨识，不改变配方、槽位和转移语义。

### V3 真实地表小地图

- 读取当前世界已驻留区块的顶层可见材料，表现草、土、沙、石、水、树冠和建筑；跳过花草等细小装饰。
- 以高度邻差作柔和坡面明暗，使同一草原也能读出起伏；取消常态区块网格。
- 保持北向固定、玩家朝向、比例尺与清晰圆形边界。未知区域使用明确暗色，不用纯绿假装已知。
- 分批采样，限定每帧工作量；读取锁忙时延后刷新；不加载新区块、不生成预测世界、不写存档。
- 玩家原地放置/破坏也能刷新；换世界、传送和负坐标不会复用错误缓存。

验收：树冠与空地可区分，水岸及建筑与真实方块相符；负坐标、未加载区块、编辑刷新、切世界与采样上限有定向自动检查。地图快照只属派生表现，不向 World 引入 Ogre 依赖。

### V4 世界材质与空间层次

先改善现有地形的读图质量：草地由荧光黄绿收敛到自然灰绿，地表细节与低频色块建立尺度对比；坡向光照加强地形轮廓，保留阴影关闭回退及昼夜差异。标准/兼容材质和有/无阴影路径需一致。保持立方叶轮廓、植被根部与已修复的水面连续性。

E5 的新水系在其任务中继续；本轮不改变已保存世界的地形身份。后续地貌美术可根据真实水岸、草甸和山麓的整合画面继续调整，不能用新生成规则掩盖 UI 与地图数据缺陷。

## 4. 验证与交付

1. 冻结当前工作包、源码起点和原始截图。正常输入体验与诊断机位明确分开。
2. 字体生成确定性、资源包/本地化、受影响 C++ 双配置编译；地图定向及完整 WorldRuntime，相关 UI/输入/保存测试。
3. 固定 terrain v10、seed 20260807、窗口 1280×720、时间 6000，林地、海岸、草甸和山麓前后对比；字体、HUD、空/满槽、制作/容器检查。夜间和阴影关闭补查可读性。
4. 同条件三轮性能：静态与快速移动，并覆盖主要画质路径；比较 P95/P99 中位数，不超过基线 1.10，失败保留并定位。新地图的 CPU 工作量必须有固定上限。
5. 同一个工作客户端原位刷新，保留用户存档。交付详细报告、方案、可运行版本与本地截图；不把新画面称为用户已认可，不用历史 E4 PASS 覆盖本轮结果。

## 5. 优先顺序与完成标准

先修真实性（地图）和可读性（字体），再改 HUD 与物品呈现，最后调整世界光色并做整体实机迭代。所有四项均属于这次实施，不仅提交一份建议书。

整体退出条件：本轮改动已进入真实运行路径；必要自动验证通过；有同场景前后图和正常界面自测；性能/工具限制与未满足项如实记录。现有 E2 海岸 P99 问题独立保留，不被本轮结论覆盖。

## 6. 玩家与生物表现补充（2026-09-19）

用户明确视觉范围还包括玩家、动物等模型。上述 v10 内容是首轮方案，当前整合版本已是 terrain v12，
后续顺序与退出条件以[综合 Goal](visual-upgrade-goal-prompt-2026-09-17.md)及执行记录为准。
角色升级沿用体素分面和低饱和野外配色，优先解决身体存在感、轮廓辨识与动作连接。

| 顺序 | 产品/用户目标 | 美术与实现方向 | 检查重点 |
| --- | --- | --- | --- |
| 1 玩家手部 | 空手也能感到角色存在，工具有明确握持关系 | 青灰袖子、皮质袖口、暖色手掌与有体积的指节；空手、握图标、托方块三类姿态，手与物共用动作 | 昼夜、三档反馈、连续开采、食物/种子/方块、窄窗口和面板隐藏；本批 r20 已实现，结果见执行记录。 |
| 2 生物关节与步态 | 行走和攻击时身体连接稳定，斜向步态也能变化 | 肩、髋为摆动轴；四足头与口鼻围绕共同颈部运动；步态依据有界实际位移而非坐标之和 | r21 已实现；八方向、停止/恢复、传送和关节点定向检查通过，状态随渲染实例清理。AABB、攻击 tick、伤害与存档不变；不包含姿态混合或脚掌贴地。 |
| 3 生物身份与表面 | 远处可辨类型，近处不只是同色积木 | Stalker 使用布料/系带/护腕，Brute 使用胸甲/宽下颌，Spitter 使用背腹/口鼻分区；守护者 crest 增加符记 | r22 已实现并完成昼夜、12/24 m 诊断图、近远连续帧和 GPU 检查；24 次相关性能及候选交付通过。24 m 夜间细节辨识有限，正常战斗和人类辨识度尚未关闭。 |
| 4 动物方向 | 物种外形与行为一致，能融入生态 | 按物种确定头身比例、耳鼻尾轮廓和四足步态，再接入匹配的真实行为；先检查现有 Actor 与生成边界 | 当前只有敌人原型，独立动物体系尚未实现。新增物种需把生成、行为、生命周期和保存边界一起设计，不能只换敌人颜色。 |

上述两处已在 r21 修正：旧步态使用 `(x + z) * 4.5`，沿 135°/315° 方向移动时相位抵消；
旧四肢绕自身中心旋转，使本应固定的肩髋端点随动作移位。r22 已补面部和表面层次；
侧面连续画面显示 Spitter 抬头时头部虽有固定支点，实际连接面积仍偏小，下一批补颈部几何。
第一人称手臂不代表第三人称全身玩家已完成；动物方向亦不计入当前已交付能力。
