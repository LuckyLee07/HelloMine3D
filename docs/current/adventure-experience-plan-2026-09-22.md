# 冒险世界体验升级规划

日期：2026-09-22。状态：用户已明确启动完整 Goal，当前 B0 基线核对与 B1 首批实施；
实际进度见[唯一执行记录](../reports/adventure-experience-execution-2026-09-22.md)。

用户要求将本轮七个迭代方向落地为文档，并写成可持续执行的 Goal。执行入口为
[完整 Goal 提示词](adventure-experience-goal-prompt-2026-09-22.md)，批准与执行状态以
[当前待办](todolist.md)为准。本文冻结目标、顺序与最低交付范围，不把设计建议写成已实现事实。

## 1. 产品目标与当前基础

让玩家从普通出生点开始，能够辨认地区、理解生存需求、发现动物和目的地、记住探索路线，
再把收获带回自己的基地。天空、地形、角色、声音和界面应共同表达同一个像素沙盒世界。

本轮调查基线为 `edccd20`，运行时最近提交为 `ee42d30`：world save v12、terrain v19。
开始实施时必须重新核对实际版本，以下记录不能替代新版本验证。

| 方向 | 已有基础与证据 | 本轮要解决的差距 |
| --- | --- | --- |
| 天空与区域氛围 | 已有日月、云、雾、昼夜和阴影；[天空调查](../reports/terrain-ecology-baseline-2026-09-21.md)观察到日月绘制存在 | 日月辨识弱、云团层次不足、云与太阳遮挡不明确；天空、远景和地表光色尚需整体协调 |
| 动物生态 | 敌人已有不同原型、关节和步态，并按生态选择；[当前待办](todolist.md)明确独立动物尚未实现 | 地区缺少被动动物、栖息地行为和自然活动场景 |

| 整套界面 | HUD、行囊与合成已有[统一美术方向](game-ui-direction-2026-09-20.md) | 世界列表、机器、暂停／设置、任务与地图详情的组织和反馈仍需整合 |

实际观察与推断分开：最近普通场景中接近敌人并连续受伤，支持开展危险节奏审查，
尚不足以认定所有新世界出生不安全；已有食物教学偏晚，不代表制作食物在机制上被铁剑锁定。
旧的持续输入、独立盲玩、声音与人类审美缺项不因本规划而改为通过。

## 2. 美术与体验原则

- 延续体素轮廓、清楚的像素尺度、克制的纹理和低饱和界面；与玩家已经认可的轻量 HUD 保持一致。
- 远景辨认轮廓，中景理解路线和危险，近景提供材料、生命与交互细节。避免用统一铺满的装饰替代层次。
- 地区差异同时体现在空间、植物、动物、声音和探索收获，不能只增加名称或换色。
- 动态表现优先连续、稳定、可读；避免阴影闪烁、镜头突跳、全屏强闪和长动画阻塞常用操作。
- 可按需使用图像生成制作图标、纹理和像素素材；在真实显示尺寸、明暗场景和正式资源路径内评审。
  概念图不是最终效果证据，静态图片不承载虚假的物品、地图或任务状态。
- 保留探索选择，不通过增加长任务链、不可跳过演出或大量重复奖励强迫玩家走固定路线。

## 4. 各批次实施范围与完成判据

### B0：冻结当前基线和验证设计

复用已完成的地形和 HUD 调查，补看相关真实路径，不重新从零调查所有历史系统。
读取相关架构、合同、验证矩阵；记录起始 HEAD、工作区、客户端路径／二进制与资源身份、
用户正在使用的进程和存档边界。

冻结至少三个普通创建种子，覆盖不同出生区域；另设八类既有生态的视觉路线以及后续洞穴路线。
普通种子应在修改前选定，不因效果不佳而换成更有利的种子。记录失败和特殊出生，修复后重走。
冻结 FOV 90／120、标准窗口与用户当前 framebuffer、时刻、画质、阴影档位和相机条件；
分别建立固定画面对照、连续场景观察、正常输入和性能采样表。

在新增系统实施前落实可测量的 Actor、寻路、声音声部、地图采样／缓存／磁盘、网格和内存上限，
写入对应批次合同。现有帧时间护栏保持；有歧义的预算先实测并冻结，不留到结果出来后调整。

完成判据：执行报告有覆盖 B1–B10 的验收清单、明确包身份、基线和下一实现步骤。

### B1：天空、云、远景、雾和光照

改进像素日月轮廓、视角下的可辨尺寸与亮度；建立云团边界、厚薄、受光、留白、移动和遮挡。
日月不应在不透明云后无条件完整叠加。清晨、正午、黄昏、夜间要有协调的天空／地表光色，
区域雾依据真实地区和距离平滑过渡，保持地形和危险轮廓可读。检查树冠与坡面的阴影稳定性。

验收覆盖八类生态的代表景观，以及林地、海岸、雪山的四个时段；在两种 FOV 下对准天体
辨认日月，允许云遮挡与天体位于视野外。连续行进／转头检查云的跳变、地平线接缝、阴影闪烁，
同时检查功能关闭与低档回退。不能靠全局提亮、雾遮住远景或只改变 FOV 掩盖问题。

完成判据：上述关系在当前生产渲染中成立，动态、档位、shader／资源和性能检查通过；
不把诊断镜头移动写成普通玩家输入。

### B2：前期成长、任务和危险节奏

把工具、食物、照明和安全落脚点组织为早期可理解的目标；保留现有合理的并行分支。
食物教学不再以制作铁剑为前置。将保存重开从必经冒险主线移出，保存功能及其回归仍保留。
受伤、材料不足、首次发现地点等提示读取真实事件和条件，说明实际下一步，避免重复抢占 HUD。
复核普通出生的敌人距离、攻击预警、恢复机会和难度差异，按实际证据调整。

目标 ID、历史完成状态和一次性奖励必须有明确迁移／映射；不能因删除或重排目标提前触发胜利、
重复发奖或抹掉旧进度。剧情主线与胜利仍可达；不顺带引入饥饿或重写全部战斗经济。

完成判据：三个冻结种子的早期路线中，材料与教学条件可达；普通难度逐个检查，轻松难度至少
补一个对照；记录前二十分钟的目标可见性、受伤恢复和自主选择。任务／配方／迁移检查通过，
正常流程与预置状态测试分开记账。

### B3：三类动物及栖息地行为

首批默认采用草地群居动物、林地小型动物、湿地水岸鸟三类，可在调查中选择更适合现有资源的
具体物种，但保留三种不同模型、栖息地和行为组合。它们从普通世界自然出现，不能只存在于展示场。

至少具备游荡、停留、进食／觅食、受惊和逃离的适用状态；水岸鸟可先在岸边步行活动，
无需把飞行体系作为前置。检查坡面脚掌、身体高度、绕障碍、避水和种群间距，避免把敌人换色
当成独立动物。动物与玩家及既有战斗的关系、死亡和掉落由合同明确。

明确持久与自然更新对象的边界，处理区块卸载／重载、切世界、保存重开、暂停和死亡；
不得重复生成或复制掉落，不无界增加实体、寻路或碰撞查询。

完成判据：三类栖息地都有自然遇见的当前证据，模型和动作可辨，普通交互与生命周期检查通过，
密集动物与流送场景的性能受控。

### B4：目的地内容、接近线索与建造收获

营地、遗迹、路标三类地点各至少具备两种有实际空间差异的布局或区域变体；
通过入口、内外空间、高差、遮挡和周边路径形成差异。复用已有机制，逐类明确补给、落脚、
材料、观察或挑战价值，不把所有地点统一成额外宝箱。

在林地、河谷与山地至少各建立一组可读的接近线索，例如林间开窗、岸边路径、山口轮廓，
并检查地点与地形、植被和入口互相避让。优先组合现有区域材料，必要时新增，形成至少三套
可实际采集、制作与建造的搭配；每套要有正式配方／用途及场景中的建筑示例，避免只有展板。

生成变化进入新版本，保留旧 terrain v1–v19 输出及用户建筑。资源与奖励经济有守恒、
重复领取和保存重开的证据，不因增加地点破坏主线可达性。

完成判据：普通探索能够发现并进入地点、获得实际收获、带回并使用；布局、资源及版本兼容检查通过。

### B5：持久探索地图与返回路线

在现有局部立体地图之上保存已探索区域，提供未知区域区分、个人标记的增删改、基地／营地
标记、追踪目的地的方向与距离；加入平面总览与局部立体视图切换，保持玩家定位和已有操作。
任务存在已知位置时关联导航，未知任务位置不得凭生成器提前揭示。

地图只消费玩家实际观察或已探索的数据，不能为绘制地图同步加载或生成远方区块。
记录地表数据的精度、可见范围、更新与失效策略；明确已探索但后来修改的区域何时刷新。
缓存和磁盘数据有上限，远区可降采样；个人标记的容量与满额反馈明确，不能静默丢弃。
存储使用现有事务／备份规则或同等级的有界协议，损坏地图缓存不得损坏世界本体。

完成判据：探索离开后区域仍可查看，重启后记录与标记保留，切世界无串数据；
选点／编辑／跟踪／返回可用，未知信息不泄漏，负坐标、超容量、损坏回退和性能检查通过。

### B6：世界列表、机器、设置、任务与地图界面

世界列表突出世界名称、预览、最近游玩和继续入口；缩减拥挤的表单感，旧世界无预览时有
合适回退，不为生成缩略图自动载入全部世界。实现主菜单可发现的设置入口，整理暂停的继续、
设置和保存出口；调试版本字段不占据普通产品流程的主要位置。

机器界面清楚表达输入、实际运行条件、进度、输出和停止原因，不显示尚不存在的动力能力。
任务以章节／分支、状态和真实材料图标组织，地图控件有明确的分组、选中、图例与选点信息。
统一悬停、按下、不可用、失败原因、数量及返回反馈，复用现有输入所有权和原子制作／转移语义。

验收中英文、0.85／1.0／1.25 字号及 640×480／1280×720；优先修最紧凑组合，再覆盖常用窗口。
包括长名称、空列表、失败状态、长任务、满背包、机器停机、提示重叠和明暗场景。

完成判据：控件可见可达、状态可信、返回与失焦正确，批量矩阵与代表正常操作有当前证据，
图像生成素材已在实际页面中协调使用；高频操作没有人为等待。

### B7：地下空间与探索

保留已有洞穴基础，新增大洞室、裂隙通道和地下水三种可辨空间；组织入口、通道、矿脉露头、
照明层次和可到达的落脚区域，至少两种地下目的地布局与真实资源或探索收获相连。
地面生态与地下地质保持可解释关系，不把所有洞穴改成同一种大空腔。

追加生成版本并保留所有旧路径；检查洞穴与河海相邻、水体边界、区块接缝、负坐标、
生成查询、入口通行、动物／敌人位置和建造碰撞。体素水体表达沿用现有机制，无需完整流体模拟。

完成判据：三个冻结种子的地下补充路线覆盖三种空间，正常入口可接近、可进入、可返回；
资源获得与地图记录可用，兼容、生成成本、内存和流送性能通过。

### B8：玩家模型、工具动作和第三人称

完善第一人称握持、工具挥动和使用动作，使视觉时序对应真实命中／使用；保持手持物的像素比例。
实现一个完整、风格协调的玩家模型，以及静止、行走、跳跃／落地、工具动作和受伤反馈。
第三人称作为可切换视角，处理近墙镜头遮挡、角色可见性和返回第一人称时的手臂／身体裁切。

视觉姿态不改变权威碰撞、攻击距离、冷却或物品消耗；需要新增相机设置时处理默认值与旧设置迁移。
不把换装、装备栏、角色捏脸和新战斗职业作为前置。

完成判据：普通移动、采集／使用、视角切换在平地、坡面、墙边和洞穴内成立，动作与实际行为同步，
无身体挡住第一人称、镜头穿墙或切换输入残留，相关性能和回归通过。

### B9：区域环境声音与材质反馈

在现有音频路径加入森林、开阔地、水岸三类环境层，区分河流与海岸；接入实际动物行为声音，
补充草／土、石、木、沙四组材质脚步。声音依据真实位置、接触地表和事件触发，
不让暂停、空中移动或打开 UI 继续产生错误脚步。

处理空间衰减、区域过渡、重复声部抑制、循环接缝、昼夜密度和危险提示优先级；
保持音量设置、字幕和关闭回退。资源来源可追踪，使用可合法分发的素材或本项目制作的声音。

完成判据：实际听感覆盖地区切换、近水／远水、动物远近、四类地面、暂停／恢复、设置重开；
不存在持续刺耳叠加、突变或虚假方向。加载日志和字幕只证明对应机制，不替代听觉验收；
无法获得实际声音证据时保留该项未验。

### B10：完整回路、可靠性和交付

至少完成一条普通创建世界后的完整回路：理解初期目标 → 采集／制作 → 恢复或照明 →
经过两类以上地区并遇见动物 → 发现目的地并获取收获 → 标记与使用地图 → 返回落脚点并建造使用 →
保存退出并重开核对。另补地下进出、玩家视角切换和环境声音场景。
三个冻结普通种子都要保留出生、早期资源／危险和任务记录，不能只交表现最好的一个。

必要工程回归按实际变更覆盖世界、目标、配方、实体、输入、地图、资源、保存与迁移；
在实际可用的批准平台做 Debug／Release 构建及干净包检查，不外推其他平台通过。
整合性能同时覆盖常驻、流送、密集动物、地图开启、地下和昼夜变化。

完成判据：B1–B9 的最低交付及本节回路有当前版本证据，必要检查通过；分批代码已提交，
普通菜单启动的客户端、交付说明、精简证据和明确限制完整可用。

## 5. 兼容、性能与执行约束

- world save、terrain、settings、objective definition 是不同兼容域。需要新字段时明确版本与迁移，
  保留旧世界、用户建筑、背包、任务与胜利状态；不要承诺所有新增持久能力都能保持原格式号。
- 新生成版本只影响采用它的新世界；旧版本已保存与未生成区块继续原规则。稳定的 block／item／actor
  身份不可重排，旧存档回归覆盖实际受影响版本及损坏／事务失败。
- 复用现有权威状态、固定 tick、事件、快照和资源清单；新增能力进入正式路径，不能只在诊断分支存在。
- 适用性能采用同机、同分辨率、FOV、画质、种子、路径和采样条件，至少三对重复；
  P95／P99 中位数比沿用不超过 1.10 的护栏，并记录绝对帧时间。测量不带截图编码，
  前台与后台分开；同时记录生成／保存耗时、几何量、实体、CPU／GPU 内存与新增缓存。
  每批与其基线、最终版本与 B0 都要比较，避免小批次各涨一点后累积失控。
- 新版本地形与旧版同坐标可能已不是同一种场景。保留同种子／路线总体成本对照，
  另做匹配工作量的渲染与实体对照；不能把场景换成海洋后的低负载当成森林优化。
- 必要检查通过后，仅因新改动、失败或未解决疑点扩测；文档批次检查链接、状态和一致性，
  不触发游戏全量构建。B0 与新增系统合同只冻结必要语义，不制造额外审批关卡。
- 每个可验证小批次结束后中文本地提交，只暂存本批文件；不推送、发布、打标签或改写共享历史。
- 保护用户正在使用的客户端，不操作、刷新或关闭它。自动诊断默认隐藏／不激活；正常窗口验收
  使用身份明确的独立工作包和已有窗口授权，不通过等待用户观察阻塞任务。
- 在工具与系统权限范围内推进；实际拒绝与产品失败分开记录，继续其他可执行工作，
  不更换工具绕过访问控制，也不反复重试同一无新证据的阻塞。
- 复用一个工作包和必要基线；冻结交付包不原位刷新。截图／短片只保留当前必要对照，
  不提交验收媒体或重复测试包；批次后整理产物，保护资源、美术源文件、存档和用户交付包。
- 本地参考资料按[工作流](agent-workflow.md)仅保留在忽略目录，提交文件、文件名、说明和交付资源
  不含约定排除的参考工程标识；检查方法读取本地笔记，未来推送另审整个待推送范围。

## 6. 验收声明与完成边界

执行报告逐项记录：批次与需求、当前源码／包身份、实际步骤、结果、证据、失败和下一步。
至少区分代码／工程检查、预置测试状态、诊断相机、正常输入、实际听感及独立盲玩。
实现者自测不能称独立盲玩，也不替用户宣布乐趣、审美或物理设备手感已获认可。

外部能力受限时允许先交付已完成批次并继续其他工作，但受影响项保持 `NOT_RUN`／`BLOCKED`；
缺少整个最低功能或正常回路的关键证据时，不宣布总 Goal 完成。
全部必做范围与必要工程／性能／兼容检查完成，并交付当前可复核的实际验证后，才可标总目标完成；
用户明确调整范围时应更新此表及 Goal，不能把后续批次静默变成候选。

本轮不包含完整气象／季节模拟、体积云技术竞赛、流体物理、繁殖驯养、复杂食物链、多人联机、
城镇 NPC、角色捏脸、通用机械动力网络或无关架构重构。它们不作为上述交付的隐藏前置条件。
