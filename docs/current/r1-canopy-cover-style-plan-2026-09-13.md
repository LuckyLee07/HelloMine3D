## 目标和可比边界

封面使用 [WarmWildernessMenu.png](../../media/textures/WarmWildernessMenu.png)
这张独立静态图片，不是实时游戏截图。目标是**正常游玩时，树冠呈现与封面相近的
像素叶簇密度、立体明暗和松散边缘**，而不是把封面贴到游戏里或承诺逐像素复制
整张画面。天空、草块、镜头构图会影响整体印象，但本方案只改树叶／树冠表现。

用户给出的两图机位不同：封面为低机位穿林视角，当前试玩图为较高处俯看树林。
实施前先在同一个 v5 世界里固定一个**低机位林中近景**、一个**中远景/俯视**，
记录 seed、位置、朝向、时刻、FOV、画质、实际 Retina 尺寸和包哈希；之后所有
前后图使用同一机位。另保留用户原图作为美术目标，不用不同机位的画面充当
精确 A/B 结果。

| 观察点 | 封面参照的目标 | 当前不合格现象 |
| --- | --- | --- |
| 近处叶面 | 小而成簇的清晰像素叶片，有亮、中、暗三层，不是均匀噪点 | 旧 16 像素叶被放大，大片重复深绿块 |
| 树冠轮廓 | 仍有方块体积，但顶缘、侧缘和下缘有适度缺口与碎叶感 | 两层平整大方冠，边缘像裁齐的板 |
| 光照与空间 | 向阳顶面可见亮叶，侧面有层次，林下深色但能看清叶簇 | 整冠偏黑或只有一个绿调，远树连成平面 |
| 中远景与移动 | 林冠合成稳定的大色块，近叶细节渐退，不闪烁、不成棋盘 | mip 后断裂、变黑、突然消失或出现规则网格 |

这些是实机视觉验收目标。最终“像不像封面、是否好看”由用户在游戏画面中确认；
自动检查只能证明资源、性能和可观察缺陷，不能代替审美签收。

## 现状判断及约束修订

当前 [makeOakTree](../../src/HelloMine3D/World/Generation/Structures/TreeGenerator.cpp)
主要以两层 5×5 叶块和顶部十字组成树冠。标准 64 像素纹理数组虽然有独立 mip，
但 [构建器](../../tools/build_warm_texture_array.py) 对 16 个树叶语义层仍沿用
旧版 16 像素颜色及 Alpha。地形 shader 仅使用通用地形光照，难以从旧叶内容中
得到封面所见的细小叶簇明暗。

现行 [M1 合同](../contracts/warm-wilderness-m1-contract-v2.md)明确冻结旧叶像素，
因为之前的薄交叉卡片和叶壳原型被用户否定；叶壳还有密林 Off P99 1.358 倍、
Medium P95 1.319 倍及常驻网格约 +20.5% 的失败证据。本方案将**新叶材质**列为
R1 视觉修订项；不把旧原型直接恢复，也不把旧性能 PASS 自动套给新包。
本次用户后续指令已授权落实本方案；R1 合同/报告记录修订，候选身份和性能
计划在实施与采样前单独冻结。

## 推荐实施路径

1. **先做材质样板，保留有体积的方叶。**以两张新绘和一张派生变化形成三种
   128×128 像素叶母版，
   以封面中的紧密小叶团和暖阳亮面为方向；标准路径烘焙到 64×64，
   派生现有 16 个树叶语义层，保留各生态的合理色差。叶簇以中尺度明暗块组织，
   避免柔化手绘、过亮荧光绿、逐像素椒盐噪点和整齐重复图案。
   透明缺口集中在边缘和少量簇间，中心维持饱满体积；沿用已有 Alpha 颜色延展、
   独立 mip 与覆盖率保持，检查近景、斜视和远景都不产生黑边或破洞。
   源图、创作说明/提示、许可与哈希按现有美术来源目录留档。

   实施记录：实际取得两张带真实 Alpha 的新源图；第三次生成没有 Alpha，未入库。
   构建器将 A、B 烘焙为 128×128 母版，第三变化由 A 的水平镜像确定性派生，
   仍覆盖现有三种生态叶层变化。该选择避免把白底/假透明源图混入正式资源。

2. **只在材质不足时微调叶面受光。**先用现有地形太阳、环境光、AO 与阴影实测；
   若亮暗仍糊成一片，只对已识别的叶材质调整顶/侧/背光层次，保持夜间与
   阴影 Off 的可读性。Alpha 阴影与可见叶片使用同一裁剪语义。
   不靠全局曝光、饱和度或 Bloom 把整张画面调绿，也不改世界光传播。

3. **若边缘仍太方，才试有界轮廓样板。**在不改变叶块真实位置、碰撞、选取、
   采集、掉落和存档的前提下，仅对外露叶面做少量单元格内缺口/像素化边缘；
   内部相邻叶面继续剔除，不增加交叉卡片、整层叶壳、跨格悬伸或逐帧重建。
   先单树与密林测几何、Alpha 阴影和成本；只要观感不如材质版或护栏失败，
   该样板保留为 FAIL 并退回材质版。是否进入这一步由材质样板的实机图决定。

4. **树形变化单列决策。**现有 v1–v5 的树生成结果与旧世界未探索区块必须稳定。
   若上述表现仍不能让整片树林接近封面的高低/冠幅层次，需另立版本化树形
   生成方案，先证明新世界/旧世界、资源经济和保存重开行为；不得直接修改
   共享 `makeOakTree` 来悄悄改变 v1–v5。此项不混进首次树叶样板。

实施时优先触及美术源文件、`tools/build_warm_texture_array.py`、
`media/textures/WarmWilderness64.hmt` 及必要的地形/阴影 shader、资源与网格
定向测试。兼容 profile 保留旧图集作为可靠回退；标准路径必须真实显示新叶。
不改 T1 地貌、Actor、固定 tick、save v12、方块/物品身份和 32 字节地形顶点格式。

## 样板选择与正式退出条件

- 先用**同一固定机位**出旧版与两种新叶材质的原始 PNG，覆盖近/中/远、正午与
  背光、阴影 Off 与 High；再出短视频观察镜头移动与阴影边缘。样板阶段只跑
  资源/Shader 定向检查与必要窗口检查，不重复完整门禁。用户先看实机画面选定
  一个方向；未选中的素材和失败画面保留，不冒充通过。
- 选定候选后，以新源码和资源重新制作独立 macOS Release 包和逐文件 SHA-256。
  运行数组/图集确定性重建、16 叶层与 mip/Alpha 校验、缺失/坏资源负例、
  实际 GLSL、受影响 Debug/Release 目标、适用完整门禁、标准/兼容与昼夜/回退图。
- 树叶变化会影响林地与密林全部画质档。正式性能计划须在采样前冻结：
  林地/密林 × Off/Medium/High，每组 v1 和新候选各三轮、5 秒暖机、
  30 秒采样，记录固定运行顺序、宿主/显示环境和每次原始 CSV/截图/日志；
  P95/P99 中位数比值均 ≤1.10，密林常驻地形 buffer ≤1.35，
  标准新增纹理预算 ≤16 MiB。最大帧及 >33/50/100 ms 数量单列，失败不重选。
  2026-09-13 的成对 PASS 只归属旧叶包身份：可执行 SHA-256
  `f1a3621830709fb0efb22dda92d9f018f77ddc5f9b8ebf37c67ba68939190c3e`，
  发行清单 SHA-256
  `209f9aeb8f15a63a6cd0ab9d40c99955d1e8c7b8701710388af0409ba98eee76`；
  只换资源、程序哈希不变时也不能继承旧结论。
- 用**新包的正常菜单和真实持续键鼠输入**完成创建/载入、移动转头、采集/换物、
  暂停设置、保存退出/重开；留移动时树叶、林缘和阴影原始视频。
  诊断强制机位与固定机位视频不能代替正常玩法。独立包外操作者与用户审美
  另列结果；若工具无法持续按键，明确记 BLOCKED，不能填 PASS。
- 完成适用验证后，交付带哈希 R1 验收包、实机原图/视频、
  PASS/FAIL/BLOCKED 与剩余风险，供用户判断树冠是否达到封面所指的方向；
  等用户**明确确认 R1 整轮通过**，只暂存本轮文件做一个本地提交。
  验收失败就在 R1 修，未经确认不提交完成版、不进入 R2，也不推送、发布或打标签。
  用户现另行明确授权按已认可的当前树冠版本做一次**本地检查点提交**；
  该提交不等于整轮完成，不改变持续输入与动态画面的 BLOCKED 判定。

## 主要风险

64 像素新叶能明显改善叶面与边缘，但不能单独改变两层 5×5 的树冠主形；
需要用相同机位样板确认是否已足够接近封面。Alpha 缺口过密会让树冠稀薄、
阴影漏光和远景闪烁；过密又会回到整片绿墙。新增表面几何最可能重现旧
叶壳的性能失败，因此是**有条件、可撤回的试验**，不能以效果图先验宣布通过。
