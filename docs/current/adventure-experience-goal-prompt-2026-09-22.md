优先级，持续完成实现、验证、中文小批次本地提交与可运行客户端交付。

通过地图记录路线，再把收获带回基地。天空、区域、角色、声音和界面共同形成协调的像素沙盒体验。
保持玩家已认可的轻量、低饱和 UI 与体素美术；不同地区必须在实际空间、生态行为与探索价值上有差别。

### 一、恢复与冻结基线

检查 HEAD、未提交内容、实际 Goal、运行进程、用户客户端和存档身份，保留已有工作。
读取 `AGENTS.md`、`docs/current/todolist.md`、相关架构／合同、验证矩阵和 agent-workflow，
复用最近地形与 HUD 调查，核对当前实现，不让历史任务的优先级覆盖本 Goal。

规划基线是 `edccd20`，运行时为 `ee42d30`、world save v12、terrain v19；实施以实际新版本为准。
太阳、日月、洞穴、三类地标、食物、敌人步态和 HUD 入口已有基础，不将它们误列为从零开发，
也不把它们已有的工程 PASS 当成新目标已经完成。

建立唯一执行报告 `docs/reports/adventure-experience-execution-2026-09-22.md`，维护 B0–B10
清单和恢复区：范围、版本／包身份、已完成、正在运行的真实 handle、待办、失败原因、授权和下一步。
冻结三个普通种子、八类生态代表场景、普通探索路线与当前性能条件；
为实体、寻路、地图持久化／内存、声音声部和新增几何确定有界预算，再进入实现。

### 二、依次推进全部批次

1. **B0 基线与路线。** 完成上述调查、视觉／玩法／性能基线与逐项验收清单后，立即开始 B1。
2. **B1 天空与区域氛围。** 完成清楚的像素日月、成形云团、云对天体的遮挡、连续移动、
   协调的晨昼昏夜光色、区域远景／雾与阴影稳定性；检查普通视角和功能关闭回退。
3. **B2 前期成长与任务。** 提前食物、照明和落脚点引导，食物教学解除铁剑前置；
   保存重开不再阻塞必经冒险主线。提示依据真实状态，审查早期危险与恢复机会，
   保留任务历史、奖励幂等和胜利可达，明确目标定义迁移。
4. **B3 动物生态。** 草地、林地、湿地各落地一种独立动物，具备不同模型、栖息地和适用的
   游荡／停留／觅食／受惊逃离行为；处理贴地、绕障、避水、自然生成与保存／卸载生命周期。
5. **B4 探索目的地与建造收获。** 营地、遗迹、路标各完成至少两种空间布局或区域变体，
   形成接近线索、可进入空间和不同实际用途；至少三套区域材料搭配可采集、制作、建造使用。
6. **B5 持久探索地图。** 已探索区域和个人标记跨重启保留，提供未知区域区分、基地定位、
   已知任务目的地、方向距离、平面总览／局部立体视图。只消费实际探索数据，采样、存储和缓存有界。
7. **B6 整套界面。** 完成世界列表、主菜单设置入口、暂停／设置、机器、任务与地图详情的
   层级与交互反馈；保持真实数据、现有制作／转移语义，检查双语、三字号和紧凑窗口。
8. **B7 地下探索。** 完成大洞室、裂隙通道、地下水及至少两类地下目的地布局，
   入口、资源、地图与返回路线成立；新生成版本保护旧世界并覆盖水体、接缝与流送边界。
9. **B8 玩家模型与动作。** 完善第一人称握持／使用，增加完整玩家模型、基础移动／工具动作，
   实现可切换第三人称、近墙遮挡处理与第一人称裁切；动作对应实际行为，不改变权威碰撞和战斗数值。
10. **B9 环境声音。** 完成森林、开阔地、水岸环境层并区分河流／海岸，接入真实动物声和
    草土／石／木／沙四类脚步；处理空间衰减、循环过渡、声部限制、暂停、设置和字幕。
11. **B10 整合交付。** 完成普通创建后的采集制作、生存恢复、跨地区探索、遇见动物、
    进入目的地、取得收获、地图标记、返回建造及保存重开回路，另补地下、视角与听感检查，
    交付必要回归、当前性能与独立客户端。

可把每个批次拆成更小的实现／验证／提交单元，但不能自行删去最低结果。
常规设计和局部修复自主决定，按依赖推进；外部阻塞只暂停依赖部分，继续其他可执行工作，
把调整记录到同一执行报告。不要反复请求已提供的常规实施授权或等待用户观看画面。

### 三、工程、存档与美术约束

- 运行时变更读取相关合同；只对新增持久状态或语义变化建立／更新合同与架构，避免无关重构。
- 地形变化追加版本，旧版本已生成与未来生成保持原规则，不能覆盖用户建筑。
  地图、动物、目标和相机设置如需新存储，明确版本、默认值、迁移、事务、备份、损坏回退和容量。
  稳定 ID 不重排，原有背包、任务、奖励、结局和世界可靠性保持。
- 新素材进入正式资源清单，真实尺寸下检查像素尺度和风格；可使用图像生成完成适用的素材，
  不用写实质感、厚重边框或静态背景假装完成实际 UI／模型／地图能力。
- 不添加完整天气／季节、流体、繁殖驯养、复杂食物链、多人联机、捏脸或通用机械网络作为前置。
- 保留用户客户端与存档，默认后台不激活；正常验收使用独立工作包和公开 Computer Use，
  只在系统与工具权限内操作。实际审批拒绝保留动作、对象和理由，继续允许执行的工作，
  不换工具绕过安全控制、不反复重试无新证据的同一失败。
- 复用少量工作包，冻结包不原位刷新；截图和短片用于本批对照，不提交验收媒体，
  及时清理冗余构建／测试副本，保护运行资源、美术源文件、用户数据与交付包。
- 本地参考工程标识与源码索引仅存 Git 忽略的本地笔记。按既有本地排除列表审查暂存内容、
  文件名、提交说明及交付资源，不将参考标识写入仓库或线上内容。

### 四、验证与提交

按实际变更和验证矩阵执行必要聚焦检查、Debug／Release 受影响构建、资源、世界、目标、配方、
实体、地图、输入、存档迁移及生命周期回归。文档编辑只检查链接与状态，不触发全量游戏门禁。
代码批次通过必要验证后立即按既有中文形式本地提交，例如 `视觉: 完善日月与云层遮挡`，
只暂存本批文件；不推送、发布、打标签，不积累大量未提交改动。

每个渲染／系统批次执行适用同机三对性能对照，P95／P99 中位数比保持既有 1.10 护栏，
记录绝对耗时、生成／保存成本、CPU／GPU 内存、实体与新增缓存；最终再与 B0 比较累计开销。
FOV、画质、时刻、分辨率、种子和采样条件冻结，前后台结果分开，不带截图编码采样，
不得删除慢样本、换简单场景或放宽门槛换 PASS。

画面检查覆盖八类生态、关键昼夜、FOV 90／120 与动态过渡；UI 检查中文／英文、
0.85／1.0／1.25 字号、640×480／1280×720；普通流程按三个预冻结种子核查前期体验。
完整至少一条普通探索回路，不能用传送、库存注入、存档编辑或诊断镜头充当正常采集与移动。
声音用实际可听证据验证，字幕／日志不是听感。自测、诊断、正常输入、独立盲玩和人类审美分开记录。

### 五、退出与交付

只有规划中 B1–B9 的最低范围全部实现、B10 普通回路及对应实际检查有当前证据、必要工程／
兼容／性能通过，代码已分批提交，普通菜单启动的干净客户端和交付记录完成，才标总 Goal 完成。
最终记录每批提交、程序／资源身份、版本迁移、验证范围、已知问题和复现入口。

若输入、声音或平台能力限制仍影响必要验收，明确保留 `NOT_RUN`／`BLOCKED`，
先交付已完成阶段并继续其他工作，不能把未验补成 PASS 或将整项静默删除。
宿主 Goal 状态严格按其真实规则更新；阶段交付不等于总目标完成。
不以旧测试数量、诊断展示、精选截图或单个首批完成宣称完整体验升级达标，
不替用户宣布审美或乐趣已获认可。
