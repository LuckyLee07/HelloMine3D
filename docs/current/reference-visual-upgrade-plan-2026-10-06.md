# HelloMine3D 参考画质实现方案

日期：2026-10-06。状态：首版在 `codex/reference-visual-v1` 为 Engineering Done，已交付 HDR、两类形状及可保存样板；普通输入验收因服务不可用为 BLOCKED，详见[执行记录](../reports/reference-visual-prototype-execution-2026-10-06.md)。

建议先在现有 Ogre 1.10 与 GL3Plus 上建立线性 HDR 渲染，再配套精细建筑部件、材质受光和水面倒影，形成一段能正常游玩、编辑和保存的临水街道。样板应同时包含室外、室内和水岸，以判断当前引擎能否支持目标，以及资产能否持续制作。引擎迁移在样板暴露明确瓶颈后评估。

参考图提供的目标是细致的方块建筑、协调的石材与陶瓦、可信的明暗和倒影。项目可以保留 1 m 世界格，在格内增加较小的建筑细节；无需先缩小全世界体素，也无需预设光线追踪。截图不能确定其实际渲染算法。

用户已于 2026-10-06 授权从 master 创建新分支实现首版，范围和状态见[当前任务账本](todolist.md)。完整材质、倒影和建筑套件的后续范围仍按样板结果收敛。 全部批次的持续执行入口见[Goal 提示词](reference-visual-goal-prompt-2026-10-06.md)。

## 样板范围与美术规则

样板先限制在约 48×48 m：一栋约 12×12 m 的两层临水小屋、一段 6 m 宽街道、石岸和一间可进入的工坊。保留现有自然树，加入少量花槽、栏杆和灯具。街道留出可拆、可填的区域，便于检验建筑、光照和倒影随编辑更新。

第一套建筑部件控制在 10–12 类：石砖整块、半砖、台阶、檐口、瓦台阶、瓦檐口、木梁、栏杆、窗框、窗台或花槽、灯具。拱门通过多格阶梯组合。先做浅石、粗石、陶瓦、木材四种关键材质，再补道路、金属、叶和花。

采用三层细节：建筑体量和屋顶决定远景轮廓；窗框、檐口、台阶和栏杆用真实几何；砖缝、木纹和细凹凸交给材质。颜色先统一明度和冷暖关系，减少每块独立随机变化。贴图尺寸根据正常行走距离确定，首轮沿用 64 像素数组，不全面提高分辨率。

保留四种可运行组合：现有资产与现有渲染、新资产与现有渲染、现有资产与新渲染、新资产与新渲染。固定镜头、世界时间和显示尺寸，分别看资产与渲染带来的收益。最终判断还包括连续行走和近距离交互。

## 批次一 线性 HDR 基础

新增独立渲染模式，建议配置字段为 `renderpipeline legacy|linear-hdr`，设置格式由当前 v11 升为 v12。旧设置迁移为 legacy；原 `postprocessingquality off|on` 不重新解释为 HDR 开关。首期渲染模式变更在重启后应用，以保持世界创建前的材质选择和冻结顺序。

新流程为：颜色输入解码 → 线性光照与雾 → 线性透明混合 → FP16 场景颜色 → 固定曝光与色调映射 → 显示颜色编码 → HUD 与 ImGui。

legacy 模式的 Off 无 compositor，On 保留原后处理。linear HDR 模式始终需要曝光与输出转换；其中 Off 关闭可选美术后处理，On 首期可在映射后的 LDR 图像上应用既有轻量处理。该中间颜色目标也纳入资源预算。

最小实现包括：

1. 在 `Ogre/` 新增 `HdrPipeline`，管理创建、安装、缩放、回退和销毁；Bootstrap 负责组合，不继续堆积全部细节。
2. 新增 HDR compositor、program 和末端 shader，场景颜色使用 `PF_FLOAT16_RGBA`。首轮只用固定曝光和一种色调映射，自动曝光、景深和运动模糊暂缓。
3. 将地形、植物、角色、天空、水、玻璃、手持物、地下边界背景、开采高亮／裂纹和世界碎屑接入同一输出域。天光、方块光保持各自语义；颜色参数与亮度强度分开处理，避免重复 gamma 和逐 shader clamp 到 1。深度与 Alpha 保持数据语义。
4. 首期可在新 shader 分支显式解码颜色、末端显式编码；关闭 framebuffer sRGB 写入，保留共享 atlas 和 array 的旧硬件标记。此时旧贴图的过滤和 mip 仍有既有颜色域限制；批次三为新材质补齐专用 sRGB 采样与正确 mip。
5. HUD 和 ImGui 仍在主窗口末绘，保护并恢复 `GL_FRAMEBUFFER_SRGB` 等状态。离屏目标不得绘制 UI；切模式和切世界也不得留下旧 compositor。

新资源有独立启动接口校验，旧 LDR 合同保持原样。能力不足或渲染目标创建失败时原子回到 legacy，记录请求、实际模式和原因；非法资产、坏 shader 不伪装成能力不足。浮点创建成功之后还要验证实际像素，避免驱动静默降为 8 位。

本批交付是颜色、混合和亮度范围正确的可切换管线。此时建筑资产仍可使用现有版本，不能仅凭 HDR 开启就宣称达到参考品质。

## 批次二 可编辑建筑部件

本批可与 HDR 基础并行。保留 shape v1，新增单格内复合盒的 shape v2。建议每格最多 8 个轴对齐盒，坐标按 1/8 m 离散，生成几何设置独立上限。加载时消除内部和重叠面，缓存四向旋转；世界存储仍是一格一个方块，不增加 1/8 m 子体素状态。

v2 定义盒边界、逐面语义材质、按实际尺寸缩放的 UV、碰撞与选取属性。新增建筑 ID 追加到现有注册表，不替换 Stone、门等旧 ID。新 ID 的 metadata 低两位定义四向旋转；既有树种、成熟状态和熔炉位保持原义。现有 metadata 字节可保存朝向，但仍须验证合法值、放置提交和保存往返。

必须拆清当前 `Opaque` 同时承担的职责：纹理 Alpha、邻面遮挡、整层封闭、AO 和格级阻光分别定义。部分形状不能隐藏邻块整面或使整层被当作实心。首期可以采用保守的部分面剔除和格级阻光；屋面与墙的阻光规则要保证室内不会因薄形状全面漏光。更细的光传播独立评估。

共享纯几何查询供区块网格、玩家及生物碰撞、ray 选取、轮廓、裂纹和新部件手持／掉落使用。栏杆空隙可以选中后方方块，台阶按真实盒体登上，放置前按最终朝向检查占用。地图继续使用现有表面概览，保证新材质和高度正确即可。

主要改动接入点为 `BlockShape`、`BlockDataHolder`、`ChunkMeshBuilder`、`BlockInteractionSystem`、`BlockSelection`、`Player`、World 通行查询、`BlockSurfaceGeometry` 和 `OgreItemGeometry`。ID 或 metadata 编辑仍递增原 revision，边界相邻网格随之失效；不绕过 World 直接修改 Ogre 节点。

本批完成后，用基础游戏正式注册的资源搭建样板。进入、拆建、拾取、保存、重开和卸载再返回都走正常路径。资源包仍覆盖 manifest 已声明的路径，不新增 mod 注册或热重载系统。

## 批次三 材质与室内外光照

在同一 semantic 到 layer 映射上增加 normal 和 surface 通道；surface 可打包粗糙度、金属度及发光遮罩，具体通道约定写入新 profile 版本。颜色按 sRGB 采样，normal 和 surface 按线性数据采样。新材质用独立颜色纹理绑定完成解码前过滤，不改变 UI 共用图集；颜色 mip 在线性域生成，法线 mip 正确归一化，裁切材质保持覆盖率。

`TerrainMaterialProfile`、资源解析及预检增加完整集合校验，同一材料的通道和各级 mip 必须对应同一身份。旧包缺少新通道时整套选择兼容材质；声明新格式却内容损坏时明确失败。禁止把不同覆盖层的颜色和法线静默拼接。

地形先实现有明确参数的漫射与镜面受光，使石材、陶瓦和木材在同一光源下产生不同响应。复合盒平面可从世界位置和未折返 UV 的导数构建切线基，退化时回到几何法线；优先保留现有 44 字节顶点及 natural-root 属性。普通与阴影接收 variants 同步维护材质、裁切、生态染色、雾和曝光。

太阳阴影先在样板中校准已有稳定投影和滤波，重点验证低太阳角度、连续移动和远原点。如果单张无法同时满足近景细节与远景覆盖，再扩为至多近远两段，稳定各自投影并平滑衔接。级联增加的绘制和采样成本单独记录。

室内先沿用传播方块光的漫射作用和明确的发光材质，再加入至多 8 个邻近真实灯源的表现快照，为方向受光和镜面提供位置。源索引随编辑和卸载更新，不每帧遍历世界，也不向 World 写回渲染结果；同时定义与原方块光的能量分工。至多一盏有明确方向的主灯使用聚光阴影，其余灯暂不投影，避免每盏点灯增加六张阴影图。

这个范围提供可编辑场景的太阳、环境和局部光基础。静态烘焙不作为可拆建筑的唯一光照来源；全局实时 GI 在确有画质收益和预算后再考虑。

## 批次四 水面真实倒影

新增 `Ogre/PlanarWaterReflection`，首期只管理一张反射颜色纹理、一台反射相机和一个选定水位。尺寸取主渲染目标的一半并设置绝对像素上限；按物理 framebuffer 尺寸核算，Retina 倍率不能沿用逻辑窗口尺寸估算。

反射相机使用水面镜像视图及斜裁切，绘制已驻留的世界、植物、角色和天空，不增加区块流送需求。排除水面、第一人称手臂、操作反馈和 UI，阻止递归。相机矩阵、观察位置、雾和阴影绑定按该视图更新，不能临时修改全局阴影开关来凑出倒影。

反射纹理保留线性 HDR，水面按 Fresnel 混合倒影、原水体颜色与深度，波纹扰动采样。当前水深与岸线查询保持；其它水位、水下、能力不足和关闭档使用现有近似。明确裁切边缘与无效投影的回退，避免倒影被拉伸成整屏色块。

可先每帧更新，测量后再决定是否降低频率。若缓存，实际编辑、水位或相机变化必须使缓存失效；不能靠固定截图掩盖一帧以上的明显陈旧。RTT 可能带来额外阴影绘制，必须统计真实提交成本。

## 批次五 植被 抗锯齿与扩展成本

完成前四批后，再改善树木轮廓、植被疏密和建筑边缘。首样板使用已有自然树，先验证新建筑与现有树林能否协调；不直接恢复已经撤回的叶簇原型。后续树冠方案单独比较正常视角、碰撞、阴影、风摆、natural-root 标签及远景 mip。

抗锯齿先比较有界的空间后处理与目标平台实际支持的方案，放在 UI 之前。以连续移动中的栏杆、叶片、屋瓦和倒影检验闪烁与清晰度。TAA 需要运动向量、历史失效和反遮挡处理，不作为第一期捷径。

资产生产保留可编辑源和确定性导出：部件数据生成网格、碰撞与材质预览；颜色、法线及 surface 共用语义映射。完成第二栋不同布局的小屋，记录制作、整合和返工时间，检验首套件能否复用。

## 预算与验收

以下是初始范围上限，实际性能依据样板测量后收敛，不构成已测结论：

| 项目 | 首期上限或规则 |
| --- | --- |
| 建筑形状 | 单格、四向、每形状最多 8 个盒；几何生成另设数量上限 |
| 新材质 | 先验证 4 种关键材质；同一通道统一 layer 和 mip 身份 |
| HDR | 一张 FP16 场景颜色；先固定曝光，不增加自动曝光历史 |
| 阴影 | 先保留单张太阳影，确有覆盖缺口时至多两段；至多一盏聚光投影灯 |
| 局部受光 | 至多 8 个邻近来源，查询与缓存有界 |
| 水面反射 | 一张有像素上限的半尺寸颜色目标；其它水位回退 |

1280×720 的单张 RGBA16F 颜色约为 7.0 MiB，半尺寸约为 1.8 MiB；两者仅计颜色，不包含深度、阴影、其它附件或驱动开销。每新增一份完整 RGBA8、64×64×256、7 mip 数组约为 5.3 MiB。诊断应统计实际目标、纹理和缓冲数量，切世界、切档、缩放与退出后资源回到对应基线。

按[验证矩阵](validation-matrix.md)逐批选择检查：

| 变化 | 工程验证 | 实际客户端验证 |
| --- | --- | --- |
| HDR 管线 | 真实 FP16 framebuffer 与大于 1 的信号；解码、混合、编码和灰阶；全部场景类别生产 GPU 绘制，含地下边界与世界碎屑；shader 错误及创建失败；设置迁移与清理 | 室外亮部、室内暗部、地下背景、碎屑、玻璃、水、手持、HUD；支持与回退；缩放和切世界 |
| 建筑部件 | v1 保持；v2 坏数据、四向几何、碰撞和选取；新 ID 和 metadata 保存往返；MeshDirty 及上传确认 | 正常放置、挖掘、台阶、栏杆空隙、拾取；保存重开和卸载返回 |
| 材质与光 | 通道身份及错误覆盖负例；实际普通／阴影 GPU；array 与 atlas；阴影稳定性和灯源失效 | 近远材质、日夜、室内外转场、增删灯、持续移动；兼容档 |
| 倒影 | 镜像矩阵、裁切、队列排除、绑定、资源数量与回退 | 水位边缘、入水出水、转身、拆墙和填岸后倒影更新；多帧证据 |

涉及 C++ 时运行受影响的定向检查、必要世界回归及 Debug／Release 客户端和资源检查，构建入口按 [README](../../README.md)。shader 和资产变化使用生产 GLSL、独立参考和负例；不能只检查 token 或用测试实现代替生产路径。

同场景比较记录模式、资产身份、实际 framebuffer、图形档、frame P95/P99、渲染提交和内存。当前严格性能验收延期约定保持；新功能仍需有限预算并排除崩溃、明显持续卡顿和无界资源增长。隐藏截图属于画面诊断，普通输入与玩法分开记账。

目标画质通过条件是：正常高度能看清协调的建筑细节；石、瓦、木受光可辨；室内有可读明暗层次；水面反映真实建筑和编辑；连续行走不过度闪烁；UI 清楚；建造、碰撞和保存可靠。固定图、动态画面、工程检查和用户审美分别报告。

## 引擎选择与第一批交付

继续现有 Ogre 的条件是：前四批能形成满意画面，目标机器支持必要格式，运行成本有界，第二套内容能够复用。若样板仍缺少关键效果，或维护多套 shader 与渲染调度的成本明显高于迁移，再用相同场景和资产做引擎比较。

[Ogre Next 官方文档](https://ogrecave.github.io/ogre-next/api/latest/_using_ogre_in_your_app.html)提供现成的 PBS 和 Unlit 实现；接入仍需注册 HLMS、部署其资源并改造项目适配。它是可评估的迁移方向，不是给当前工程换一个库版本就自动得到参考画面。其它引擎也应比较动态编辑、持久化边界、平台支持、资产制作与实际运行成本。

第一批具体交付：固定室外／室内／水岸对照场景；独立 linear HDR 模式及真实支持／回退证据；一种台阶和一种窗框的 shape v2 技术样件，证明四向、碰撞、选中、手持和保存一致。随后扩展建筑套件与四种关键材质，整合阴影和倒影。工期在这些基础样件完成并记录实际投入后估算。
