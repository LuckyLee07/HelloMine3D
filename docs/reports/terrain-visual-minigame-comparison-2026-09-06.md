## 3. 逐项对照与修订

### 3.1 基础地貌：新增最高优先级的坐标域问题

**代码事实（H1、H2、H8）：** `NoiseGenerator::getHeight` 在转换后的 X 或 Z 小于 0 时直接
返回 `WATER_LEVEL - 1`，即 63。基础高度按未偏移的世界坐标采样；基础生态另有 `chunk + 10`
偏移，因此其负域退化分界位于世界坐标 -160 附近，不能把高度和生态分界混为一谈。
v4 的山地 value noise 使用 floor 和固定宽度无符号 hash，但 `getTerrainV4HeightAtWorld`
仍调用旧基础高度。负坐标区域不是完全没有山，而是旧基础高度的多样性被削弱，山地叠加掩盖了
部分问题。现有 v3 固定测试还明确要求 `(-128,-128)` 高度为 63。

**修订建议：** 将“全有符号坐标基础生成”放在新版本地形的首批，早于增加生态种类。
新路径使用明确 floor、固定宽度 hash 和有界坐标运算，覆盖四象限与坐标轴附近。
旧代码的 signed hash 溢出/移位也需要在新路径消除；不能仅删除负坐标 early return，因为
`noise` 当前用向零截断模拟 floor，直接开放负域会引入另一组语义问题。
此处不是断言已观察到跨平台失败，而是明确新算法应采用的可移植算术约束。

验收要比较四象限高度方差、生态占比和轴线附近剖面；不要求象限镜像或统计完全相等。
旧 v1–v4 保留原行为，不能把修复直接写回共享旧函数而改变既有世界未生成区块。

### 3.2 山体与生态高度混合：合理，但不直接换成全三维生成器

**代码事实（H2、M1）：** 当前主地表是旧高度插值加山地 relief，再硬限制到 1..176。
旧高度在半区块网格的四角采样后插值；v4 继续继承该基础。MiniGame 在低分辨率三维采样网格上
计算两组基础噪声的混合密度，用生态高度参数塑形，再插值为体素；生态参数来自周围 5×5
采样点的加权结果，不是周围 5×5 个区块。其顶部也有密度淡出边界。

**合理部分：** 为平原、丘陵、山麓、山脊与谷地建立连续参数场，控制区域尺度、起伏幅度、
坡度和低通路。用世界空间邻域混合参数，减少生态交界处的突变。山地最大高度保护继续存在。

**需要修改：** “硬截顶会形成大量平顶”尚无统计证据，改为采样风险；先测最大高度命中率、
同高连片面积和剖面，再决定是否使用软压缩。高度图也可以做峭壁和谷地，不必为它们上三维场。
三维场主要用于悬挑、拱洞等多表面形状，放到后续局部实验。

三维实验前必须明确 `getSurfaceHeightAtWorld` 是最高实体面、可站立面还是规划参考面，
并核对出生、结构规划、植被、洞口以及光照的调用语义。额外洞面会增加 mesh、AO、阴影与流送
成本；噪声采样只是成本的一部分。MiniGame 的噪声层数不作为 HelloMine3D 的默认参数。

### 3.3 河流与湖泊：方向合理，上一轮建议需要拆小

**代码事实（H2、M2、M4）：** HelloMine3D 基础水体由地表到统一海平面 64 填充，岸滩主要
按 64..67 的高度带选择。MiniGame 的 River 图层根据邻域 ID 差异产生河流标签，再与生态图
合成；它不是按降雨、流量和高程求解的水文系统，不能从类名推导出“河流都顺坡入海”。
MiniGame 湖盆由多个椭球组合，并在写入前检查边界固体和液体，这种防漏思路值得保留。

**修订实施顺序：**

1. 先做与实际水体邻接的岸线材料、低地浅滩和有界封闭湖盆；湖盆必须有完整边界检查。
2. 再做世界空间连续的低地河道计划：中心线、宽度、河床、液面、岸线由同一计划派生，
   明确区域接缝、河口和洞穴相交规则。首版可限定为接入同一海平面的低地河道。
3. 高海拔湖泊、分段下降河流和瀑布后置。需要另行定义液面、连接段和破坏后的水行为，
   不承诺真实水文或动态流体。

不能只在最终高度上画一条低噪声带再统一灌水，否则可能出现无水峡谷、横切山体或贯穿洞穴。
静态水系仍要处理玩家挖开湖堤后的行为，并检查出生、营地、遗迹、树根和矿物受淹。
在水体生成后安排植物和结构适地判断；现有单一海拔条件不足以代表“在陆地上”。

### 3.4 生态和植被：保留，但纠正已有能力与接入成本

**代码事实（H2、H4、M3、M6）：** 当前基础生态由单一噪声阈值划分，Mountain 额外覆盖；
树木按世界坐标 hash 与生态频率选择，跨区块局部投影。橡树已有 4..7 格树高变化，棕榈也有
高度和冠幅变化，因此改善应是扩大轮廓组合与分布层次，而不是“首次增加随机树高”。
Mountain 的树木全部跳过，但低于裸岩阈值的山地仍可能生成草和花；上一轮若理解为“山地
完全没有植物”则不准确。高处裸岩限制与山地树木禁用属于既有 v4 语义，见 H9。

MiniGame 有温湿度、高度、覆盖层和装饰参数，但其 `getGrassColor` 实际返回配置的
`GrassColor`，`getLeafColor` 复用草色；温湿度颜色查表调用被注释。不能把字段存在视为
已经实现连续气候染色。`EcosysUnitForest` 是树形与放置实现，本次没有证明其具有所建议的
森林聚落密度场。

**修订方案：** 首版仅给已有生态增加林地密度场、林缘/空地、坡度与近水适地条件；保留
当前可采集树木和植物的功能身份。山麓稀林作为新 terrain 版本的可选规则，不能覆盖整个
Mountain 而遮住远景轮廓。独立温度/湿度字段可随后加入，不要求一次建完整气候系统。

树形扩展要同步 `MaximumStructureRadius=6` 的影响范围，不能扩大树冠却漏生成邻区块树叶。
采用有界世界空间候选、稳定优先级和最小间距，检查树干支撑、冠层占用及结构/洞口预留空间；
不要用已加载邻区块状态决定是否放树。H4 的 builder 直接投影写块，M6 的地基/空间检查值得
借鉴，但应检查确定性计划或原始地形，避免引入加载顺序依赖。

芦苇、雪、专门灌木等不是“调整概率”即可得到的现成内容。当前
[BlockId](../../src/HelloMine3D/World/Block/BlockId.h) 没有芦苇和雪方块；新增类型需要资源、
碰撞、掉落、方块注册与存档兼容处理，后置为独立内容项。首批可以复用已有草、花、树叶。

### 3.5 洞穴：保留自然化，优先保证可达与回程

**代码事实（H3、M5）：** HelloMine3D 已有三维 value noise 洞穴雕刻，不是整个生成系统
只有二维噪声。v4 普通洞穴最高雕刻到 `min(surface-5,88)`；天然入口在 Mountain 中选择
四个轴向，生成长 24、宽 3、高 3 的阶梯状下降通道，下降 18 格。
终室是水平半径 3、竖直固定范围的房间，并非完整球形洞室。

入口到终室的雕刻不搜索已有洞网，因此不保证接入大洞穴。尤其高入口的终室可能仍高于普通
洞穴雕刻上限。没有据此宣称所有洞口都死路，也未测量实际比例。MiniGame 的路径洞穴有转弯、
半径变化和递归分叉，但算法本身不保证玩家能行走、回程或遇到合适奖励。

**修订方案：** 先用有界计划保证入口、通道、目标洞室之间的玩家尺寸连通与回程，再让洞口
随坡面朝向变化，增加宽窄和转弯。目标可为明确设计的小洞室，不强求每个入口都连大型洞网。
需要更长路线时，再以有界分支连接普通洞穴；设置分支数、长度和影响半径上限。

洞穴计划应与水系、地表厚度和结构保护区共同判断。可见矿脉和奖励会改变资源获取，必须对照
当前煤铁高度/次数与探索奖励身份评估，不能在视觉批次中顺手提高产量。

### 3.6 坡面材质和生态过渡：拆开方块变化与纯视觉变化

**代码事实（H2、H6）：** 山地裸岩主要按高度 100 判断；地表下两层在非裸岩时直接写 Dirt。
现有外观已覆盖草顶/侧、树叶、水及高草等对象，有 3 种变体和 4 格 patch，Mountain 外观
复用 TemperateForest 行。greedy 合并受外观 key 和光照条件约束。

**修订方案：** 使用平滑后的宏观地表坡度与海拔决定岩土分布，不用体素面的轴向法线作为
坡度；先限制斑块尺度和对比度，避免一格一色的噪点。改变 Stone/Dirt 等真实方块会改变挖掘
和掉落，属于生成规则升级。仅换 tile、调色或 shader 则按材质/资源接口验证，通常无需升级
terrain 身份，但会影响旧世界外观，须明确声明。

生态交界优先评估有限过渡变体；连续染色要另选数据载体（顶点属性或 shader 可采样字段），
验证 greedy 合并后的插值、区块边界、资源包和性能。不能简单“每顶点加颜色”却不计顶点
布局、合并率与上传量，也不应直接按所有方块全局染色而污染矿石、建筑和交互标识。

### 3.7 水面表现：已有动态效果；真实深浅色是独立工程项

**代码事实（H7）：** 当前水面已有双波形顶点动画、Fresnel、天空色近似反射、太阳高光和
昼夜颜色。深浅色使用观察距离及法线角度；没有实际水底深度输入。波形生成的 normal.y
通常接近 1，所谓角度项也不能等同于真实水深。当前水下分支用相机高度与当前水面片元比较，
这也不是完整的“相机实际处于水体内部”判定。

MiniGame 的 M7 按相机眼部方块处理水下雾，可参考局部介质判定；本次没有追踪其全部水材质
或证实有真实深度反射，因此不提出“照搬 MiniGame 水 shader”的结论。

**修订方案：** 先改善浅滩地形与岸线，并检查岸上低处视角、高地湖面、水下切换的实际表现。
真实深浅色作为独立渲染候选，可比较：

- 有界水柱/水底派生数据：需要支持玩家挖掘后的失效与更新、未知邻区块回退，不能只缓存出生
  时的高度图；竖直水深也不能冒充沿视线的光程。
- 场景深度采样：需要深度资源、透明绘制顺序、视口变化与低档回退，有更高的接入成本。

选择有证据支持的最低成本方案，保留当前材质回退。瀑布、折射、复杂反射、天气和体积效果
不列入首批；已有波动、雾、AO、阴影和植被动画不重复开发。

### 3.8 探索点、远景和游戏效果

**代码事实（H5）：** 遗迹/营地已经有生态资格、最低海拔及 footprint 高差筛选，不能描述为
完全随机乱放。新增地貌与水系后，应复查这些条件能否识别最终岸边、坡地和洞口，不必先造
新的通用结构框架。

候选收益是让开阔地、河湾、山口和可见地标形成探索路线，同时保留木材、食物、煤铁和路标
主线的可达性。地标的可见性、发现时间和路线绕行需要正常玩家视角验证。

远景表示与增大视距暂不优先：先比较同视距下的轮廓、雾和流送缺口，实际证明当前表示限制
风景后再评估 LOD/远景网格。扩大视距不能替代地貌改善，也会触及 residency、内存、上传、
阴影和切换连续性。该项属于成本未知的后续候选，不是已诊断的性能缺陷。

## 5. 版本、生成阶段与架构边界

1. 下一次改变生成输出的正式身份可追加 terrain v5；不能把 T1 到 T5 每轮不同输出都发布为
   同一个 v5。首次公开冻结 v5 后，后续改变确定性输出须再追加版本或先设计明确的生成配置
   身份。内部未发布实验世界应隔离，不冒充稳定存档。
2. 当前 save v12 已持久化 terrain 版本。仅增加生成版本未必需要改 save 格式，但解析器上限、
   默认值、显式旧版用例、未知版本负例及客户端路径必须一起更新。新增需要持久化的数据时
   再评估格式，不预先承诺 save v12 永远足够。
3. 新字段从 seed、世界坐标、固定 salt 和版本纯派生；不直接修改旧随机流。各装饰阶段使用
   稳定身份，避免调整树木次数连带改变矿物或奖励。跨区块特征由有界计划加本区块投影实现，
   同一特征使用相同所有权和冲突优先级，不同步加载邻区块。
4. 新阶段建议为：基础地貌/水系计划 → 洞穴与水体冲突检查 → 地表与体素生成/雕刻/填水 →
   矿物 → 按保护区与适地规则投影植被/结构。具体先后需在实现合同中固定；结构预留空间应在
   植被决策前已知，不能事后任意清除玩家修改。旧版本保持 H2 的原阶段顺序。
5. 保存区块以玩家实际方块为准；重开不重跑装饰覆盖存量数据。用于外观的派生缓存应随挖掘、
   放置及卸载失效。生成器查询和可变世界查询的语义必须区分。
6. MiniGame M1 的装饰路径有 `cacheChunks(chunkx-8,...,chunkx+8,...)`、全局重光照开关和
   `BlockSand::m_FallInstantly`。借鉴形状和参数组织，不搬入这些世界/全局状态耦合，也不要求
   HelloMine3D 接入其 WorldProxy、配置管理器或整套引擎资源。
