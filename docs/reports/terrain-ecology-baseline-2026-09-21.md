范围：核对 HelloMine3D 当前实现，并使用独立隐藏包进行两组当前天空诊断。本轮未修改生成器、shader 或用户客户端。用户将冒险地图级地形生态设为最高优先级并要求整理 Goal prompt，执行入口见[新目标](../current/adventure-terrain-goal-prompt-2026-09-21.md)。本机调研来源和完整采集路径留在 Git 忽略的本地笔记中。

## 地形与生态的当前差距

| 当前实现 | 下一阶段需要解决的问题 |
| --- | --- |
| `sampleLandform` 在 v11 高度基础上混合局部地貌，已有沙丘、岩台、湿地、盆地及版本兼容 | 将区域构成、变化尺度、过渡与探索连通一起设计。不能仅按生态枚举数量判断丰富性。 |
| 地表主要由每列高度决定，再独立雕刻洞穴 | 评估区域高度参数混合与局部有界三维密度场的分工，让峡谷、陡壁和山地具有区别，并保持区块边界和公开查询一致。 |
| 地形、植被及颜色已有各自的生成参数 | 形成完整区域设计表，使轮廓、材料、植物和颜色共同表达身份，实际接入生产生成器。 |
| E6 的 Standard/Tall/Broad 仍是同种橡树轮廓 | 补充按地区辨认的树型与植物组合，不能只改变橡树大小或颜色。 |
| 已有地被、树木与地点生成 | 按坡度、距水和区域特点安排中小尺度内容，并保留空地和通路；同步考虑真实方块语义与生命周期。 |

现有实现并非没有差异地貌，局限在于它继承既有宏观高度，再做有界局部混合。E6 主要增强同类树的形态与疏密，后续颜色过渡也没有形成一套新的区域生态。此前 r33 报告明确保留四米材质变体纹样的问题。下一阶段应提升区域整体身份与探索体验，具体方案仍需在多 seed 生产采样和实际路线中验证。

## 天空实际核对（现后置）

当前天空 fragment 已包含太阳盘和光晕，环境时间 6000 时太阳方向近乎天顶。独立包以时间 6000／仰视 70° 和时间 3000／对准上午太阳进行采集，均实际看到太阳；不能将用户“白天没太阳”的感受直接判定为太阳绘制缺失。观测到的太阳是较小的纯白光斑，云层为较大的模糊色块，体积层次较弱。当前 shader 在云之后叠加太阳，缺少明确的云对太阳遮挡关系，属于可继续改进点。

用户工作包配置为 FOV 120°，而这两组诊断使用既有工具的 FOV 90°；较宽 FOV 会缩小天体和远处轮廓的画面尺寸，这是需单独比较的因素，不足以解释全部观感问题。本次没有修改用户设置。CUA 只读取用户应用，此时它显示主菜单背景；该背景不作为当前实时地形证据。

后续天空方向包括日月轮廓、云密度与受光的分工、昼夜色彩和雾的协调；本轮未实施这些改动，其优先级低于地形生态主线。
