# V01 材质源

`ground-sheet-v1.png` 是内置 ImageGen 制作的原创 2×2 图集：左上／右上／左下为草地顶面 A／B／C，
右下为林床。完整提示词、参考素材及构建方式见 `generation.json`。旧源图保持不变。

`tools/visual_polish_texture_source.py` 使用冻结的 1254×1254 源尺寸，分别裁取四个 627×627 单元，
最近邻采样为统一 16×16 创作网格，避免四格之间混色；这一步只编译已生成素材，不程序化重绘。
标准数组将同一网格放大后沿用独立线性光 mip，兼容／UI 图集直接使用 16×16 内容。
草地生态 tint 沿用既有五地区与三变体规则，林床保持棕土地表身份；方块 ID、地形和存档不变。

V01b 新增两份同尺寸原创源图，提示词、输入、源尺寸和 SHA 见 `materials-generation.json`：

- `earth-wood-sheet-v1.png`：左上土、右上石、左下橡木侧面、右下端面年轮。
- `foliage-sand-sheet-v1.png`：左上橡叶 A、右上橡叶 B、左下沙、右下草丛。

草侧由同一土层与前三组草色上缘组合；橡叶 A／B／镜像 A 保留生态变体。
叶片与草丛的 RGB 最大通道不超过 12 时编译为透明，其余像素保留原色。
16×16 网格的叶片 A／B 覆盖率分别为 87.109375%／88.28125%，草丛为 38.671875%。
这些是完整方块树冠的表面材质，未改变树木几何或增加树叶卡片。
标准数组从最终图集读取这 70 个材质单元，连同草侧、生态 tint、颜色及透明孔洞保持同物身份。
缩小 mip 时维持预期覆盖率；同透明度的边界像素以稳定顺序分配，避免低分辨率孔洞被整组填满。
旧源图与旧 masters128 保留为历史，当前打包不再加载它们。

V01c 新增三份 1254×1254 原创源图，完整提示词、参考、尺寸和 SHA 见
[species-stone-generation.json](species-stone-generation.json)：

- `birch-spruce-wood-v1.png`：左上／右上为云杉侧面／端面，左下／右下为桦木侧面／端面。
- `birch-spruce-stone-v1.png`：左上云杉叶、右上桦叶、右下苔石；左下石面候选因仍有明显斜纹未采用。
- `stone-planes-v2.png`：单格石面，替代旧石面；宽色块与短裂缝降低大面积墙面的斜向重复。

每格分别采样到16×16。云杉／桦叶的黑色键编译为透明，覆盖率分别为87.109375%／87.5%；
沿用原有mip覆盖保持算法。标准数组、兼容和UI图集现在共用77个材质单元；
本批只改变石、苔石和两树种的侧面／端面／叶共8槽，其余248层在所有mip中逐字节保持。
V01c阶段剩余雪、砾石、黏土和淤泥仍使用冒险源图；V01d接续替换，旧源图作为历史来源保留。

V01d新增同尺寸原创2×2源图`snow-sediment-v1.png`，完整提示词、象限和SHA见
[snow-sediment-generation.json](snow-sediment-generation.json)。左上雪、右上砾石、左下黏土、
右下淤泥。保持16×16共用网格：雪为低对比淡蓝白面，砾石为较宽颗粒，黏土为暖色块面与短层纹，
淤泥为深棕土团与少量夹石，全部不透明。雪源RGB各通道下限205／219／231，覆盖后仍检查
最暗通道至少180，防止裁边混入邻格。源图不作程序化重绘。

标准数组、兼容和UI图集现在共用81个材质单元，包含全部12种冒险自然材质。本轮只改变上述
四个语义槽；其他252层在全部7级mip逐字节不变。图集重建和数组重建确定，颜色／透明度错配
及雪面暗色污染负例被拒绝。旧源图／独立黏土源仍留在历史编译链中，最终材质以新覆盖为准。

V01e新增两张1254×1254全不透明单格原创源`coal-ore-v1.png`和`iron-ore-v1.png`，

赭色铁矿夹杂，减去旧矿石的碎亮纹与强暗边。每张独立最近邻采样16×16，不程序化重绘。

共享来源增至83槽；煤／铁地址保持`(13,0)`／`(14,0)`，方块和物品ID不变。图集与全部7级mip
只有这两槽改变，其余254层逐字节不变；数组和图集字节数保持。校验器独立锁定83个共享语义、
两矿来源、槽位与不透明性，并从正式PNG独立采样核对图集，不只信任数组报告。
标准／兼容及铁矿详情同机位生产诊断原图已查；普通采矿、手持／掉落和连续移动仍单列待验。

V01h新增两张1254×1254全不透明原创单格源`cobblestone-planes-v1.png`和

纹理仍使用既有运行资源路径与语义地址，不新增运行时纹理内存。源图是正式素材，不属于可清理截图。
