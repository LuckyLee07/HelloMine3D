## 排期原则

### 玩家价值优先

优先级按“能否形成一条更清楚、更长、更有反馈的玩家循环”决定：

- `P0`：阻止正常玩家完成主流程的问题，或直接形成目标/成长闭环的能力。
- `P1`：明显改善战斗、世界差异、反馈和可用性的能力。
- `P2`：正式发行证据、长稳、内容扩容和高级体验。

### 验收后置，但开发护栏不后置

正式验收可以放到玩法和 UI 稳定以后，但不能把所有验证一起取消。后续区分三层门禁：

| 层级 | 每批是否执行 | 内容 |
| ---- | ------------ | ---- |
| 开发门禁 | 必须 | 受影响目标可编译、定向自动测试、失败语义、数据守恒、旧存档兼容和资源引用检查。 |
| 里程碑门禁 | 每个大阶段结束执行 | Debug/Release 全流程夹具、隐藏客户端冒烟、固定种子旅程、保存退出和重开。 |
| 正式产品验收 | 后置集中执行 | 真人键鼠、视觉/听感检查、批准的性能预算、崩溃符号化、长稳、干净发行包和兼容性矩阵。 |

这样可以避免 UI 仍在变化时反复录制人工证据，同时也不会把存档损坏或状态复制问题拖到
最后才发现。

### 一个批次只解决一个玩家问题

每批应能独立提交和回滚，推荐保持“合同/数据边界 → 核心逻辑 → UI/表现 → 定向回归”
的顺序。涉及世界、库存、容器或玩家状态的新字段，必须在接 UI 前先定义版本、默认值、
旧格式迁移、非法值处理和事务失败语义。

## 近期详细批次

### G5：完成基础音频反馈

状态：`Done`。本节的实现和失败语义已经固定到 `audio-feedback-contract-v1.md`，人工听感
与物理输入证据继续后置，不影响 G6 开始。

目标不是移植一套大型声音引擎，而是建立稳定的业务事件和可降级播放边界。

1. **G5.1 数据和后端收口**
   - 固定版本化音频定义、分类音量、2D/3D、listener、并发上限和缺失资源策略。
   - Windows 使用轻量真实后端；其他平台、无设备、显式禁用或初始化失败时使用 dummy。
   - 真实后端不得被 `World`、`Player` 或 UI 直接持有。
2. **G5.2 事件和产品接线**
   - 只在成功的方块破坏/放置、拾取、制作、命中和 UI 动作上发布一次事件。
   - 暂停时停止世界/环境声音推进，但菜单 UI 声音仍可用；设置应用后分类音量立即生效。
   - 音频资源进入 manifest 和启动诊断；声音文件缺失必须静默降级，不能阻止世界加载、
     保存或退出。
3. **G5.3 定向回归和合同**
   - 覆盖重复事件、失败动作、静音、零音量、暂停、缺资源、无设备、并发上限和生命周期。
   - 完成 Windows Debug/Release 目标编译、运行时 smoke 和隐藏客户端冒烟。
   - 固定音频合同，再把 G5 标记为 `Done`。

G5 退出条件：七类基础提示可达；一次成功动作最多一次播放；失败动作零播放；强制 dummy、
缺文件或无设备时完整玩家流程仍可保存并正常退出。

### G6：打通可玩 Alpha 垂直切片

状态：`Done`。十步旅程和版本 4 存档语义已经固定到
`playable-alpha-contract-v1.md`；截图与可比较性能参考在紧随其后的 Alpha 检查点批准。

先用固定种子和确定资源位置做一条可重复流程，再补随机世界冒烟。正常流程不得调用
debug-only 发物品、传送、生成敌人或修改时间接口。

1. **G6.1 固定旅程夹具**
   - 创建世界并取得木材。
   - 制作并放置工作台，制作木镐。
   - 采石并升级石镐，取得受等级限制的铁矿。
   - 遭遇并击败一个自然敌人，拾取掉落。
   - 保存退出，从主菜单重开并继续游玩。
2. **G6.2 最低限度目标提示和平衡**
   - HUD 只显示当前一步、必要材料和完成反馈，不在本批引入通用 Lua 任务系统。
   - 调整出生点安全区、首批资源距离、工具速度/耐久、敌人伤害和掉落，使流程无需反复
     试错也能完成。
   - 所有提示从可观察状态或领域事件派生，不能直接修改库存或世界。
3. **G6.3 集成回归**
   - 自动证明关键物品总量、工具耐久、世界方块、演员和目标状态在保存/重载后守恒。
   - 补固定种子流程、随机种子启动、失败保存恢复、截图和可比较性能参考。
   - 只做一次开发者交互冒烟；正式真人输入记录继续后置到 N6 后。

G6 退出条件已经满足：新玩家从空存档开始，能只依赖游戏内 UI 完成“创建 → 采集 → 制作
→ 升级 → 战斗 → 保存 → 重开”，且中途退出重进不会复制或吞掉物品、工具状态和世界修改。

### N5：生态差异与探索目标

状态：`Done`。详细生成、迁移、目标和性能身份语义见 `ecology-exploration-contract-v1.md`。

当前已有 biome、洞穴、矿物和 decorator 边界，本批只增加有玩法意义的差异：

- 每个首发生态至少有一种可识别地表、一种特有资源/植物或一种敌人差异。
- 增加一个由 seed 确定、跨区块稳定、能服务目标链的轻量地标。
- 新生成规则带独立版本；旧世界保持原生成身份，不能因升级静默改写已探索区块。
- 所有 decorator 使用 world seed + chunk 坐标派生随机，不依赖加载顺序或邻区块是否存在。
- 先通过内容规模和快速移动预算，再考虑天气、村庄、地牢群或大量装饰方块。
- 已落地五类稳定生态身份，沙漠自然敌人为 Brute，其余生态为 Stalker；terrain v2 每个

## 暂不进入近期计划

- 多人网络、账号、云世界、排行榜、商城和在线活动。
- Lua/可执行 mod、运行时热更新和在线资源下载。
- 完整场景、方块、模型或 UI 编辑器。
- 新渲染后端、D3D9 兼容或整套旧 OgreMain 迁移。
- 附魔、复杂装备、红石式自动化、载具和大规模地下城。

这些方向不是永久否决，但都应该在单机 Release Candidate 有稳定存档、性能和内容生产
数据后独立立项，不能挤占当前“完整单机游戏”主线。
