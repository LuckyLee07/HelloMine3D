# HelloMine3D Stage 9 / Beta 迭代路线

本文是 Release Candidate 之后继续把 HelloMine3D 推进成“更像完整单机游戏”的权威预排
路线。它固定开发顺序、范围边界、版本策略和回归合同，方便后续逐批实施和复盘；当前状态、
历史任务数量仍以 `docs/todolist.md` 为准，已经完成的自动化证据仍以
`docs/runtime-validation.md` 为准。

最后更新：2026-08-26。

## 状态和统计边界

- `Planned` 表示已经排定方向，但尚未成为当前 `Todo` 或 `Doing`。
- `FS1-FS3`、`N7-N12` 和 `BETA-RC` 不计入拆分前的 77 项正式总账。`FS1-FS3`、`N7A/N7B`、
  `N8A/N8B`、`N9A/N9B`、`N10`、`N11A/N11B`、`N12A/N12B/N12C` 与 `BETA-RC` 工程封板
  已进入 `Done`，`RC0/R3` 的剩余真人验收按用户决定延后；历史总账仍为
  `73 Done / 4 Verify`。
- 只有开始某个批次时，才在 `docs/todolist.md` 建立该批的正式任务和合同；不得一次性把
  后续所有细项转成活跃待办。
- 每批开始前先固定合同和版本边界，完成后再记录真实测试数、性能数据和提交，而不是把本文
  的预期值当作已经取得的证据。

## FS1/FS2/FS3：首次游玩与视觉基线

玩家问题：当前真实创建路径可能沿用占位出生点，让玩家从海面开始；即使进入正常地表，
水面、天空、颜色和 HUD 仍明显带有调试原型感。具体合同、兼容边界和截图矩阵见
`docs/first-session-visual-baseline-contract-v1.md`。

- `FS1` 先关闭首次世界初始化缺口：确定性安全陆地出生、附近首轮木材、随机建议种子和
  严格受限的旧占位世界救援。该批不改变保存/terrain 版本。
- `FS2` 已建立独立水面着色、风格化云层、雾色和整体颜色基线；固定森林/海岸昼夜截图、
  双配置 536 项运行时回归、隐藏 Ogre 客户端和相关 Q1 性能比较均已通过。
- `FS3` 已完成统一图集、快捷栏图标、手持物、基础交互反馈、资源来源与隐藏输入隔离；
  R3 按计划放到下一批 RC0 执行。

## RC0：基线收口

目标：在 FS1-FS3 改动稳定后建立可恢复、可人工确认的新起点，避免对即将变化的首屏和 UI
重复执行真人验收。

范围：

1. 重新生成覆盖“线上基线到当前 HEAD”全部未推送提交的 Git bundle，并执行
   `git bundle verify`；bundle 放在仓库外或明确忽略的位置，不进入发行包。
2. 核对 `docs/todolist.md`、路线图和运行证据的状态一致性。
3. 在目标 Windows Release 构建上执行 `docs/manual-input-acceptance-v1.md` 的 R3 十二项
   真人输入记录；完成后同步关闭 D2、D4 和 D6。
4. R3 通过后可创建本地 RC 标签；是否推送仍需用户另行明确授权。

执行边界：

- 自动化 EXE 一律隐藏或后台运行；R3 因需要真人输入和观察，可以在事先安排的窗口前台运行。
- 本批不增加玩法、不改存档版本、不重批性能预算。
- Git 提交和标签只保存在本地，不 push。

退出条件：bundle 校验通过，文档状态一致，R3 记录通过，D2/D4/D6/R3 全部关闭，且工作区
不把 `tmp/` 或本地产物混入提交。

## N7A/N7B：结局状态、文本键与首个胜利闭环

玩家问题：当前目标链在“修复路标”后结束，已有探索终点但缺少高潮、结果反馈和可继续辨认的
世界状态。

内部交付顺序：

1. `N7A` 先新增独立的 `WorldOutcomeState`/`VictoryFlow`。至少区分未开始、已激活、遭遇中、
   已胜利和奖励已领取；它是世界列表标记、恢复和一次性奖励的唯一事实来源。
2. `N7A` 同时建立语义化文本 key、`en-US`/`zh-CN` 资源、缺失 key 回退和开发期诊断。
   目标定义不再继续扩张硬编码玩家文案，也不采用 MiniGame 的数字字符串 ID。
3. `N7B` 为 Waystone 增加可理解的激活配方或仪式，材料复用现有铁级、食物、敌人掉落和
   生态资源。
4. `N7B` 先使用现有 Stalker/Brute 或仅调整数据参数的精英敌人组成固定波次。数量、生成距离、
   失败恢复和离场行为必须有上限；专属 Guardian/Boss 行为延后到 N8 证明需要后再立项。
5. 完成后展示胜利覆盖层、目标结果和世界列表完成标记；应用状态继续保持 `Playing`，玩家可
   关闭覆盖层并继续沙盒，不新增独立 Victory 应用阶段。
6. 奖励、目标事件和路标状态必须幂等；重复加载、重复交互或崩溃恢复不能重复发奖。
7. 增加约 3-5 个终局目标，把现有 23 项目标串到准备、激活、防守和完成。目标负责引导和
   描述，不得再用“当前没有可见目标”推导世界已经胜利。

N7A 已建立 `waystone-victory-contract-v1.md`，固定结局状态权威、事件状态机、失败语义、
奖励 epoch/领取标志、文本 key、保存格式和 UI 快照边界。世界保存因三个实际持久字段升级到
v9；v1-v8 精确迁移为未开始状态，非法混合字段和不一致状态拒绝。

资源包、8 类启动错误、36 个性能夹具、十三个测试目标、隐藏客户端、131,817 字节受控 dump
和 69 文件干净包通过；发行 ZIP SHA-256 为
`9F52C3C9F6F9DE60F85D7864ED707A60FD358B15E062CF9E85807ABA8494BDD2`。固定 seed 的 nominal/

最低回归：

- 新世界正常路径无需 debug 注入即可完成胜利。
- 激活前、中、后保存和重开；旧 v1-v8 fixture 迁移；非法阶段值拒绝或安全归一；世界列表只
  从持久结局状态生成完成标记。
- 重复事件、满背包奖励、死亡、暂停、卸载路标区块和恢复备份均不复制状态或物品。
- 中英文终局 key 集合一致；缺 key、未知语言和非法文本资源按合同安全回退。
- 守卫数量、掉落、目标进度、事件队列和驻留区块均满足既有上限；运行相关 Q1 场景和短时
  nominal/stress soak。

明确不做：独立 Victory 应用阶段、多结局、剧情对话树、过场动画系统、通用任务管理器、
专用 Boss 框架、无限事件或在线成就。

退出条件：干净新世界能沿正常玩家路径获得一次清晰胜利；重启后胜利、奖励和世界列表标记
一致；胜利后继续游玩不会重复触发终局事件；定向回归、迁移和性能护栏全部通过。

## N8A/N8B：战斗可读性与远程遭遇

玩家问题：当前近战和敌人差异已经可用，但敌我意图、空间压力和应对选择仍不足以支撑终局
守卫战和后续营地探索。

内部交付顺序：

1. `N8A` 先交付攻击前摇/预警、方向性受击反馈、短硬直或击退；逻辑判定和视觉表现保持
   分离，让 N7B 守卫战无需等待投射物也具备可读性。
2. 将敌人定义扩展为小型、版本化的战斗档案，覆盖近战/远程模式、攻击距离、前摇、恢复、
   冷却以及必要的投射物参数；状态机限制为 Idle/Chase/Windup/Recover 等显式状态。
3. `N8B` 再增加一种远程敌人和有界投射物：固定 tick、寿命、最大距离、速度、伤害、碰撞、
   遮挡和全局/活动区上限均由定义控制。
4. 投射物只保存发射者 ActorId 等稳定身份，属于瞬态状态，不写入世界保存；保存重开、区块
   卸载、发射者死亡、超时或越界都必须清理。
5. 增加最低限度防御，例如盾牌或格挡；先验证时机与资源取舍，不建设复杂护甲树。
6. 增加调试快照：敌人当前状态、目标 ID、最近转换原因、活动投射物数量/上限以及本 tick
   使用的射线或寻路预算。目标失效时必须安全回到可恢复状态。

批次开始时建立 `combat-encounter-contract-v1.md`，固定敌人战斗档案、攻击阶段、投射物所有权、
命中顺序、射线/寻路预算、死亡清理、保存排除和容量策略。若敌人资源 schema 变化，必须在
合同中声明版本和非法字段降级，不得把这些参数散落到专用敌人类。

## BETA-RC：集中封板

   最终再执行 nominal/stress 各 1800 秒正式 Q3。
