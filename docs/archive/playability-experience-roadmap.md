# HelloMine3D Stage 11 可玩性与操作体验路线

本文是 Stage 11 的权威范围与批次合同。Stage 10 / VISUAL-RC 已完成 Windows 工程封板，但实际
试玩仍暴露出两个相互放大的问题：基础操作不够顺手，现有内容又没有持续产生足够多的选择、反馈
和目标感。因此本阶段不直接进入 `1.0-RC`，也不靠堆叠浅层配方、结构或敌人掩盖核心体验缺口；
先补可制造光源这一项最小可玩内容依赖，再修输入与动作反馈，随后重构前 30 分钟的玩法循环和
探索奖励，最后补敌人表现并集中封板。

P11-0、P11A、P11B、P11-1、P11C、P11D、P11-2、P11E 与 P11F 均已完成 Windows 自动工程
范围，当前没有剩余 Stage 11 代码批次。项目已明确为个人 Architecture Lab，不会建立外部玩家
验收团队，因此原“真人项后置”策略已由 `docs/current/ai-assisted-gameplay-acceptance-v1.md` 取代：
功能流程映射到 AI/Computer Use，可观察表现映射到 AI 视觉，人类主观与物理体验为
`NOT_CLAIMED`。首份 AI 场景尚未执行，状态为 `NOT_RUN`，不冒充 PASS。

2026-08-28 的内容与视觉复核在原有六批之间插入了三个内容密度批次 `P11-0`、`P11-1`、
`P11-2`。它们不是新阶段，也不回写拆分前 77 项历史总账；插入理由是原有批次的退出条件
依赖世界里并不存在的内容（可制造的光、建造材料、有垂直度的地形）。

## 当前体验判断

以下 2026-08-28 诊断是 Stage 11 的立项基线；其中操作冲突、光源、最小建造集和工具 class 已由
P11-0/P11A/P11B/P11-1/P11C/P11D/P11-2 关闭工程缺口，其余判断继续驱动后续批次。项目已有完整的技术底座和一条
可走通的单机旅程，但“能完成”还没有稳定转化为
“愿意继续玩”：

1. 数据数量不是零，但密度和分化不足。当前约有 19 个配方、4 种食物、3 个冶炼配方、3 类手工
   探索结构、28 个目标和 6 个敌人定义；真正形成不同战斗决策的主体仍主要是 Stalker、Brute、
   Spitter，再加基础或守护者变体。
2. 目标大多按单线清单推进。玩家常在执行已知步骤，而不是同时比较建造、成长和探索中的两个以上
   可见选择；配方发现也不足以承担“下一步提示”的职责。
3. 探索奖励经常回到普通材料或铁，胜利后事件也复用既有敌人与铁奖励。完成一次探索后，玩家的
   下一步计划和能力通常没有改变。
4. 敌人目前主要由 `src/HelloMine3D/Ogre/OgreActorRenderer.cpp` 中的 `buildUnitCube`、缩放和
   俯仰提示表现，轮廓、蓄力、受击和死亡动作不足，玩家需要依赖 HUD 才能读懂战斗。
5. 操作语义存在硬冲突。`src/HelloMine3D/Ogre/OgreBootstrap.cpp` 当前把右键同时映射为
   `placeBlock` 与 `guardCombat`；鼠标与快捷栏/调试键也没有进入现有九项键盘重绑定范围。
6. R3 v1 只覆盖旧的十二项物理输入基线，且没有完成正式记录；它保留为历史合同。当前 D2/D4/D6
   和 Stage 11 的焦点恢复、鼠标映射、放置/使用/格挡分离由 `AI-01..AI-04` 验证功能范围，
   物理设备手感不声明。
7. 世界里没有玩家可以制造的光源。运行时和资源清单注册的 21 个方块定义中只有 `Rose`
   （错误的 L2 遗留值 14）和 `WaystoneCore`（12）发光，因此 `CaveGenerator` 生成的洞穴
   实际不可探索、夜晚缺少持续活动，`V10A` 已实现的方块光与四角 AO 也缺少内容驱动。
8. 建造材料不足以支撑“建一个安全落脚点”。可放置材料实际只有泥土、石头、沙、原木、树叶和
   两种玻璃；没有木板、圆石、门和台阶。`media/blocks/` 下的 `OakPlank`、`OakSapling`、
   `CobbleStone` 是未进入 `BlockId` 枚举的孤儿文件，`oak_planks` 甚至已经有图集 tile。
9. 工具只有 `pickaxe` 和 `weapon` 两个 class，采集速度只按 tier 分档，“带哪把工具出门”
   不构成任何选择。
10. 敌人掉落缺乏身份。六个敌人定义**每一个**都带 `loot hellomine:dirt 1 1`，击杀的保底
    奖励是一块泥土。
11. 地形是单层高度图，五个生物群系的 amplitude 只有 85-100、smoothness 195-235，没有
    悬崖、山脉或天然洞口。`V10C` 的大气纵深和 `V10D` 的方向阴影因此缺少可表现的轮廓。

所以 Stage 11 的首要目标不是“再加多少内容”，而是让每次输入都可预测、每个动作都有反馈、前
30 分钟持续出现有意义的选择，并让一次探索真正改变玩家之后的玩法。为此必须先补齐这些循环
所依赖的最小内容，而不是在缺内容的世界上验收体验批次。

## P11-0：世界光源与洞穴照明

`P11-0` 是 Stage 11 的首个工程批次，现已完成工程实现。它排在 `P11A` 之前，是一次明确的产品顺序
调整：用一个有界的世界运行时与内容批次先补齐可制造光源，使洞穴、夜晚和 `V10A` 的方块光
成立，并给 `P11A` 的 AI 交互验收提供完整场景。`P11A` 仍是最高优先级的交互修复，但必须等这个
短批达到退出条件后开始；不得借 `P11-0` 扩张为通用动态光源或重开渲染管线。

范围限定如下：

- 新增可制作、可放置的火把；当前材料表没有独立煤物品，因此首版配方明确使用
  1 个 `hellomine:coal_ore` + 1 个 `hellomine:oak_bark` 产 4 个，在玩家 2x2 制作区即可完成，
  不需要工作台；不得在本批顺带新增煤物品或改矿石掉落链。
- 修正 `Rose` 的 `Light 14`，该值是 L2 光照里程碑的遗留测试值。
- 把方块发射从"只按 id"扩展为"id + metadata"，并让燃烧中的熔炉成为第一个消费者；
  除本批明确修改的 `Rose` 与 `Furnace` 外，所有现有方块的光照输出必须逐字节不变。
- 发射值翻转时触发一次且仅一次局部重光照，复用 L3 已有边界。

本批不引入灯笼、营火、熄灭机制、光源支撑检查、动态携带光源或任何 shader 变化，也不升
`save`、`terrain`、`settings` 版本。完整的数据字段、失败语义、兼容约束和验证矩阵见
`docs/contracts/world-light-source-contract-v1.md`。

## P11A：核心操作手感合同

P11A 已在 `P11-0` 工程退出后完成实现，范围限定如下：

- 将世界内的放置、上下文使用和战斗格挡建模为独立动作。默认键位允许共享物理设备，但同一次
  输入只能由明确的上下文决策消费，不能再把 `guardCombat` 直接复制自 `placeBlock`。
- 键位设置扩展到鼠标主/副/中键及适用侧键；冲刺和潜行均支持“按住/切换”。重复绑定必须在
  保存前给出冲突提示，保留恢复默认值入口。
- 灵敏度使用可解释、可回归的曲线；相同物理鼠标增量在不同窗口尺寸和帧率下产生一致 yaw/pitch，
  垂直翻转只改变 pitch 符号。不得用窗口中心像素位移间接决定转向幅度。
- 进入世界后捕获鼠标；暂停、菜单、失焦时可靠释放；恢复焦点时不吞掉确认点击、不产生视角跳变，
  也不向后台窗口发送采挖、放置或攻击。
- 鼠标与 HUD 交互、快捷栏滚轮、容器/制作界面、暂停菜单和世界操作必须有单一消费所有者；同一帧
  不得同时触发 UI 与世界动作。
- 手柄支持不进入 P11A；先把 Windows 键鼠路径做到稳定且可验收，再决定是否立项控制器批次。

### AI 输入功能验收与历史 Physical Input v2

Physical Input v2 保留为历史真人/物理输入合同，十三项、模板和校验器语义不变，但不再作为
Architecture Lab 当前退出门槛，也不得由 Computer Use 冒充物理操作者填写 PASS。功能范围按
下表迁移：

| 组别 | AI/Computer Use 操作 | 可声明结果 |
| ---- | --------------------- | ---------- |
| 移动与视角 | 走、跑、潜行、跳跃；两档灵敏度和 Y 轴反转。 | 状态/方向/设置单调与准星交互方向正确；不声明物理移动距离或舒适度。 |
| 世界动作 | 连续采挖、单次放置、上下文使用、攻击和格挡。 | 每次输入只有一个预期动作；失败不消费。 |
| UI 所有权 | 滚轮快捷栏、箱子、制作、设置、暂停。 | UI 不穿透世界；关闭后一次恢复控制。 |
| 焦点恢复 | `Alt+Tab`、最小化/恢复、窗口内外点击、暂停后继续。 | 后台无动作；回焦无跳转、卡键或误触；不主动抢焦点。 |
| 持久化 | 修改按键、鼠标、hold/toggle、灵敏度和反转后退出重启。 | 设置准确恢复；非法冲突被拒绝。 |

自动测试先证明动作仲裁、配置迁移、冲突检测、灵敏度计算和焦点状态机；`AI-01..AI-04` 再通过
干净 Release 包证明窗口功能。D2/D4/D6 在对应 AI 场景 PASS 后可标 `Done（AI Functional）`；
原 R3/Physical Input 记录保持 `NOT_RUN/SUPERSEDED`，物理设备手感为 `NOT_CLAIMED`。

## P11B：动作反馈边界

P11B 已完成工程实现，只强化已有动作的可读性，不在同批改资源经济、敌人掉落或增加敌人：

- 采挖显示有界裂纹阶段，方块破坏/放置产生与表面材质一致的少量粒子；第一人称手或工具有开始、
  接触和恢复阶段，动画不能改变实际命中时刻。
- 攻击命中提供短促且有上限的停顿、反冲、音色/音量变体；未命中、被格挡和造成伤害必须可区分。
- 准星或近准星区域显示攻击冷却；受伤显示方向，低生命提示不得持续遮挡中心视野。
- 拾取物具有轻微弹跳、吸附和收取反馈，但磁吸距离、存活时间和同时可见数量必须有上限。
- 镜头震动、受击闪烁和其他易引起不适的效果必须可调或可关闭；关闭时不丢失关键状态信息。

实现冻结为 settings v8 的 `off|reduced|full`、十级/最多 120 段裂纹、48 粒子、0.55 秒粒子
寿命、0.045 秒表现层命中停顿、3 米/5 米每秒吸附、300 秒掉落寿命、两次弹跳和 256 个可见
item 上限。world save 仍为 v11；AI 动态辨识映射到 `AI-05/AI-07`，人类打击感、眩晕和
长期舒适度为 `NOT_CLAIMED`。详细时序、回退和验证证据见 `docs/contracts/action-feedback-contract-v1.md`。

## P11-1：建造材料与工具分化

`P11-1` 已完成工程实现。它排在 `P11C` 之前，因为 `P11C` 的退出条件之一是“建一个安全
落脚点”，而立项时可放置材料只有泥土、石头、沙、原木、树叶和两种玻璃，玩家只能堆原木盒子。

- 补最小建造集：木板（原木转木板，`oak_planks` 已有图集 tile）、圆石（石头破坏产圆石、
  圆石冶炼回石头）、以及一种可开关的门或活板门。台阶与楼梯不进入本批。
- 增加 `axe` 与 `shovel` 工具 class，并为对应方块标注采集类别，使"带哪把工具出门"产生
  可感知差异；不新增工具 tier，不改现有 `pickaxe`/`weapon` 的数值。
- 清理 `media/blocks/` 下未进入 `BlockId` 枚举的孤儿文件（`OakPlank`、`OakSapling`、
  `CobbleStone`）：要么正式注册，要么删除，不允许继续留在资源目录里。
- `BlockId` 与 `Material::ID` 一律末尾追加，旧存档零迁移；新增配方必须通过资源经济的
  可达性与无环校验。

本批不做家具、装饰方块、多方块结构、涂色变体或建造辅助 UI。

最终冻结为 `BlockId` 22-25、`Material::ID` 35-39 的末尾追加身份；save v11、terrain v3 与
settings v8 均不变。Stone 权威掉落改为 Cobblestone，圆石可冶炼回 Stone；木板、单方块门、
木斧和木铲形成 24 配方/4 冶炼/8 工具的严格注册表。真实采集/建造/开门映射到 `AI-05`；
人类建造乐趣和主观速度手感为 `NOT_CLAIMED`。详细定义、失败策略和验证证据见
`docs/contracts/minimum-building-tools-contract-v1.md`。

## P11C：前 30 分钟体验

P11C 工程实现已经完成。Architecture Lab 使用一次无源码/路线图上下文的全新世界 AI 盲玩作为
“AI 可理解性代理”，而不是继续延长单线目标列表或冒充真人体验：

- 开场尽早同时暴露“建一个安全落脚点”“取得一项工具/成长”“追踪一个探索线索”三个方向中的
  至少两个，允许玩家自由切换，且进度不会因切换而丢失。
- 目标 UI 只提示近期机会和原因，不把全部流程写成教程清单。配方发现应由获得材料、查看工作台、
  找到蓝图或完成探索自然触发。
- 前 30 分钟记录首次建造、首次升级、首次有效探索、首次战斗决策和首次主动改计划的时间；同时
  记录超过 60 秒没有明确目标、反复打开菜单查找配方或走错流程的时段。
- 饥饿不会作为首版主循环强制加入。只有后续工程需求或 AI 代理证据稳定表明资源决策缺少持续张力，且恢复/死亡/难度
  合同可以同步处理时，才另立批次评估。

当前实现把目标定义升级为 v3，在保留十步 Alpha 兼容顺序的同时增加建造和探索两条分支；HUD
最多显示三项已满足前置的近期机会。配方知识随正向取得材料或成功制作触发，保存为确定性的
`recipe.<fnv64>` 扩展标识；手动正确摆放仍可制作，不形成权限锁。save v11、terrain v3、
settings v8 保持不变，v1/v2 目标状态归一到 v3。工程证据与 AI/主观声明边界见
`docs/contracts/first-thirty-minutes-contract-v1.md`。

## P11D：探索奖励（工程完成）

## P11-2：地形轮廓与洞口

`P11-2` 已完成工程实现。它是 Stage 10 之后视觉的下一档，但收益同时落在玩法上，所以排在内容线而不是
视觉线。Stage 10 提升的是表面质量（顶点 AO、材质、大气、阴影、色调），而画面的构图质量
由地形轮廓决定，Stage 10 明确没有触碰 `terrain v3`。

- 增加山地生物群系与高度域重映射，产生真实的高地、陡坡和垂直落差，让 `V10C` 的远景纵深
  与 `V10D` 的方向阴影获得可表现的对象。
- 让洞穴在接近地表时形成可进入的天然洞口，使地下探索可以被发现，而不是只能靠向下挖。
- 已形成 `terrain v4`。Mountain 只在枚举末尾追加，高度限制为 1..176；天然入口以 96×96
  世界 cell 和 24 格有界通道确定性生成，且不雕刻水方块。
- 旧世界永久保留创建时的 v1-v3 生成身份，不静默重生成、不回填已有区块；save v12 仍显式保存
  terrain 版本，固定 v3 样本和 v3/v4 保存恢复均已通过。

本批没有引入天气、体积光、地形破坏物理或新的渲染后端，也没有放宽 `V10A-V10E` 已批准的
性能护栏。PLAYABILITY-RC 已按新地形身份完成快速流送与规模玩法正式 Q1 baseline/repeat，
结果通过；洞口寻找、通行和轮廓可见性进入 `AI-05/AI-07`。
湖泊、河流、瀑布和通用水文生成保持 `Unscheduled`；它们需要独立的流体边界、跨区块确定性和
性能合同，不与山地轮廓/洞口一同塞入 `terrain v4`。

## P11E：敌人表现与机制原则

P11E 已完成工程实现。现有 Stalker、Brute、Spitter 改为 6-7 部件的有界体素轮廓；Idle、Chase、
Windup、Recover、受击和 8 tick 死亡姿态只读取确定性的玩法快照，渲染表现不反向修改伤害判定。
Waystone 守护者在既有原型上增加 crest，未知兼容类型仍安全回退为单立方体。

- Stalker 用窄身长臂表达快速接近，Brute 用宽身双臂表达重击，Spitter 用横向四足与 muzzle 表达
  远程压制。低表现能力下，既有 HUD、字幕和战斗音频仍保留危险窗口提示。
- 正常死亡产生最多 32 个、每个精确 8 tick 的只读表现快照；它们不进入碰撞、选取、自然生物或
  Waystone 数量、保存和卸载所有权。
- 本批没有增加新敌人或材料。六个正式敌人定义移除共同 Dirt；三类自然敌人都保证 Plant Fiber，
  同时保留 Wheat/Raw Meat、Coal Ore、Wheat Seeds 的身份差异，Waystone 守护者分别掉落 Iron Ore
  与 Iron Ingot。Alpha 拾取目标改为 Plant Fiber，因此不会因首个敌人类型不同而卡住。
- 守护战再次使用 core 可在 8 格内打断正处于 Windup 的已登记守护者：不造成伤害，进入 12 tick
  Recover，成功后冷却 80 tick；没有合格目标时不消耗冷却。这提供了时机与站位决策，而不是增加
  血量、数量或复用普通波次。

双配置、定向、完整世界、资源和客户端构建已经通过。动态辨识、战斗与完整守护战功能进入
`AI-05/AI-07`；人类危险感、掉落价值感和战斗乐趣为 `NOT_CLAIMED`。详细边界见
`docs/contracts/enemy-presentation-waystone-resonance-contract-v1.md`。

## 非目标与停止线

Stage 11 不包括多人联网、Lua/可执行脚本 mod、运行时热更新或下载资源包、新渲染后端、完整编辑器
和控制器支持。以下工作仍未获批为后续开发路线：

- 继续大规模润色地形渲染或重做 Stage 10 已封板的视觉基础；`P11-2` 改的是地形生成身份
  与轮廓，不是渲染管线，不得借它重开 shader、材质或后处理批次；
- 批量增加只有数值/换色差异的结构、敌人、生态、配方或掉落；
- 在前 30 分钟选择和探索奖励尚未成立前先做成就、统计或强制饥饿；
- 用事件注入、隐藏夹具、截图数量或内容计数代替 Computer Use 的正常玩法步骤；
- 把 AI 可理解性、AI 视觉判断或开发者自测改写成人类乐趣、审美、舒适度或物理手感 PASS。

若某批无法证明玩家问题得到改善，应缩小、返工或取消该批，而不是继续向后叠加内容。
