# HelloMine3D Stage 11 可玩性与操作体验路线

本文是 Stage 11 的权威范围与批次合同。Stage 10 / VISUAL-RC 已完成 Windows 工程封板，但实际
试玩仍暴露出两个相互放大的问题：基础操作不够顺手，现有内容又没有持续产生足够多的选择、反馈
和目标感。因此本阶段不直接进入 `1.0-RC`，也不靠堆叠浅层配方、结构或敌人掩盖核心体验缺口；
先补可制造光源这一项最小可玩内容依赖，再修输入与动作反馈，随后重构前 30 分钟的玩法循环和
探索奖励，最后补敌人表现并集中封板。

当前只立项 `P11-0`。其余批次都是有固定顺序的预排批次，状态为 `Queued`；每批必须用真实
试玩记录证明前一批已达到退出条件，才能把下一批切换为 `Planned`。这九批不得同时开工。

2026-08-28 的内容与视觉复核在原有六批之间插入了三个内容密度批次 `P11-0`、`P11-1`、
`P11-2`。它们不是新阶段，也不回写拆分前 77 项历史总账；插入理由是原有批次的退出条件
依赖世界里并不存在的内容（可制造的光、建造材料、有垂直度的地形）。

## 当前体验判断

截至 2026-08-28，项目已有完整的技术底座和一条可走通的单机旅程，但“能完成”还没有稳定转化为
“愿意继续玩”：

1. 数据数量不是零，但密度和分化不足。当前约有 19 个配方、4 种食物、3 个冶炼配方、3 类手工
   探索结构、28 个目标和 6 个敌人定义；真正形成不同战斗决策的主体仍主要是 Stalker、Brute、
   Spitter，再加基础或守护者变体。
2. 目标大多按单线清单推进。玩家常在执行已知步骤，而不是同时比较建造、成长和探索中的两个以上
   可见选择；配方发现也不足以承担“下一步提示”的职责。
3. 探索奖励经常回到普通材料或铁，胜利后事件也复用既有敌人与铁奖励。完成一次探索后，玩家的
   下一步计划和能力通常没有改变。
4. 敌人目前主要由 `src/HelloMine3D/Ogre/OgreActorRenderer.cpp` 中的 `buildUnitCube`、缩放和
   俯仰提示表现，轮廓、蓄力、受击和死亡动作不足，玩家需要依赖 HUD 才能读懂战斗。
5. 操作语义存在硬冲突。`src/HelloMine3D/Ogre/OgreBootstrap.cpp` 当前把右键同时映射为
   `placeBlock` 与 `guardCombat`；鼠标与快捷栏/调试键也没有进入现有九项键盘重绑定范围。
6. R3 v1 只覆盖旧的十二项物理输入基线，且尚未完成全部真人记录；它不足以验收当前 D2/D4/D6
   或 Stage 11 新的焦点恢复、鼠标映射、放置/使用/格挡分离和持续操作体验。
7. 世界里没有玩家可以制造的光源。运行时和资源清单注册的 21 个方块定义中只有 `Rose`
   （错误的 L2 遗留值 14）和 `WaystoneCore`（12）发光，因此 `CaveGenerator` 生成的洞穴
   实际不可探索、夜晚缺少持续活动，`V10A` 已实现的方块光与四角 AO 也缺少内容驱动。
8. 建造材料不足以支撑“建一个安全落脚点”。可放置材料实际只有泥土、石头、沙、原木、树叶和
   两种玻璃；没有木板、圆石、门和台阶。`media/blocks/` 下的 `OakPlank`、`OakSapling`、
   `CobbleStone` 是未进入 `BlockId` 枚举的孤儿文件，`oak_planks` 甚至已经有图集 tile。
9. 工具只有 `pickaxe` 和 `weapon` 两个 class，采集速度只按 tier 分档，“带哪把工具出门”
   不构成任何选择。
10. 敌人掉落缺乏身份。六个敌人定义**每一个**都带 `loot hellomine:dirt 1 1`，击杀的保底
    奖励是一块泥土。
11. 地形是单层高度图，五个生物群系的 amplitude 只有 85-100、smoothness 195-235，没有
    悬崖、山脉或天然洞口。`V10C` 的大气纵深和 `V10D` 的方向阴影因此缺少可表现的轮廓。

所以 Stage 11 的首要目标不是“再加多少内容”，而是让每次输入都可预测、每个动作都有反馈、前
30 分钟持续出现有意义的选择，并让一次探索真正改变玩家之后的玩法。为此必须先补齐这些循环
所依赖的最小内容，而不是在缺内容的世界上验收体验批次。

## P11-0：世界光源与洞穴照明

`P11-0` 是 Stage 11 的首个工程批次，现已完成工程实现。它排在 `P11A` 之前，是一次明确的产品顺序
调整：用一个有界的世界运行时与内容批次先补齐可制造光源，使洞穴、夜晚和 `V10A` 的方块光
成立，并给 `P11A` 的真人试玩提供完整场景。`P11A` 仍是最高优先级的交互修复，但必须等这个
短批达到退出条件后开始；不得借 `P11-0` 扩张为通用动态光源或重开渲染管线。

范围限定如下：

- 新增可制作、可放置的火把；当前材料表没有独立煤物品，因此首版配方明确使用
  1 个 `hellomine:coal_ore` + 1 个 `hellomine:oak_bark` 产 4 个，在玩家 2x2 制作区即可完成，
  不需要工作台；不得在本批顺带新增煤物品或改矿石掉落链。
- 修正 `Rose` 的 `Light 14`，该值是 L2 光照里程碑的遗留测试值。
- 把方块发射从"只按 id"扩展为"id + metadata"，并让燃烧中的熔炉成为第一个消费者；
  除本批明确修改的 `Rose` 与 `Furnace` 外，所有现有方块的光照输出必须逐字节不变。
- 发射值翻转时触发一次且仅一次局部重光照，复用 L3 已有边界。

本批不引入灯笼、营火、熄灭机制、光源支撑检查、动态携带光源或任何 shader 变化，也不升
`save`、`terrain`、`settings` 版本。完整的数据字段、失败语义、兼容约束和验证矩阵见
`docs/world-light-source-contract-v1.md`。

## P11A：核心操作手感合同

P11A 已在 `P11-0` 工程退出后完成实现，范围限定如下：

- 将世界内的放置、上下文使用和战斗格挡建模为独立动作。默认键位允许共享物理设备，但同一次
  输入只能由明确的上下文决策消费，不能再把 `guardCombat` 直接复制自 `placeBlock`。
- 键位设置扩展到鼠标主/副/中键及适用侧键；冲刺和潜行均支持“按住/切换”。重复绑定必须在
  保存前给出冲突提示，保留恢复默认值入口。
- 灵敏度使用可解释、可回归的曲线；相同物理鼠标增量在不同窗口尺寸和帧率下产生一致 yaw/pitch，
  垂直翻转只改变 pitch 符号。不得用窗口中心像素位移间接决定转向幅度。
- 进入世界后捕获鼠标；暂停、菜单、失焦时可靠释放；恢复焦点时不吞掉确认点击、不产生视角跳变，
  也不向后台窗口发送采挖、放置或攻击。
- 鼠标与 HUD 交互、快捷栏滚轮、容器/制作界面、暂停菜单和世界操作必须有单一消费所有者；同一帧
  不得同时触发 UI 与世界动作。
- 手柄支持不进入 P11A；先把 Windows 键鼠路径做到稳定且可验收，再决定是否立项控制器批次。

### Physical Input v2

Physical Input v2 是 P11A 的真人验收合同，不是一个可以只靠注入事件关闭的自动化套件。至少覆盖：

| 组别 | 真人操作 | 必须观察的结果 |
| ---- | -------- | -------------- |
| 移动与视角 | 走、跑、潜行、跳跃；快/慢移动鼠标；切换分辨率和画质。 | 状态切换稳定；yaw/pitch 幅度符合设置，不随帧率或窗口尺寸明显改变；准星与实际交互方向一致。 |
| 世界动作 | 连续采挖、单次放置、上下文使用、攻击和格挡。 | 每次输入只有一个预期动作；长按、点按和冷却可预测；放置不误格挡，格挡不误放置。 |
| UI 所有权 | 滚轮快捷栏、箱子、制作、设置、暂停。 | UI 打开时不穿透到世界；关闭后控制恢复；鼠标显示/捕获状态正确。 |
| 焦点恢复 | `Alt+Tab`、最小化/恢复、窗口内外点击、暂停后继续。 | 后台无世界动作；回焦首帧无跳转、无卡键、无误触；窗口不抢占其他应用焦点。 |
| 持久化 | 修改按键、鼠标和按住/切换设置，退出并重启。 | 设置准确恢复；旧版本迁移确定；无效、未知或冲突数据按合同拒绝或回退并给出可读提示。 |

自动测试应覆盖动作仲裁、配置迁移、冲突检测、灵敏度计算和焦点状态机；它们负责证明实现没有明显
回归，但不能代替上表的真人操作与观察。D2、D4、D6、R3 只按 v2 记录实际覆盖逐项更新，不允许
因为 P11A 代码完成而整体改为 `Done`。

## P11B：动作反馈边界

P11B 只强化已有动作的可读性，不在同批改资源经济、敌人掉落或增加敌人：

- 采挖显示有界裂纹阶段，方块破坏/放置产生与表面材质一致的少量粒子；第一人称手或工具有开始、
  接触和恢复阶段，动画不能改变实际命中时刻。
- 攻击命中提供短促且有上限的停顿、反冲、音色/音量变体；未命中、被格挡和造成伤害必须可区分。
- 准星或近准星区域显示攻击冷却；受伤显示方向，低生命提示不得持续遮挡中心视野。
- 拾取物具有轻微弹跳、吸附和收取反馈，但磁吸距离、存活时间和同时可见数量必须有上限。
- 镜头震动、受击闪烁和其他易引起不适的效果必须可调或可关闭；关闭时不丢失关键状态信息。

## P11-1：建造材料与工具分化

`P11-1` 排在 `P11C` 之前，因为 `P11C` 的退出条件之一是"建一个安全落脚点"，而当前可放置
材料只有泥土、石头、沙、原木、树叶和两种玻璃，玩家只能堆原木盒子。

- 补最小建造集：木板（原木转木板，`oak_planks` 已有图集 tile）、圆石（石头破坏产圆石、
  圆石冶炼回石头）、以及一种可开关的门或活板门。台阶与楼梯不进入本批。
- 增加 `axe` 与 `shovel` 工具 class，并为对应方块标注采集类别，使"带哪把工具出门"产生
  可感知差异；不新增工具 tier，不改现有 `pickaxe`/`weapon` 的数值。
- 清理 `media/blocks/` 下未进入 `BlockId` 枚举的孤儿文件（`OakPlank`、`OakSapling`、
  `CobbleStone`）：要么正式注册，要么删除，不允许继续留在资源目录里。
- `BlockId` 与 `Material::ID` 一律末尾追加，旧存档零迁移；新增配方必须通过资源经济的
  可达性与无环校验。

本批不做家具、装饰方块、多方块结构、涂色变体或建造辅助 UI。

## P11C：前 30 分钟体验

P11C 以一次全新世界真人试玩为设计单位，而不是继续延长单线目标列表：

- 开场尽早同时暴露“建一个安全落脚点”“取得一项工具/成长”“追踪一个探索线索”三个方向中的
  至少两个，允许玩家自由切换，且进度不会因切换而丢失。
- 目标 UI 只提示近期机会和原因，不把全部流程写成教程清单。配方发现应由获得材料、查看工作台、
  找到蓝图或完成探索自然触发。
- 前 30 分钟记录首次建造、首次升级、首次有效探索、首次战斗决策和首次主动改计划的时间；同时
  记录超过 60 秒没有明确目标、反复打开菜单查找配方或走错流程的时段。
- 饥饿不会作为首版主循环强制加入。只有试玩证据表明资源决策缺少持续张力，且恢复/死亡/难度
  合同可以同步处理时，才另立批次评估。

## P11D：探索奖励原则

P11D 的验收单位是“奖励是否改变之后的玩法”，而不是“箱子里物品数量是否更多”。候选能力包括
背包扩展、便携工作台、格挡升级、特殊照明和导航工具；最终只选择能形成清晰决策、可保存迁移且
不破坏既有经济守恒的最小集合。

- 每类正式结构需要独特资源、蓝图或能力线索，普通木石铁只能作为补充奖励。
- 不同生态的结构与奖励应支持不同准备方式或后续路线，不能只换表面颜色和掉落数量。
- 胜利后事件必须提供新的目标或规则变化；不得只复用已有敌人并再次奖励铁。
- 新持久状态、新物品或地形放置需要在当批合同中明确 save/terrain 身份、旧版迁移和旧区块边界，
  不得静默回填已有世界。

## P11-2：地形轮廓与洞口

`P11-2` 是 Stage 10 之后视觉的下一档，但它的收益同时落在玩法上，所以排在内容线而不是
视觉线。Stage 10 提升的是表面质量（顶点 AO、材质、大气、阴影、色调），而画面的构图质量
由地形轮廓决定，Stage 10 明确没有触碰 `terrain v3`。

- 增加山地生物群系与高度域重映射，产生真实的高地、陡坡和垂直落差，让 `V10C` 的远景纵深
  与 `V10D` 的方向阴影获得可表现的对象。
- 让洞穴在接近地表时形成可进入的天然洞口，使地下探索可以被发现，而不是只能靠向下挖。
- 形成 `terrain v4`。旧世界永久保留创建时的生成身份，不静默重生成、不回填已有区块；
  新旧地形边界与结构重复必须有明确测试。

本批不引入天气、体积光、地形破坏物理或新的渲染后端；也不因为地形变化而放宽 `V10A-V10E`
已经批准的性能护栏。快速流送与规模玩法 Q1 必须按新地形身份重新采集基线后再比较。
湖泊、河流、瀑布和通用水文生成保持 `Unscheduled`；它们需要独立的流体边界、跨区块确定性和
性能合同，不与山地轮廓/洞口一同塞入 `terrain v4`。

## P11E：敌人表现与机制原则

P11E 优先重做已有敌人的轮廓、动作和战斗窗口，再判断是否需要新敌人。多部件体素模型应保持低
复杂度和批量上限，动画状态由确定性的玩法状态驱动；渲染表现不得反向修改伤害判定。

- Stalker、Brute、Spitter 在距离、轮廓、移动节奏、攻击预警和声音上分别表达接近、重击、远程
  压制决策。
- 待机、移动、蓄力、攻击、受击和死亡至少有明确关键姿态；低画质回退仍保留危险窗口提示。
- 新敌人只有在同时带来一种新决策和一种有价值的新奖励时才可加入。
- 同批修正敌人掉落身份：移除六个敌人定义中共有的 `loot hellomine:dirt 1 1`，让 Stalker、
  Brute、Spitter 与 Waystone 守护者各自掉落可辨识的材料。若需要新增材料，P11E 合同必须先
  冻结 `Material::ID` 追加、资源经济守恒、目标链和旧存档边界。
- Waystone 守护阶段必须拥有独特的空间、时序或目标机制；单纯增加血量、数量或重复普通波次不算
  新阶段。

## 逐批试玩与 PLAYABILITY-RC

工程开发按固定顺序继续，代码、自动测试、双配置构建和可在当前环境执行的自主验收仍须逐批关闭。
`P11-0` 至 `P11E` 的 10-30 分钟目标试玩（P11C 至少完整 30 分钟）统一后置为 Deferred；记录不能
只写“感觉更好”，恢复验收时至少包含：

- commit/构建身份、Debug/Release、操作系统、CPU/GPU、分辨率和输入设备；
- 目标场景、关键里程碑实际耗时、误点/串键/卡键次数、死亡次数和原因；
- 超过 60 秒不知道下一步的时段、主动改变计划的时刻、退出或继续玩的主观原因；
- 自动门禁、相关 Q1/Q3、保存退出/恢复和旧版本迁移结果；
- 明确的 `PASS`、`FAIL` 或 `Verify`，以及仍待修复或延期的条目。

P11F 只集中复核已经逐批留下的证据，不允许把所有真人试玩拖到阶段末尾。自动化可以复现输入状态
机、经济守恒、迁移和性能，但不得生成“真人验收通过”结论；最终 PLAYABILITY-RC 也不会自动
push、打标签或关闭没有目标机器证据的 macOS 项。

## 非目标与停止线

Stage 11 不包括多人联网、Lua/可执行脚本 mod、运行时热更新或下载资源包、新渲染后端、完整编辑器
和控制器支持。以下工作在 P11F 前也不应抢占主线：

- 继续大规模润色地形渲染或重做 Stage 10 已封板的视觉基础；`P11-2` 改的是地形生成身份
  与轮廓，不是渲染管线，不得借它重开 shader、材质或后处理批次；
- 批量增加只有数值/换色差异的结构、敌人、生态、配方或掉落；
- 在前 30 分钟选择和探索奖励尚未成立前先做成就、统计或强制饥饿；
- 用自动输入、截图数量或内容计数代替真实试玩中的可读性、误操作和目标感结论。

若某批无法证明玩家问题得到改善，应缩小、返工或取消该批，而不是继续向后叠加内容。
